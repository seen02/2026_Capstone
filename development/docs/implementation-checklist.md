# 매직아일랜드 기능별 개발 체크리스트

기준일: 2026-11-17. [최신 개발 명세](design.md)를 구현하기 위한 작업 목록이다. **체크 항목 하나를 새 채팅 하나의 작업 범위**로 삼는다. 시뮬레이션 1–2번 설정 기반과 3D 지도·시설 표시를 완료했고 그 다음 미완료 항목은 3번 시간별 유입·개인 체류다. 공통 데이터 계약 문서를 작성했으며 전체 제품의 다음 작업은 아래 QR 시연·추천 연동의 추천 서버 최소 구현이다.

이 목록은 최종 제품 중 시뮬레이션 하위 작업이다. QR 관람객 화면·영상 기반 분석 및 추천 서버·관리자 대시보드의 전체 범위와 순서는 [최종 소프트웨어 계획](software-plan.md)을 따른다.

## QR 시연·추천 연동 체크리스트

아래 항목은 기존 시뮬레이션 3–9번과 구분되는 제품 연동 작업이다. 추천 로직과 서버를 먼저 개발하되, 시뮬레이션 상태가 아직 없으므로 초기 검증에는 출처를 명시한 모의 대기 현황을 사용한다. 모의 데이터 연결을 시뮬레이션 엔진이나 영상 분석 완료로 간주하지 않는다.

- [x] **공통 데이터 계약** — 시설 ID·지도 버전, 사용자 세션·가상 위치, 선호 순위, 시설 운영·대기 상태, 추천과 수락·이동·이용·보상 상태를 정의한다. 시뮬레이션 실행 ID·시각 및 데이터 출처를 구분한다. **완료 기준:** 기존 설정·지도·경로 코드와 대조한 계약 문서에 필수 필드, 자료형·단위, 예시, 상태 전이와 미집계 처리가 있고, 이후 모의 데이터와 시뮬레이션 상태를 같은 추천 입력으로 연결할 경계가 명확하다. 실제 구현되지 않은 API를 완료된 것처럼 표시하지 않는다.

  문서: [공통 데이터 계약 v1](contracts/recommendation-v1.md), [검증 기록](verification/recommendation-data-contract.md). 기존 지도에서 계산한 경로를 포함한 모의/시뮬레이션 입력과 추천·수락·완료·보상 JSON 예제를 대조했다. 시뮬레이션 입력과 workflow는 구조 검증용 가정이며 실행 결과가 아니다. 추천 서버·경로 어댑터·상태/보상 엔진 구현은 다음 항목으로 남는다.
- [ ] **추천 서버 최소 구현** — 시설별 선호 순위, 가상 위치와 이동거리, 이용 가능 상태, 예상 대기시간을 고려해 다음 시설 한 곳과 추천 이유를 반환한다. 초기 모의 입력과 실제 시뮬레이션 입력을 구분한다.
- [ ] **QR 사용자 진입과 선호 입력** — 공통 QR로 접속한 사용자별 세션을 만들고 놀이기구 선호 순서를 입력받는다. 자이로스핀·혜성특급·자이로드롭 사이 표지판의 좌표를 정하고 사용자 캐릭터를 주변에 식별 가능하게 배치한다.
- [ ] **추천 수락과 가상 이동** — 사용자 웹에서 추천과 예상 대기·이유를 표시하고 수락을 받는다. 시뮬레이션에서 해당 캐릭터를 목적지로 이동시키며 웹에 같은 사용자와 상태를 표시한다.
- [ ] **대기·이용 완료와 보상** — 시뮬레이션상 대기·이용이 완료되면 중복 지급 없이 체험 보상을 제공하고 현재 가상 위치와 최신 대기 현황으로 다음 추천을 제공한다. 추천 수락 인원은 이후 혼잡 계산에 반영한다.
- [ ] **다중 사용자 현장 시연** — 여러 휴대폰의 세션과 캐릭터 대응, 시간 압축, 데이터 갱신 및 QR 접속부터 보상까지의 전체 흐름을 검증한다.

위치에는 시뮬레이션의 가상 좌표를 사용하며 휴대폰 GPS는 사용하지 않는다. 보상은 시뮬레이션 체험 보상이며 실제 시설 이용 인증은 별도 후속 검토 사항이다. 시뮬레이션의 유입·대기·운행 엔진은 아래 항목에서 계속 개발한다.

공통 기준은 **10:00–19:00 관측, 시간별 계획 유입 합계 10,350명, 대기 포함 개인 예정 체류 120–240분, 6개 시설**이다. 세부 수치와 시간표는 명세를 사용하고 이 문서에 중복 정의하지 않는다. 각 항목에는 관련 검증과 변경된 명세·조사 문서 갱신까지 포함한다. 마지막 항목까지 테스트를 미루지 않는다.

- [x] **1. 시나리오 선택과 설정 분리** — 기존 아쿠아리움과 매직아일랜드의 지도·운영·선호 설정을 구분하고 서버·실행 진입점에서 선택할 수 있게 한다. **완료 기준:** 아쿠아리움이 기존대로 실행되고, 새 시나리오 설정을 독립적으로 불러오며 잘못된 설정을 검출한다. 이후 기능을 연결할 기반까지 작업한다.

  구현 위치: `aquarium/`·`lotteworld/` 독립 프로젝트, 루트 `run.py` 선택 진입점. [설정 계약](../lotteworld/docs/configuration.md)과 [검증 기록](verification/scenario-isolation.md)을 참고한다. 매직아일랜드는 설정 검증 서버까지 제공하며 실제 재생은 아직 지원하지 않는다.

- [x] **2. 매직아일랜드 3D 지도와 시설 표시** — 안내도에 대응하는 주 섬·메이플 돌출부·호수·6개 시설의 상대 배치와 입체 특징을 구성하고 성 정면·앞 광장·사선 다리를 같은 직선 축으로 연결한다. 섬 내부 대부분은 넓은 포장 보행 광장으로 두고 녹지는 작은 식재 구획으로 제한한다. 혜성특급은 지상 모형으로 표시한다. **완료 기준:** 전체 보기에서 시설·동선을 구별하고 같은 미터 좌표의 3D 형상과 보행 공간 판정을 사용한다. 다리에서 입출구까지의 연결, 회전·확대·이동·시점 복귀·가림 처리와 모형 선택을 확인한다. 최종 대기 자리 수는 4번에서 검증한다.

  구현: `lotteworld/web/map3d.js`·`rides.mjs`, `configs/map.json`·`map_geometry.py`. [3D 지도 검증 기록](verification/magic-island-map3d.md)과 [설정 계약](../lotteworld/docs/configuration.md)을 참고한다. `public_walkable`로 넓은 포장 영역을 정의했으며 `navigation.mjs`가 그 면을 활용한 표시 경로를 찾는다. 6개 대기줄은 공연 대기줄 형태의 정적 표시다. [추가 검증](verification/queue-and-open-plaza.md)을 참고하며 실제 보행·대기·운행 엔진 완료와 구분한다.

- [ ] **3. 시간대별 유입과 개인 체류** — 10–19시 시간표, 구간 내 무작위 도착, 실제 진입 시각부터의 2–4시간 체류를 구현한다. 19시 관측 종료와 개인 복귀 시각을 분리한다. **완료 기준:** 계획 수요 10,350명이 재현되고 진입 지연·미진입을 구분하며 늦은 입장자의 체류와 19시 상태가 보존된다.

- [ ] **4. 물리적 대기열과 승하차 보행** — 줄 합류·전진·이탈, 승차 지점 접근, 전용 퇴장 동선과 하차 후 합류 공간을 구현한다. 긴 대기를 담을 공간과 실제 자리 수를 검증하고 기존의 작은 대기 상한을 재검토한다. **완료 기준:** 보행로·난간을 가로지르지 않고 줄이 차면 다른 시설로 이동하며 입구·출구 이동과 대기 자리 정원이 지켜진다. 운행과의 최종 연결은 5–6번에서 마친다.

  곡선 벨트와 정적 자리 배치는 선행 검증했다. 화면에는 자리 수를 표시하지 않는다. 시설별 대기 구획은 1회 탑승 정원의 2.5배 이상을 만족한다. [검증 기록](verification/queue-capacity-and-reload.md)을 참고한다. 실제 줄 이동·합류·이탈·승하차 연결이 남아 있어 4번 전체는 미완료다.

- [ ] **5. 회차 단위 놀이시설 운행** — 자이로드롭·자이로스윙·자이로스핀·아르카나라이드의 승차·확인·운행·하차 반복을 연결한다. 미확인 시간은 근거나 가정과 조절 범위를 명시한다. **완료 기준:** 4개 시설에서 실제 대기객이 정원 안에서 탑승하고 빈 좌석 출발·반복 운행·체류 만료 중 하차가 정상 동작한다.

- [ ] **6. 아트란티스·혜성특급 차량 운영** — 여러 차량·편성의 가용 상태와 승하차 위치, 운행시간·출발 간격을 구분해 순환 운행을 구현한다. 아트란티스의 보고서 기준을 적용하고 혜성특급 미확인 값은 근거 또는 가정으로 정리한다. **완료 기준:** 차량을 재사용하며 보유 대수·좌석을 초과하지 않고 승하차나 코스가 막히면 다음 출발이 늦춰진다.

- [ ] **7. 방문객 선호와 반복 이용 행동** — 해양 전시 선호를 놀이시설에 맞게 바꾸고 시설 선택·대기 허용·포기·재선택·재탑승을 연결한다. 과거 논문 수치와 가상 가중치를 구분해 설정한다. **완료 기준:** 개인 선호와 남은 시간에 따라 행동이 달라지고 한 번씩 탔다고 강제 퇴장하지 않으며 같은 시드에서 재현된다.

- [ ] **8. 재생 화면과 운영 지표 연결** — 기존 시뮬레이션 화면에 시설별 운행 상태·대기·탑승 인원과 시간별 유입, 완료·진행 중 대기를 연결하고 재생·배속·되감기·결과 내보내기를 맞춘다. **완료 기준:** 지도와 패널이 같은 재생 시각을 보여 주고 19시 잔류·진행 상태를 확인할 수 있다. 최종 관리자 앱과 지도·지표 컴포넌트를 공유할 수 있도록 데이터 출처·실험 ID·재생 시각을 구분한다. 현장 영상·관람객 제품 연결은 전체 계획의 별도 단계다.

- [ ] **9. 9시간 통합 실행과 성능 검증** — 최신 시간표 전체를 실행해 사람·차량 보존, 대기 공간, 양방향 통행과 피크 시간 성능을 검증하고 필요한 개선을 한다. **완료 기준:** 10–19시를 끝까지 실행하고 계획·진입·복귀·잔류·미진입이 맞으며 재생·되감기 결과가 일치한다. 논리 인원을 줄이지 않고 수천 명 동시 체류를 처리하며 실행 방법·제약·검증 결과를 문서에 남긴다.

각 항목은 해당 기능의 완료 기준을 확인한 뒤에만 체크한다. 다음 작업은 위 QR 시연·추천 연동의 추천 서버 최소 구현이며, 모의 입력을 사용하는 추천 기능부터 구현하면서 시뮬레이션 항목을 이어간다. 실제 기능을 마치고 새 채팅으로 인계하는 시점에는 프로젝트의 인계 절차를 따른다.

QR 관람객 화면·영상 수신 및 인원/밀집도 분석·추천 서버·관리자 대시보드와 추천 효과 평가는 최종 소프트웨어에 포함되며 [전체 계획](software-plan.md)의 후속 연동 단계에서 진행한다. 이 목록의 9번 완료를 최종 제품 전체 완료로 보고하지 않는다. 비상 대피·퍼레이드 관람 이동·실물 하드웨어 제작은 별도 범위다.
