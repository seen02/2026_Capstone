예매·입장 정보로 관객의 출발 구역을 연결하고, 위험 통로를 제외한 안내를 영화관 앱과 현장 가변 표지판에 함께 제공한다. 앱 이용이 어려운 관객도 현장 안내를 받을 수 있게 하며, 도움 요청과 대피 확인을 관리자 화면으로 연결한다.

‘자리’ 참고자료의 실행 계획 → 과제 계획서 → 요구사항명세서 → 상세설계서 구성을 따른다. 본 문서는 신규 아이디어의 설계안이다. 함께 제공하는 웹앱 목업은 가상 데이터로 화면과 상태 전환을 보여주며, 실제 영화관·센서·푸시·표지판에는 연결되지 않는다.

제안의 핵심
웨어러블 지급을 스마트폰 앱으로 대체한다. 상용 적용은 영화관 사업자가 기존 예매 앱에 기능을 추가하는 형태, 종합설계는 예매·입장을 모사한 독립 웹앱과 모형 표지판으로 검증하는 형태로 구분한다. 앱 설치율·알림 허용률·예매 API 접근 권한이 확보됐다고 가정하지 않는다.

1 프로젝트 목표와 범위

1.1 왜 영화관인가

영화관은 상영관·회차·좌석이 정해져 있어, 시설 전체에서 사람을 정밀 추적하지 않아도 입장 시점의 출발 구역을 연결할 수 있다. 관객은 어두운 공간에서 화면을 보고 있고 여러 상영관의 퇴장 동선이 공용 복도에서 합쳐질 수 있으므로, 안내 변경을 알아차리고 같은 구역에서 같은 방향으로 이동하게 하는 문제를 연구하기 좋다.

예매 앱이 이미 있는 관객에게는 별도 기기 지급을 줄일 수 있다. 그러나 대리 예매, 여러 명을 한 계정으로 예매한 경우, 현장 발권, 휴대폰 미소지 관객이 있으므로 예매 계정 수·휴대폰 수·실제 관객 수를 동일하게 계산하지 않는다.

1.2 개발 목표

  1. 입장 확인한 회차·상영관·좌석을 대피 안내 세션에 연결한다.
  2. 통행 제한 이벤트를 입력하면 해당 통로를 경로 후보에서 제거한다.
  3. 같은 의사결정 구역의 앱과 표지판이 같은 경로 버전을 사용하게 하고, 적용 불일치를 표시한다.
  4. 관객의 위치 수정·도움 요청·대피 자기신고를 관리자에게 전달한다.
  5. 통신 단절, 위치 미확인, 표지판 무응답 등 예외 상황을 정상 상태와 구분한다.

위험 입력 버튼 또는 허가된 설비 인터페이스가 서버에 이벤트를 제공한다. 서버와 표지판은 로컬 네트워크로 통신한다. 웹앱을 열어 둔 실험에서는 WebSocket으로 상태를 전달하며, 실제 기존 앱에 넣는 단계에서는 사업자의 인증·예매 시스템 및 운영체제 알림 기능과 연동한다.

2.3 같은 구역에서 충돌하지 않는 안내

개인화는 우선 출발 구역, 언어, 글자 크기, 도움 요청에 적용한다. 공용 복도 C에서 어떤 앱은 A를, 표지판은 B를 안내하는 식의 개인별 분산은 필수 범위에서 제외한다. C 구역에 도달한 이용자에게는 동일한 정책을 제공한다. 좌석에서 C까지의 경로는 다를 수 있다.

서로 다른 상영관을 서로 다른 출구로 분산하는 기능은 확장 단계에서 다룬다. 이때에도 공용 분기점 이후의 안내는 일치해야 하며, 그룹별 안내가 필요하면 구역명·문자·화살표가 명확히 분리된 표지판을 별도로 설계하고 사용자 시험을 해야 한다.

3.2 처음 12인시의 진행 판단

  1. 휴대폰 두 대가 같은 서버 화면에 접속해 이벤트를 받는지 확인한다.
  2. ESP32 1대가 명령을 받고 적용 응답을 보내는지 확인한다.
  3. 노트북에서 A 통로 차단 → B 경로 변경 → 앱과 모형 표지판 반영을 연결한다.
  4. 공유기 분리 후 장치가 설정된 시간 안에 오래된 가변 화살표를 해제하는지 확인한다.

학교 Wi-Fi의 단말 간 통신 차단이 있으면 실험용 공유기로 전환한다. 이 기본 연결을 완성하기 전에는 BLE·푸시·AI를 추가하지 않는다.

4.2 권장 기술 단계

1단계: QR/티켓 연결 + 구역 선택 + 전경 웹앱 + Wi-Fi 표지판. 2단계: Android 네이티브 앱에서 BLE 구역 추정과 푸시를 별도로 검증. 3단계: 영화관 사업자와 기존 앱·검표·설비 연동을 협의한다. 졸업작품에서 실제 예매 시스템 사용 권한이 있다고 가정하거나, 앱이 이미 설치되어 있으니 곧바로 센서처럼 쓸 수 있다고 설명하지 않는다.

웹 Bluetooth는 브라우저 호환성과 보안 컨텍스트 제약이 있어, 모든 휴대폰 웹앱에서 비콘을 자동 검색하는 기능을 필수로 잡기 어렵다.[R1] Android의 백그라운드 BLE도 별도 실행·권한 설계가 필요하다.[R2] 일반 BLE RSSI와 정밀 측위용 AoA는 구분해야 한다.[R6]

4.3 영화관 앱의 알림 문제

영화 중에는 무음·방해금지·화면 꺼짐이 흔할 수 있으므로 ‘앱이 모든 관객을 반드시 깨운다’를 전제로 하지 않는다. Android 13 이상에는 알림 런타임 권한이 있고, iOS의 무음·집중모드를 넘어 소리를 내는 Critical Alerts는 별도 권한과 사용자 승인이 필요하다.[R3][R4] 푸시는 단말 상태와 메시지 수명에 따라 지연되거나 전달되지 않을 수 있다.[R5]

앱은 개별 안내와 양방향 요청 수단이다. 기본 경보·방송·법정 피난설비·직원 안내는 계속 필요하다. 실험의 ‘웹앱 실행 중 전달 시간’ 결과를 ‘잠긴 스마트폰에도 전달 보장’으로 확대하지 않는다.

6.2 사람이 이해하는지 확인

실제 화재·연기·암전 없이 안전하게 통제된 모의 공간에서, 동의한 성인 6–10명을 대상으로 탐색적 평가를 한다. ‘가변 표지판만’과 ‘가변 표지판 + 앱’ 조건의 순서를 참가자별로 번갈아 배치하고, 서로 비슷하지만 다른 차단 시나리오를 사용한다.

알림 인지 시간, 첫 경로 선택 정확도, 잘못된 분기 선택 횟수, 도움 요청 성공 여부, 읽기 부담을 기록한다. 이동 속도를 경쟁시키거나 실제 피난 시간을 단축했다고 일반화하지 않는다. 앱 사용으로 보행 중 화면 주시가 늘어나는지도 함께 기록하고, 필요하면 앱 내용을 ‘다음 표지판 한 개’로 줄인다.

6.3 기록의 구분

예매 좌석 수, 검표 인원, 앱 연결 세션 수, 알림 표시 세션 수, 대피 자기신고 수, 직원 확인 인원을 분리한다. 미응답을 잔류·사망·위험 인원으로 자동 분류하지 않는다. 실험 시작 전에 기기·OS·브라우저·네트워크·버전을 적고, 아직 실행하지 않은 시험은 ‘미실행’으로 남긴다.

7 위험 대응과 완료 기준

상황설계 대응
예매 좌석에 없음마지막 위치의 근거·시각 표시. ‘현재 위치 수정’을 제공하며, 위치 불명 시 좌석 기반 이동 화살표를 숨김
같은 계정으로 여러 명 예매좌석별 일회용 연결 또는 대표자 세션임을 구분. 휴대폰 1대를 4명 위치로 복제하지 않음
센서가 말이 없음‘정상’으로 간주하지 않음. 영향 구간 UNKNOWN으로 처리하고 동적 추천에서 제외
앱·표지판 불일치새 추천을 일치 완료로 표시하지 않음. 관리자에게 해당 장치·버전·마지막 응답 표시
선택할 경로가 없음임의 경로 생성 금지. ‘확인 가능한 경로 없음’과 현장 경보·직원 안내 확인, 도움 요청을 제공. 무조건 그 자리에 대기하라고 지시하지 않음
전원·통신 장애추가한 가변 출력은 만료 후 해제. 독립된 기존 피난 안내 유지. 실제 운영의 예비전원·배선·화재 내성은 별도 시설 설계
위험 해제 신호한 번 값이 정상으로 돌아왔다고 자동 재개방하지 않음. 권한 있는 운영자 확인 후 새 사건 버전으로 해제
위치정보와 개인정보회차 한정 가명 세션, 최소 구역·근거·시각만 수집. 종료 후 보관기간을 정해 삭제하고 개인 예매·결제정보는 저장하지 않음

완료 기준: 실제 표지판 노드 2개와 휴대폰 2대가 연결된 상태에서 필수 시나리오를 재현하고, 장애 표시·버전 처리·이벤트 기록을 검증한다. 경로 차단 시험과 역순 명령 시험을 통과하며, 성능 미달은 수치와 함께 보고한다. 현재 전달하는 HTML 목업만으로 이 완료 기준을 충족했다고 주장하지 않는다.

A1 과제 목적 및 필요성

과제명은 ‘영화관 예매·입장 정보와 가변 표지판을 연동한 대피 안내 및 도움 요청 시스템’이다. 영화관의 상영관·좌석 정보로 관객의 초기 출발 구역을 연결하고, 위험 통로를 제외한 경로 안내를 앱과 표지판에 일관되게 제공한다. 현장 안내 변경의 인지와 도움이 필요한 관객의 의사 전달을 보완하는 것이 목적이다.

기존 앱의 접근성은 활용하되 전원·통신·알림 허용 여부에 따라 앱을 사용할 수 없는 관객이 존재한다는 전제로 설계한다. 학교 실험에서는 실제 영화관 서비스 권한을 전제로 하지 않고 예매와 검표를 모사한다.

A3 기대효과 및 활용방안

개별 기기 지급 부담을 줄이고 관객에게 익숙한 티켓 화면에서 안내에 접근하도록 할 수 있다. 위치를 알 수 없는 경우와 전달되지 않은 경우를 구분함으로써 관리자가 시스템의 한계를 파악할 수 있다. 효과는 모의 실험으로 평가하며 실제 사고 감소나 대피 시간 단축은 아직 입증되지 않았다.

후속 연구로 다상영관의 공용 복도 정책, 접근 가능한 대피공간 안내, 다국어 제공, 사업자 시스템 연동을 고려한다. 이동약자 경로는 사전 검토된 시설 계획을 입력받아야 하며 일반 승강기 자동 안내는 제외한다.

C2 위치와 경로 계산

C2.1 위치의 유효성

검표는 초기 구역 추정 근거로만 사용한다. 시제품은 사용자가 출발 구역을 확인한 후 개인 경로를 보여준다. 대피 안내 중 위치 확인이 30초 이상 갱신되지 않으면 ‘이전 확인 위치’로 표시하는 것을 초기 정책으로 삼고, 경계 이동이나 사용자 이의가 있으면 즉시 UNKNOWN으로 전환한다. 30초는 검증할 설계값이며 좌석 위치를 보장하는 시간은 아니다.

확장 BLE는 휴대폰이 고정 비콘을 관찰하는 방식이다. 서버가 일반 스마트폰의 신호를 수동 수집해 모든 관객을 추적한다고 가정하지 않는다. 여러 신호 표본과 구역 전환 유지 시간을 적용하고, 후보가 비슷하면 어느 한 구역으로 억지 분류하지 않는다.

C2.2 그래프 모델

좌석 구역 S1 / S2 → 내부 통로 J → 공용 분기점 C
C → 통로 LA → 출구 EA → 사전 정의된 외부 집결 구역
C → 통로 LB → 출구 EB → 사전 정의된 외부 집결 구역

간선: from, to, length_m, allowed_profile, state, updated_at
state: AVAILABLE / BLOCKED / UNKNOWN
AVAILABLE은 사전 정의된 통행 허용 상태이며 현장 안전 보증이 아니다.

위험 통로와 미확인 통로를 제거한 뒤 Dijkstra로 허용 경로를 계산한다. 필수 버전은 거리만 사용한다. 확장 버전에서만 검증된 혼잡 입력을 대기 비용으로 추가한다. 혼잡 변화만으로는 작은 차이에 즉시 변경하지 않되, 위험 이벤트는 지연 규칙과 무관하게 즉시 기존 추천을 무효화한다.

계단 이용이 어려운 이용자는 allowed_profile로 사전에 검토한 경로만 선택한다. 해당 경로가 없으면 직원 지원을 요청하게 하며, 임의의 승강기·대기 장소를 만들어 안내하지 않는다. 위치가 미확인이어도 C 표지판은 C 자체의 정책을 유지할 수 있지만, 개인 앱의 출발 경로는 제시하지 않는다.

C3 표지판 동기화와 장애 처리

서버·앱·표지판은 (epoch, revision)으로 안내 버전을 식별한다. epoch는 서버의 새 실행·사건 세대를 구분하며 인증된 재접속 절차로만 갱신한다. 같은 세대에서는 revision이 증가하고 이전 버전은 거부한다. 각 명령은 멱등 처리하며 중복 명령은 응답만 반복한다.

  1. 위험 이벤트를 접수하면 현재 위험 경로를 즉시 무효화하고 영향 구역에 INVALIDATE를 전송한다.
  2. 새 경로 정책을 계산하여 해당 장치에 적용 요청한다. 앱은 ‘안내 갱신 중’을 표시한다.
  3. 장치가 표시 버퍼를 갱신한 뒤 해당 버전의 ACK를 보낸다.
  4. 필수 장치의 ACK가 모두 확인되면 앱에 새 경로를 활성화한다. 일부 장치가 실패하면 ‘현장 표시 적용 미확인’과 확인 필요 안내를 제공한다.
  5. 위험이 해제돼도 자동으로 최초 경로로 복귀하지 않고 운영자 확인 후 새 버전을 만든다.

무선망에서 완벽한 동시 전환을 보장할 수는 없다. ‘같은 버전을 목표로 배포하고 적용 불일치를 감지’하는 설계다. ACK는 실제 빛 출력이나 관객 인지를 검증하지 않으므로 하드웨어 시연에서는 화면을 직접 관찰하는 시험도 수행한다.

표지판은 수신 시 단조 시계를 사용해 남은 유효시간을 관리하고 지연·만료된 패킷으로 시간을 다시 늘리지 않는다. 앱도 메시지의 절대 만료시각과 수신 경과시간을 검증한다. 실험에서는 서버와 단말의 시간 차이를 측정하고, 큰 차이가 있으면 경로를 활성화하지 않는다.

연결이 끊기면 만료된 가변 화살표를 해제하고 ‘가변 안내 확인 불가’ 상태로 바꾼다. 기존 법정 유도등의 전원을 끄거나 가리지 않는다. 모든 경로 미확인 시에는 앱이 ‘확인 가능한 경로 없음’을 표시하고 현장 경보·직원 안내를 확인하도록 하며, 일률적인 정지·대기를 지시하지 않는다.

C5 하드웨어·화면 상세

C5.1 장치 제작

정확한 GPIO는 구매한 개발보드의 핀맵을 확인한 뒤 확정한다. 화면은 I²C 또는 SPI 연결 제품 중 한 종류로 통일하고 전압·소비전류·주소 충돌을 확인한다. 입력 버튼은 내부 풀업과 디바운스를 적용하며, 실제 화재 수신반의 전압을 GPIO에 직접 연결하지 않는다. 장치 부팅 시 출력은 방향 없음으로 시작한다.

소형 OLED에는 긴 한글 문장 대신 큰 화살표·A/B·연결 상태를 표시할 수 있다. 전체 문장은 관리자와 앱이 제공한다. 대형 LED 매트릭스로 확장할 때는 별도 전원·드라이버·휘도 검증을 해야 한다.
