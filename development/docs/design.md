# 매직아일랜드 시뮬레이션 개발 명세

기준일: 2026-11-11. 사용자 확정 사항과 계산한 개발용 기본 시나리오다. 시나리오 선택·설정 검증과 안내도 배치를 참고한 3D 지도 표시를 구현했다. 유입·개별 보행·운행 엔진은 아직 구현되지 않았다. 현재 아쿠아리움의 구현·실행 기록은 [아쿠아리움 설계](../aquarium/docs/design.md), 출처와 조사 한계는 [운영 조사](magic-island-research.md), 코드 재사용은 [재사용 내역](../aquarium/docs/reuse.md)을 참고한다.

최종 결과물은 3D 시뮬레이션, QR 관람객 화면, 영상 기반 인원·밀집도 분석 및 추천 서버, 관리자 대시보드로 구성한다. 전체 구성과 연동 순서는 [최종 소프트웨어 계획](software-plan.md)을 따른다. 이 문서는 그중 시뮬레이션의 명세다.

구현 순서와 기능별 완료 기준은 [개발 체크리스트](implementation-checklist.md)에 정리했다. 각 항목을 새 채팅 하나의 작업 범위로 사용한다. 세부 수치·동작은 이 명세를 기준으로 한다.

## 확정 범위와 표시

- 시뮬레이션 1차 범위는 매직아일랜드 3D 지도·개별 보행·유한 대기열·차량별 반복 탑승이다. QR 관람객 화면·영상 수신 및 인원/밀집도 분석·추천 서버·관리자 대시보드는 최종 제품에 포함하며 별도 연동 단계에서 개발한다. 비상 대피와 퍼레이드 관람 이동은 별도 범위다. 기존 정적 시안은 참고 자료다.
- 시설은 아트란티스·자이로드롭·자이로스윙·자이로스핀·혜성특급·아르카나라이드의 6개다. 쁘띠빵빵은 제외한다.
- 기존 아쿠아리움처럼 조작 가능한 3D로 구현하고, 2026 가이드맵의 섬 윤곽·성·다리·시설 배치와 시설별 입체적 특징을 살린다. 상대적 위치와 연결을 참고하고 시설 사이 공간을 넓힌다. 한눈에 시설·사람·보행로·대기열을 구별하는 것이 우선이다. 넓힌 거리와 폭은 가상 설계값이며 이동 계산에도 같은 미터 좌표를 사용한다.
- 다리에서 진입하고 같은 다리로 복귀한다. 공원 정문–다리 이동, 호텔 조기 입장, 재진입, 6개 시설 외 목적의 방문은 초기 모형에서 생략한다. 키·아동·보호자·일행을 구분하지 않고 시설 이용 조건을 충족하는 개인으로 추상화한다.
- 전체 보기에서 6개 시설 이름·대기 인원·운행 상태를 읽을 수 있게 한다. 시설별 단순 형상을 구별하고 성·호수는 위치를 알아보는 배경으로 사용한다. 혜성특급도 다른 시설처럼 지상에 표시하며 지하 절개·B1 표시는 사용하지 않는다. 섬 내부 대부분을 넓은 포장 보행 광장으로 두고 작은 식재 구획만 녹지로 구분한다. 보행자 수를 표시 편의로 잘라내지 않는다.

## 관측 시간과 체류

| 항목 | 최신 기준 | 성격 |
| --- | --- | --- |
| 시작 | 10:00, 구역 내 0명부터 다리로 순차 진입 | 사용자 확정 |
| 종료 | 19:00, 월드 오브 라이트 시작 시각 | 사용자 확정 |
| 관측 길이 | 9시간, 개장 전 예열 없음 | 위 시간 기준 |
| 개인 예정 체류 | **대기를 포함한 120–240분** | 사용자 확정 |
| 체류 추출 | 개인별 균등분포 `Uniform(120, 240)`분 | 개발 기본 가정 |
| 유입 | 아래 시간별 계획 인원을 구간 안에 무작위 배분 | 합성 실험 입력 |

2026-11-11 실제 공식 화면에서 개장 10:00과 월드 오브 라이트 19:00을 확인했다. [운영시간](https://adventure.lotteworld.com/) · [공식 공연 일정](https://adventure.lotteworld.com/enjoy/performance/list). 퍼레이드는 어드벤처 1층 퍼레이드 코스에서 진행되며 일정은 바뀔 수 있다. 19시는 이 실험의 고정 종료 시각이다.

- 체류 시계는 **실제 다리 진입**부터 시작한다. 이동·대기·승하차·운행·휴식이 모두 포함되며 대기시간을 다시 더하지 않는다.
- 개인 복귀 기준은 `실제 진입 시각 + 추출 체류시간`이다. 19시로 잘라 예정 체류를 줄이지 않는다. 18시 진입자의 개인 복귀 기준이 20–22시여도 19시에 관측만 끝낸다.
- 미이용 시설을 우선하고 재탑승을 허용한다. 이전의 목표 탑승 2–4회는 확정하지 않았으므로 고정 퇴장 조건으로 사용하지 않는다. 시설을 한 번씩 이용했다는 이유로 예정 체류를 강제 종료하지 않는다.
- 개인 체류 한도 도달 시 새 탑승·대기를 중단하고 다리로 복귀한다. 운행 중이면 하차 후 복귀하므로 실제 체류는 하차·귀환 보행만큼 늘 수 있다. 19시가 먼저 오면 진행 중 상태를 보존한다.
- **19시는 관측 종료이며 폐장이 아니다.** 폐장 이벤트·전원 퇴장·강제 탑승 완료를 적용하지 않는다. 퍼레이드 사전 자리잡기·실내 이동은 이번 1차에 자동 추가하지 않는다.
- 완료 대기와 종료 시 진행 중인 대기 경과시간·미완료 여부를 별도로 집계한다. 잔류 인원을 자동 포기·실패로 처리하거나 완료 대기 평균만으로 전체 대기를 대표하지 않는다.

### 유입·재현 규칙

- 시간 구간은 시작 포함·끝 제외다. 인원 수는 각 행대로 고정하고 구간 안의 초 단위 시각을 균등 무작위로 뽑아 정렬한다. 분당 평균을 고정 생성 간격으로 사용하지 않는다. 19:00에는 새 방문객을 생성하지 않는다.
- 입장·개인 체류·선호 난수를 구분한다. 같은 설정·시드에서는 진행·되감기와 무관하게 같은 결과를 재현한다. 기본 비교 시드는 기존 20261104를 유지할 수 있다.
- 표는 **다리 경계 도착 수요**다. 몸체 공간이 없으면 실제 진입을 늦추고 계획/실제 시각을 구분한다. 19시까지 들어오지 못한 수요는 경계 밖 미진입으로 집계한다.
- 각 시점의 `실제 진입 = 실제 복귀 + 구역 내 잔류`, 종료 시 `계획 10,350 = 실제 진입 + 미진입 수요`를 점검한다. 인원을 삭제하거나 추가해서 맞추지 않는다.
- 기존 `daily_visitors`를 재사용한다면 관측 입력은 10,350명이다. 하루 기준 11,500명을 넣어 9시간에 재정규화하지 않는다. 시간별 고정 인원 입력은 아쿠아리움의 가우스 분포와 달라 별도 지원이 필요하다.
- 시간당 1,500명 * 평균 체류 3시간은 정상상태에서 약 4,500명 규모다. 변동 유입·초기 0명의 실제 피크 결과로 보고하지 않는다. 수천 명 동시 보행을 대상으로 성능을 검증하고 논리 인원을 잘라내지 않는다.

## 시설 운행과 공간

| 시설 | 정원 | 사용할 근거 | 남은 보정 항목 |
| --- | ---: | --- | --- |
| 아트란티스 | 대당 8명 | 과거 보고서의 차량 8대·운행 110초·약 30초 간격·2대 동시 승하차 | 승하차 분리·현장과의 차이 |
| 자이로스핀 | 40명 | Mega Disk'O 40: 운행 120초 + 승하차 합계 120초 | 현장 프로그램 차이 |
| 아르카나라이드 | 16명 | Speedway 8: 운행 90초 + 승하차 합계 60초 | 성인 8+아동 8 사양과 추상 이용자 구분 |
| 자이로스윙 | 40명 | 일반 모델 900명/시간, 만석 환산 전체 회차 약 160초 | 현장 회차·승하차 분리 |
| 자이로드롭 | 40명 | 운영사 정원·제조사 곤돌라 1대 | 전체 회차·승하차 |
| 혜성특급 | 26명 | 운영사 정원·제조사 설치 사례 | 투입 편성·운행·승하차·출발 간격 |

출처·확인 수준은 [운영 조사](magic-island-research.md)에 있다. 미확인 값은 구현 전에 가정값과 조절 범위를 정한다. 제조사 최대 처리량을 현장 실측으로 사용하거나 자료 공백이 해결됐다고 표현하지 않는다.

- 대기 합류 → 승차 → 확인 → 운행 → 하차 → 다음 선택·복귀로 진행한다. 도착순 탑승, 빈 좌석 출발, 실제 보행 지연을 반영한다. 정원·차량을 초과하거나 사람을 좌석으로 순간 이동시키지 않는다.
- 출발은 최소 간격·승하차 완료·차량 가용·코스 구간 가용을 모두 만족해야 한다. 30초마다 새 차량을 생성하거나 공연의 정시 시작 규칙을 그대로 복제하지 않는다.
- 제조사 승하차 합계에 안전 확인·하차 시간을 중복 가산하지 않는다. 분리할 때는 합계를 유지하고 분리 비율을 가정으로 기록한다.
- 공간 초기안은 다리·주 보행로 유효 폭 8m, 지선 5m, 대기 통로 폭 1.2m·앞뒤 간격 0.8m, 통로와 줄 사이 완충 1.5m, 시설 출구 3m다. 실측치·법정 기준이 아니다.
- 줄·하차 합류·이탈 공간을 보행로와 분리한다. 물리적 자리가 차면 합류를 중단하고 다른 시설을 선택한다. 통로 쪽 줄 연장·숨겨진 무제한 대기는 사용하지 않는다.
- 기존 대기 상한 200/150/120/120/120/80명은 **미검증 공간 초안**이다. 아트란티스 200명은 960명/시간 처리에서 약 12.5분 분량이다. 긴 대기를 재현하려면 구획을 넓히고 실제 자리 수를 검증한다. 2–4시간 체류가 긴 시설 대기를 보장하는 것은 아니다.
- 시설 가중치·개인 선호·이동시간·알 수 있는 대기정보·재탑승 감점을 구분한다. 논문 평균을 6개 시설 선택 확률로 바꾸지 않는다. 대기 포기 정책·미확인 운행값·물리적 대기 자리 배치에 따른 공간 조정은 남은 구현 설계 항목이다.

## 개발 경계와 검증

- 매직아일랜드를 별도 시나리오로 추가하고 기존 아쿠아리움 지도·설정·기록을 보존한다. 지도 고정 로드·해양 선호·공연 전용 상태·아쿠아리움 UI 명칭을 구분한다.
- 기존 엔진의 개인 deadline을 폐장으로 자르는 처리와 폐장 후 1시간 horizon을 복사하지 않는다. 관측 종료·운행 종료·개인 복귀 기준을 분리한다.
- 결과에는 시나리오·지도/설정 해시·시드·출처/가정, 시간별 계획/실제 진입·복귀·잔류·미진입, 완료/진행 대기·탑승 완료·가동률·포기·보행 지연을 구분한다. 구체 API 형식은 구현 때 기존 API와 함께 정한다.
- `web-admin`의 가상 추천·절약 시간·장치 상태는 새 시뮬레이션 결과가 아니다. DB·인증·새 백엔드는 1차 필수 조건이 아니다.
- 입력 검증: 시간별·누적 합계, 관측 비중 90%, 피크 비중 40%, 19시 이후 제외, 시드 재현성을 확인한다.
- 기능 검증: 만석·빈 좌석 출발·대기 이탈·정원/차량 보존, 체류 만료 중 하차·복귀, 18시 이후 입장자의 19시 상태 보존, 경계 진입 지연·미진입을 확인한다.
- 공간·성능 검증: 전체 보기의 시설 구별, 통로의 대기열 침범 방지, 양방향 다리, 40명 하차 직후 합류, 수천 명의 재생·되감기를 점검한다.

이 명세의 시간·인원·체류와 구현 상태를 현재 개발 기준으로 사용한다.

## 시나리오 선택과 독립 실행 기반 (1번 완료)

기존 아쿠아리움 전체는 `../aquarium/`, 새 롯데월드는 `../lotteworld/`에 분리했다. 각 폴더는 다른 시나리오 폴더 없이 실행할 수 있다. 개발 루트의 `run.py`·`run.ps1`은 `--scenario aquarium|magic-island`와 `--mode server|cli`로 독립 프로세스·작업 디렉터리를 선택한다. 기본 시나리오를 추정하지 않고 명시적 선택을 요구한다. 개별 폴더의 기존 진입점은 계속 사용할 수 있다.

매직아일랜드 설정 계약·API는 [설정 계약](../lotteworld/docs/configuration.md), 실행 명령은 [롯데월드 README](../lotteworld/README.md)를 따른다. 해양 선호·지도·아쿠아리움 화면을 매직아일랜드에 주입하지 않는다. 지도는 `map_ready`·미터 좌표 형상, 런타임은 `runnable: false`이며 재생 요청은409를 반환한다. 이번 단계의 시간표·체류 검증은 입력의 일관성 검사이며 3번의 실행 구현이 아니다.


## 매직아일랜드 지도와 시설 표시 (2번 완료)

로컬 국문 가이드맵 4쪽의 섬·다리·성·시설 상대 배치를 직접 확인하고 독립 Three.js 장면으로 구성했다. 중앙의 푸른 첨탑 성, 왼쪽 위 자이로드롭, 오른쪽 위 자이로스윙, 오른쪽 아트란티스, 왼쪽 아래 혜성특급·자이로스핀, 아래쪽 아르카나라이드와 오른쪽 아래 진입 다리를 배치했다. 탑·곤돌라, 지지대·진자, 물길·고가 코스, 디스크·U자 레일, 열차·굽은 코스, 소형 차량·순환 레일로 시설을 구별한다. 혜성특급은 요구에 따라 지상에 보이는 추상 모형이며 실제 시설 층을 재현하는 지도가 아니다.

`lotteworld/configs/map.json`의 같은 미터 좌표로 34개 꼭짓점의 비정형 섬, 시설·대기·하차·식재 구획, 참조 경로를 표시한다. 성 정면은 다리 방향으로 회전하고 성 정문·앞 광장·사선 다리를 동일한 축에 맞췄다. 주 섬과 남쪽 메이플 돌출부, 다리 양옆 수면 홈을 안내도 상대 윤곽에 맞춰 구성했다. 섬 내부는 시설·성·건물·식재·대기/하차 예약 구획을 제외한 넓은 포장 보행 공간이다. 기존의 가는 통로만 보행 가능한 모델은 사용하지 않는다. 녹지는 12개 작은 식재 구획으로 한정하고 나무도 그 안에 배치한다. `public_walkable`이 반경을 포함해 이 공간과 다리의 보행 가능 여부를 판정한다.

그래프의 다리·주 동선 8m, 입구 지선 5m, 퇴장 지선 3m는 연결 검증용 참조 통행 폭이며 섬의 전체 보행 폭을 제한하지 않는다. 표시한 접근·복귀 거리는 이 그래프의 최단 경유 거리다. 넓은 광장 전체에서의 자유 이동 최단 거리나 실제 현장 이동시간을 뜻하지 않는다. 후속 보행 구현은 포장 영역을 이용하고 장애물·밀도·개인 반경을 반영해야 한다. 대기 외곽 24×12m와 하차 합류 8×6m는 공간 예약이며 실제 줄·자리 정원·이탈 보행은 4번에서 검증한다.

드래그 회전·휠 확대·오른쪽 드래그 이동, 터치 회전·확대·이동, 전체 보기·위에서 보기·가림 줄이기·선택 시설 확대, 모형 클릭·키보드 목록 선택을 지원한다. 대기 인원·운행은 미집계다. `map_ready: true`, `map_view: guide-map-3d`, `runnable: false`로 지도와 엔진의 준비 상태를 구분한다. [3D 지도 검증 기록](verification/magic-island-map3d.md), [설정 계약](../lotteworld/docs/configuration.md), [재사용 내역](../lotteworld/docs/reuse.md)을 참고한다.
