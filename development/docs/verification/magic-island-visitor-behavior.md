# 매직아일랜드 방문객 선호와 반복 이용 검증

2026-11-19에 [체크리스트 7번](../implementation-checklist.md#연속-시연-엔진과-지도-개발)을 구현하고 검증했다. 시간은 시뮬레이션 내부 초를 사용한다. [설정 계약](../../lotteworld/docs/configuration.md#방문객-선호와-반복-이용)

## 행동과 재현성

- 같은 입장 시각과 시드에서 선호 시설을 바꾸자 첫 목적지가 아트란티스와 아르카나라이드로 달라졌다. 아트란티스 선호형의 체류가 60초인 조건에서는 예정 체류 만료까지 공공 연결점에 머물렀다.
- 혜성특급에 앞선 대기객 40명이 있는 조건에서 멀리 있는 방문객은 혜성특급으로 향했다. 입구에 도착하자 빈자리가 있었지만 관찰한 대기가 개인 한도 300초를 넘겨 합류를 포기했다.
- 아트란티스의 대기가 180초를 넘는 조건에서 자동 포기가 시작됐다. 옆 통로에 도착할 때까지 예약 자리를 유지한 뒤 해제했고, 공공 경로로 나온 뒤 이동을 재개했다. 하차 이력은 실제 하차 보행을 시작할 때 기록된다.
- 한 방문객이 여섯 시설을 모두 이용하고 여러 시설을 반복 탑승한 뒤 예정 체류가 만료되어 퇴장했다.
- 기본 시드 `20261119`와 240명 설정에서 37초마다 상태를 읽은 실행과 3,600초까지 한 번에 진행한 실행을 비교했다. 시설 선택, 대기 포기·자리 해제, 하차 완료의 방문객 ID·시설 ID·시각·발생 순서가 모두 일치했고, 실행 ID를 제외한 최종 상태도 같았다. 별도 30초 표본 실행에서 하차 완료 1,672건(동일 방문객·시설 재이용 430건), 대기 포기와 자리 해제 각 18건을 관찰했다.
- 1,500명 조건에서 7,200초까지 30초마다 인원 보존식과 정원, 자리 중복을 확인했다. 아트란티스·자이로드롭·자이로스윙·자이로스핀에서 만석을 관찰했다. 종료 표본은 누적 진입 2,662명, 현재 체류 1,499명, 누적 퇴장 1,163명이었고, 대기 포기와 자리 해제를 각각 601건 관찰했다.

## 실행한 검사

| 검사 | 결과 |
| --- | --- |
| `python -m unittest discover -s tests -p test_visitor_behavior.py -v` | 방문객 행동 5개 통과 |
| `python -m unittest discover -s tests -v`와 동일한 전체 탐색 | 54개 통과. Windows 샌드박스의 기본 임시 경로에서 권한 오류가 발생해 실행 세션에서 `tempfile.mkdtemp`가 작업 공간 내 임시 폴더를 만들게 조정했다. |
| `node --test --test-isolation=none tests/route.test.mjs tests/navigation.test.mjs` | 경로·대기줄 검사 2개 통과 |
| `python -m lotteworld_sim.server --validate-only` | 선호·시설 운행 설정 및 보행 경로 검증 통과 |
| HTTP 상태·설정 재시작 회귀 | `/api/state`에서 선호 유형·하차 횟수와 적용 중인 선호 해시를 확인했다. 실행 중 저장한 선호는 `/api/meta`에 표시됐고, 재시작 후 새 실행에 적용됐다. QR 세션과 모의 추천 회귀도 통과했다. |

3D 방문객 표시와 운영 지표 연결은 체크리스트 8번 범위다. 위 집계는 가상 시연 입력의 결과이며 현장 보정에는 시설별 실제 대기·이용·포기 자료가 필요하다.

## 현재 위치에서 시설 입구로 이동

배경 방문객의 공공 보행 경로를 현재 위치와 시설 입구 바깥 지점을 직접 연결하는 보행망으로 갱신했다. 다리를 건너는 동선과 줄·승하차 구간은 각각 전용 경로를 사용한다. 하차 지점과 시설 입구 바깥 위치에서 출발하는 경로가 여섯 시설과 퇴장 다리까지 이어지는 것을 확인했다. 시설에 도착했을 때 줄에 들어갈 수 없으면 도착 지점에서 다른 목적지로 이어진다.

방문객 행동 12개, 물리 대기열 7개, 시설 운행 10개 검사가 통과했다.

## 광장 산책과 걷는 도중 시설 선택

갈 만한 시설이 없으면 보행 가능한 포장면에서 목적지 좌표를 무작위로 고른다. 주변에 사람이 적은 후보를 조금 더 자주 고르고, 방문객 반경을 반영해 녹지·시설·해안 경계를 피한다. 산책 목적지로 사용했던 고정 지점 14개와 지도 위의 노란 점 표시를 제거했다.

방문객마다 산책 도중 8~14 내부 초 간격으로 대기열 상태를 다시 확인하고, 산책 구간이 더 일찍 끝나면 도착할 때 확인한다. 개인의 대기 허용 시간과 남은 체류 시간 안에 갈 수 있는 선호 시설이 생기면 현재 좌표에서 해당 입구로 향한다. 입구로 이동 중인 사람도 대기열의 남은 자리를 계산할 때 포함한다.

동일한 지도·시드·목표 인원 1,500명으로 기존 방식과 새 방식을 비교했다. 내부 5~20분 사이 11개 시점에서 아르카나라이드와 매직캐슬 사이(`140≤x<193, 151≤z<230m`)의 산책 인원 비율이 53.8%에서 18.7%로 낮아졌다. 산책 방문객이 지나고 있던 16m 격자 칸은 시점당 평균 63.9개에서 124.7개로 늘었다.

방문객 행동 15건, 배경 시뮬레이션 4건, 물리 대기열 7건과 브라우저 보행 보간·경로 탐색 검사를 통과했다. 걷던 위치에서 시설로 방향을 바꾸는 동작, 체류 종료 시 다리로의 이동, 여러 방문객이 남은 대기 자리 한 곳을 확인할 때 정원을 지키는 동작을 확인했다. 격리 Chrome에서 노란 표시 제거와 실시간 방문객을 확인했다.

3000번 서버 재시작 후 동일한 지도 해시의 새 실행에서 배경 방문객 1,500명, 이동 궤적의 갱신, 시설별 대기 정원과 인원 집계의 일치를 확인했다.

기본 1,500명 설정에서 QR 세션 분리, 권장 시설 선택, 실시간 대기에 따른 추천 변경, QR 추천 수락부터 대기·탑승·하차까지의 공유 상태를 확인했다. 여러 차례 방문객이 교체되는 장시간 점프 회귀는 방문객 120명 조건으로 검증했다.
