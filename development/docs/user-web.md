# 사용자 웹

기준일: 2026-11-18. QR로 접속하는 시연 참여자의 모바일 웹 요구사항이다. 로컬 사용자 웹에서 공통 QR 주소, 가상 캐릭터 식별과 시설 선호 순위 입력을 제공한다. 전체 방향은 [소프트웨어 계획](software-plan.md), 구현 순서와 완료 표시는 [체크리스트](implementation-checklist.md)를 따른다.

## 목적과 사용자 흐름

사용자가 자신의 추천을 확인·수락하고 보상과 가상 캐릭터 상태를 확인하는 화면이다.

`공통 QR 접속 → 사용자별 세션·캐릭터 연결 → 시설 선호 입력 → 추천 확인 → 수락 → 수락 보상 표시·이동 상태 확인 → 이용 완료 후 다음 추천`

보상은 유효한 추천 수락이 서버에서 확정되면 지급한다. 이동·대기·탑승·이용 완료를 기다리지 않는다. 같은 추천 수락에 중복 지급하지 않으며 지급 실패 시 처리 중 상태와 재조회/재시도를 지원하는 방향으로 구현한다. 보상량·한도·취소/회수 정책은 미정이다.

## 표시와 조작

| 항목 | 사용자 웹의 역할 |
| --- | --- |
| 세션·선호 | 자신에게 연결된 캐릭터를 식별하고 시설 선호를 입력 |
| 추천 | 시설 한 곳·추천 이유·예상 대기·이동 경로·산정 상태 확인, 추천 수락 |
| 보상 | 자기 추천 수락의 보상 지급 상태와 지급 결과 확인 |
| 3D 지도 | 기존 지도·시설 자원을 재사용해 자기 캐릭터의 현재 가상 위치·목적지·경로를 강조 |
| 진행 상태 | 이동 중·대기 중·탑승 중·다음 추천 가능 상태 표시 |
| 지도 조작 | 휴대폰에서 회전·확대·이동하고 자기 위치로 시점 복귀 |

지도 위치는 GPS가 아닌 **‘시뮬레이션 속 내 위치’**로 표시한다. 목적지 시설은 줄 입구를 기준으로 연결한다. 대기시간 미집계와 알려진 0분을 구분하고 데이터 출처·오래된 상태를 유지한다. 시뮬레이션 전체의 시작/종료·초기화·배속 조작은 사용자 웹의 기능으로 두지 않는다. 예상 대기시간과 지급 상태는 사용자에게 필요한 정보이므로 표시한다.

## 공통 서버·시뮬레이션 웹과의 연결

- 사용자 웹은 추천 수락 의사를 서버에 전달하고 서버가 확정한 결과를 표시한다. 브라우저 자체에서 보상 지급이나 이용 완료를 확정하지 않는다.
- 위치·진행 상태는 공통 서버가 제공하는 같은 `context`·`session_id`·`character_id`·`revision`을 사용한다. [시뮬레이션 웹](simulation-web.md)에 표시되는 자기 캐릭터와 같은 개체다.
- 캐릭터 이동·대기·탑승은 엔진이 계산하고 양쪽 웹은 같은 결과를 표시한다. 3D 지도·시설 렌더링 자원은 재사용하되 화면 구성과 조작의 역할은 구분한다.
- 로컬 사용자 웹은 공통 서버의 `/user?sign_id=magic-island-west`에서 열고, 서버 발급 쿠키로 세션을 찾는다. 운영 주소와 배포 방식은 배포 단계에서 정한다. [공통 데이터 계약](contracts/recommendation-v1.md)

## 완료 시 확인할 것

여러 휴대폰에서 세션과 캐릭터가 섞이지 않고, 추천 수락과 보상 표시가 자기 세션에 연결돼야 한다. 양쪽 웹의 자기 캐릭터 위치·목적지·진행 상태가 같은 서버 버전에 대응해야 한다. 모바일 조작·가림·3D 성능을 실제 휴대폰에서 확인하고 필요한 표시량·장식을 조절한다. 새로고침/재접속과 미집계·갱신 지연 상태도 확인한다.

사용자 웹에서는 가상 캐릭터 ID와 초기 위치를 확인하고 표지판이 안내하는 자이로스핀·혜성특급·자이로드롭의 1~3순위를 저장한다. 같은 브라우저 프로필에서 다시 열면 서버에 저장된 순위가 복구된다. 사용자 추천 API는 저장된 위치, 순위와 모의 현황을 사용해 세 안내 대상 중 추천을 계산한다. 추천·보상 화면과 캐릭터 3D 표시는 후속 작업이다. [로컬 실행 방법](../lotteworld/README.md#qr-사용자-진입과-선호-입력)
