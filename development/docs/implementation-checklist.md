# 매직아일랜드 기능별 개발 체크리스트

기준일은 2026-11-19다. [최신 개발 명세](design.md)를 구현하기 위한 작업 목록이다. **체크 항목 하나를 새 채팅 하나의 작업 범위**로 삼는다. 공통 데이터 계약, 로컬 모의 추천 API, QR 사용자 진입과 선호 입력을 완료했다. 시뮬레이션은 1–6번을 완료했고 다음 미완료 항목은 7번 방문객 선호와 반복 이용 행동이다.

이 목록은 공통 서버·사용자 웹·시뮬레이션 웹과 엔진의 작업을 구분한다. 영상 기반 분석과 관리자 대시보드를 포함한 전체 범위와 순서는 [최종 소프트웨어 계획](software-plan.md)을 따른다.

## 공통 서버·사용자 웹·시뮬레이션 웹 개발

세 구분은 화면과 계산의 담당을 나타낸다. 추천 서버를 먼저 로컬에서 구현하고 출처가 명시된 모의 현황으로 검증한 뒤 엔진을 연결한다. 각 체크 항목의 소유 범위와 완료 여부를 따로 확인하며 화면만 구현해 서버·엔진이 완료됐다고 표시하지 않는다.

### 공통 서버·데이터

- [x] **공통 데이터 계약** — 시설 ID·지도 버전, 사용자 세션·가상 위치, 선호 순위, 시설 운영·대기 상태, 추천과 수락·이동·이용·보상 상태를 정의한다. 시뮬레이션 실행 ID·시각 및 데이터 출처를 구분한다. **완료 기준:** 기존 설정·지도·경로 코드와 대조한 계약 문서에 필수 필드, 자료형·단위, 예시, 상태 전이와 미집계 처리가 있고, 이후 모의 데이터와 시뮬레이션 상태를 같은 추천 입력으로 연결할 경계가 명확하다. 실제 구현되지 않은 API를 완료된 것처럼 표시하지 않는다.

  문서: [공통 데이터 계약 v1](contracts/recommendation-v1.md), [검증 기록](verification/recommendation-data-contract.md). 기존 지도에서 계산한 경로를 포함한 모의/시뮬레이션 입력과 추천·수락·수락 보상·이용 완료 JSON 예제를 대조했다. 시뮬레이션 입력과 workflow는 구조 검증용 가정이며 실행 결과가 아니다.
- [x] **추천 서버 최소 구현** — 시설별 선호 순위, 가상 위치와 이동거리, 이용 가능 상태, 예상 대기시간을 고려해 다음 시설 한 곳과 추천 이유를 반환한다. `GET /api/recommendation/mock`과 `POST /api/recommendation`을 제공한다. [로컬 실행·호출 예시](../lotteworld/README.md#로컬-추천-api)와 [검증 기록](verification/recommendation-server-minimum.md)을 참고한다.
- [ ] **추천 수락·보상 API** — 유효한 수락을 확정하고 같은 추천 수락에 중복 지급 없이 보상 기록을 생성·조회한다. 이동·대기·탑승·이용 완료는 지급 조건이 아니다. 사용자 웹은 이 API의 처리·지급 결과를 표시한다.

### 사용자 웹

요구사항: [사용자 웹](user-web.md). 참여자가 자신의 추천·보상·캐릭터 상태를 확인하는 모바일 화면이다.

- [x] **QR 사용자 진입과 선호 입력** — 공통 QR 주소에 접속한 브라우저별 세션과 캐릭터를 발급하고, 표지판 `[101, 149]`m 주변에 겹침 없이 배치한다. 방향 안내판이 가리키는 자이로스핀·혜성특급·자이로드롭의 전체 선호 순위를 저장하고 같은 쿠키로 캐릭터와 순위를 복구한다. 저장된 위치와 순위로 안내 대상에 대한 모의 추천을 계산한다. [로컬 실행 방법](../lotteworld/README.md#qr-사용자-진입과-선호-입력) · [검증 기록](verification/qr-user-entry-and-preferences.md)
- [ ] **추천·수락·보상 화면** — 추천 시설·이유·예상 대기와 수락 버튼을 표시하고 서버가 확정한 보상 지급 상태를 보여준다. 이용 완료 후 다음 추천을 표시한다. UI에서 독립적으로 지급·이용 완료를 확정하지 않는다.
- [ ] **자기 캐릭터 중심 3D 지도** — 기존 지도·시설 자원을 재사용해 현재 가상 위치·목적지·경로·진행 상태를 표시하고 자기 위치로 시점을 복귀한다. 실제 휴대폰에서 조작·가림·성능을 검증한다. 별도 2D 지도는 기본 범위에 넣지 않는다.

### 시뮬레이션 웹·공통 연동

요구사항: [시뮬레이션 웹](simulation-web.md). 전체 방문객·줄·시설 운행과 QR 사용자 캐릭터를 관찰하는 화면이다. 엔진 자체의 구현은 아래 3–9번에서 관리한다.

- [ ] **전체 공간 3D 시연 화면** — 시간 표시·재생바 없는 맵 중심 화면에 엔진의 방문객·대기열·운행 상태를 연결한다. 개별 사용자 추천 수락·보상 내역 조작은 사용자 웹의 역할로 구분한다.
- [ ] **추천 수락과 엔진 이동 연동** — 공통 서버의 수락을 엔진에 연결해 해당 캐릭터가 목적지로 이동하도록 한다. 양쪽 웹은 같은 `context`·`character_id`의 위치·진행 상태를 표시한다. 이용 완료 후 현재 위치와 최신 현황으로 다음 추천을 계산한다. 추천 수락 인원은 후속 혼잡 계산에 반영한다.
- [ ] **다중 사용자·2시간 현장 시연** — 여러 휴대폰의 세션/캐릭터가 섞이지 않고 사용자 웹과 시뮬레이션 웹이 같은 상태를 표시하는지 확인한다. 수락 보상·이동·이용 후 다음 추천의 흐름과 연속 실행을 검증한다.

위치는 시뮬레이션의 가상 좌표이며 GPS를 사용하지 않는다. 보상은 추천 수락에 대한 보상이며 실제 시설 이용 인증과 구분한다. 2시간은 평가/검증 기준이고 자동 종료 조건이 아니다. 두 웹과 공통 서버의 URL·배포 단위는 구현 때 정한다.

## 완료 범위: 로컬 추천 서버 최소 구현

가상 사용자 1명의 위치·시설 선호를 입력받아 모의 시설 현황과 경로 거리를 조회하고 추천 시설 한 곳과 이유를 반환한다.

- **입력:** 기존 6개 시설 ID·지도 해시, 테스트용 `session_id`/`character_id`와 가상 위치, 선호 순서, 출처가 `mock`인 운영/대기 현황, 해당 위치에서 시설 입구까지의 경로. 필드·검증 규칙은 [공통 데이터 계약](contracts/recommendation-v1.md)을 따른다.
- **구현:** 입력 검증·`baseline-v1` 추천 계산과 로컬 조회 API. 기본 출발점은 기존 지도 노드 3곳이며 저장한 광장 경로의 거리 합산값을 사용한다. 유효한 보행 위치에 경로가 없으면 `route_unavailable`을 반환한다.
- **출력:** 선택 시설 하나·추천 이유·선호/대기/거리 근거·출처·실행/상태 버전. 후보가 없으면 그 상태와 제외 사유를 반환한다.
- **검증:** 선호·위치·대기 입력이 추천을 바꾸는 사례와 운영 불가·미집계·오래된 상태·후보 없음·잘못된 입력을 확인했다. 동일한 전체 입력으로 추천 결과를 재현했다. 지도 변경 후 현재 경로를 다시 생성했으며, PowerShell에서 자이로스핀 추천·대기 300초·경로 약 57.8m를 직접 확인했다. `--host`·`--port`·`--mock-data`로 주소·포트·모의 데이터 저장 경로를 지정한다. [재검증 기록](verification/recommendation-server-minimum.md#자이로드롭-출구-지도-변경-후-재검증)
- **예제 범위:** 고정 예제의 `simulation` 표기는 계약 검증용이다. 실제 QR 세션의 추천 경로는 사용자 웹 기능 설명에 정리했다.

공통 서버의 다음 미완료 항목은 **추천 수락·보상 API**다. [QR 시연 순서](software-plan.md#qr-기반-가상-사용자-시연)에 따라 저장된 사용자 세션과 추천을 사용해 수락·보상을 연결한다.

## 연속 시연 엔진과 지도 개발

공통 기준은 **종료 시각을 정하지 않은 연속 실행, 6개 시설, 동일 사용자 상태를 공유하는 두 3D 화면**이다. 기존 10:00–19:00·계획 유입 10,350명·체류 120–240분 설정은 이전 계획으로 보존한다. 현재 배경 순환은 별도 연속 시연 설정을 사용한다. 각 항목에는 필요한 검증과 관련 문서 갱신을 포함한다.

- [x] **1. 시나리오 선택과 설정 분리** — 기존 아쿠아리움과 매직아일랜드의 지도·운영·선호 설정을 구분하고 서버·실행 진입점에서 선택할 수 있게 한다. **완료 기준:** 아쿠아리움이 기존대로 실행되고, 새 시나리오 설정을 독립적으로 불러오며 잘못된 설정을 검출한다. 이후 기능을 연결할 기반까지 작업한다.

  구현 위치는 `aquarium/`·`lotteworld/` 독립 프로젝트와 루트 `run.py` 선택 진입점이다. [설정 계약](../lotteworld/docs/configuration.md) · [검증 기록](verification/scenario-isolation.md)

- [x] **2. 매직아일랜드 3D 지도와 시설 표시** — 안내도에 대응하는 주 섬·메이플 돌출부·호수·6개 시설의 상대 배치와 입체 특징을 구성하고 성 정면·앞 광장·사선 다리를 같은 직선 축으로 연결한다. 섬 내부 대부분은 넓은 포장 보행 광장으로 두고 녹지는 작은 식재 구획으로 제한한다. 혜성특급은 지상 모형으로 표시한다. **완료 기준:** 전체 보기에서 시설·동선을 구별하고 같은 미터 좌표의 3D 형상과 보행 공간 판정을 사용한다. 다리에서 입출구까지의 연결, 회전·확대·이동·시점 복귀·가림 처리와 모형 선택을 확인한다. 최종 대기 자리 수는 4번에서 검증한다.

  구현: `lotteworld/web/map3d.js`·`rides.mjs`, `configs/map.json`·`map_geometry.py`. [3D 지도 검증 기록](verification/magic-island-map3d.md)과 [설정 계약](../lotteworld/docs/configuration.md)을 참고한다. `public_walkable`로 넓은 포장 영역을 정의했으며 `navigation.mjs`가 그 면을 활용한 표시 경로를 찾는다. 6개 대기줄은 공연 대기줄 형태의 정적 표시다. [추가 검증](verification/queue-and-open-plaza.md)을 참고하며 실제 보행·대기·운행 엔진 완료와 구분한다.

  시연 화면은 3D 지도에 화면 대부분을 할당하고 시설을 선택할 때만 상세 패널을 연다. 참조 동선과 시설 확대는 패널에서 각각 조작한다. [시뮬레이션 웹 요구사항](simulation-web.md#기본-시연-화면과-시설-선택)

- [x] **3. 연속 유입·개인 체류·퇴장** — 수동 종료까지 개인별 예정 체류에 따라 배경 방문객을 퇴장시키고 빈자리를 보충한다. `GET /api/state`의 현재 체류·누적 진입·누적 퇴장으로 보존식을 확인할 수 있다. 240명 기본 설정과 1,500명 비교 조건에서 인원 보존·상한을 확인하고, 배경 순환 중 두 QR 세션의 식별자·캐릭터·선호·추천 유지도 검증했다. 추천 수락·보상 연결은 공통 서버 후속 항목이다. [설정 계약](../lotteworld/docs/configuration.md#연속-시연-설정과-상태) · [검증 기록](verification/magic-island-continuous-arrivals.md)

- [x] **4. 물리적 대기열과 승하차 보행** — 여섯 시설의 실제 자리 합류·전진·이탈, 승차 지점 접근, 전용 하차 보행과 공공 광장 합류를 구현했다. 만석이면 다른 시설로 이동하며, 하차한 방문객은 빨간 출구를 한 명씩 1 내부 초 간격으로 통과한다. 대기 자리 720개와 자리 중복 방지, 난간·예약 구획의 간섭, 체류 만료 후 다리 퇴장을 검증했다.

  시설별 대기 구획은 1회 탑승 정원의 2.5배 이상을 수용한다. 자리 예약·보행 상태는 `/api/state`에서 확인할 수 있다. [공간·런타임 검증](verification/magic-island-physical-queues-and-boarding.md) · [설정·상태 계약](../lotteworld/docs/configuration.md#물리적-대기열과-승하차-보행)

- [x] **5. 회차 단위 놀이시설 운행** — 자이로드롭·자이로스윙·자이로스핀·아르카나라이드의 승차·확인·운행·하차를 자동 반복한다. 선두 대기객 순서, 정원 이내 빈 좌석 출발, 장치 재사용과 탑승 중 체류가 만료된 방문객의 하차·다리 퇴장을 확인했다. 자이로드롭 만석 회차에서 마지막 방문객의 빨간 출구 통과까지 다음 승차가 지연된다. [시간의 근거와 조절 범위](magic-island-research.md#시연용-초기값) · [검증 기록](verification/magic-island-ride-operations.md)

- [ ] **9. 장시간 연속 실행과 성능 검증** — 2시간의 현장 평가 동안 연속 실행하며 사람·차량 보존, 대기 공간, 다중 휴대폰 접속과 메모리·응답 성능을 검증한다. **완료 기준:** 최소 2시간 동안 자동 종료·주기적 사용자 상태 초기화·인원 무한 누적 없이 동작하고 실행 조건·측정 결과·제약을 기록한다. 목표 인원과 부하 조건은 검증 전에 확정한다. 2시간은 평가 시간과 검증 기준이며 시뮬레이션 자동 종료 시각이 아니다. 9시간 시나리오 실행은 현재 완료 조건에 넣지 않는다.
