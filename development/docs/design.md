# 매직아일랜드 시뮬레이션 개발 명세

이 문서는 기존 지도·시설 명세와 이전 시간표 시나리오의 근거를 보존한다. 2026-11-19 기준 시나리오 선택·설정 검증, 3D 지도 표시, 배경 방문객의 연속 유입·개인 체류·퇴장, 개별 보행과 시설 운행, 방문객 선호와 반복 이용 행동을 구현했다. 아쿠아리움의 구현·실행 기록은 [아쿠아리움 설계](../aquarium/docs/design.md), 출처와 조사 한계는 [운영 조사](magic-island-research.md), 코드 재사용은 [재사용 내역](../aquarium/docs/reuse.md)을 참고한다.

최종 결과물은 3D 시뮬레이션, QR 관람객 화면, 영상 기반 인원·밀집도 분석 및 추천 서버, 관리자 대시보드로 구성한다. 전체 구성과 연동 순서는 [최종 소프트웨어 계획](software-plan.md)을 따른다. 이 문서는 그중 시뮬레이션의 명세다.

구현 순서와 기능별 완료 기준은 [개발 체크리스트](implementation-checklist.md)에 정리했다. 각 항목을 새 채팅 하나의 작업 범위로 사용한다. 세부 수치·동작은 이 명세를 기준으로 한다.

## 현재 우선순위와 이전 시간표의 취급

현장 시연은 고정 종료 시각 없이 연속 실행하는 방향이다. 로컬 추천 서버는 [모의 시설 현황과 경로](../lotteworld/README.md#로컬-추천-api)를 사용한다. 사용자 웹과 시뮬레이션 웹은 기존 3D 지도를 재사용하고 보상은 추천 수락 확정에 대해 지급한다. 시뮬레이션 기본 화면은 시간 표시·재생바 없이 3D 맵 중심으로 구성하고 시간 정보는 내부 계산에 유지한다. 현재 방향은 [소프트웨어 계획](software-plan.md), 기능별 진행 상태는 [체크리스트](implementation-checklist.md)를 따른다.

아래 10:00–19:00·총유입 10,350명·체류 120–240분은 이전 계획으로 `configs/day.json`에 보존한다. 연속 시연은 `configs/continuous.json` 설정으로 배경 방문객의 개인별 예정 체류와 빈자리 보충을 처리한다. 개인 예정 체류 기본 범위는 120~180분이며, 이용 횟수는 방문객의 선택·대기·운행 상태에 따라 달라진다. [설정 계약](../lotteworld/docs/configuration.md#연속-시연-설정과-상태) · [검증 기록](verification/magic-island-continuous-arrivals.md)

## 시설·지도 범위와 표시

- 시뮬레이션 1차 범위는 매직아일랜드 3D 지도·개별 보행·유한 대기열·차량별 반복 탑승이다. QR 관람객 화면·영상 수신 및 인원/밀집도 분석·추천 서버·관리자 대시보드는 최종 제품에 포함하며 별도 연동 단계에서 개발한다. 비상 대피와 퍼레이드 관람 이동은 별도 범위다. 기존 정적 시안은 참고 자료다.
- 시설은 아트란티스·자이로드롭·자이로스윙·자이로스핀·혜성특급·아르카나라이드의 6개다. 쁘띠빵빵은 제외한다.
- 기존 아쿠아리움처럼 조작 가능한 3D로 구현하고, 2026 가이드맵의 섬 윤곽·성·다리·시설 배치와 시설별 입체적 특징을 살린다. 상대적 위치와 연결을 참고하고 시설 사이 공간을 넓힌다. 한눈에 시설·사람·보행로·대기열을 구별하는 것이 우선이다. 넓힌 거리와 폭은 가상 설계값이며 이동 계산에도 같은 미터 좌표를 사용한다.
- 다리에서 진입하고 같은 다리로 복귀한다. 공원 정문–다리 이동, 호텔 조기 입장, 재진입, 6개 시설 외 목적의 방문은 초기 모형에서 생략한다. 키·아동·보호자·일행을 구분하지 않고 시설 이용 조건을 충족하는 개인으로 추상화한다.
- 전체 보기에서 6개 시설 이름·대기 인원·운행 상태를 읽을 수 있게 한다. 시설별 단순 형상을 구별하고 성·호수는 위치를 알아보는 배경으로 사용한다. 혜성특급도 다른 시설처럼 지상에 표시하며 지하 절개·B1 표시는 사용하지 않는다. 섬 내부의 포장면은 넓은 보행 광장으로 연결하고, 지정한 해안 녹지와 내부 화단은 보행을 제한한다. 보행자 수를 표시 편의로 잘라내지 않는다.

## 이전 계획: 관측 시간과 체류 (현재 우선 구현 범위에서 제외)

| 항목 | 이전 계획 기준 | 당시 성격 |
| --- | --- | --- |
| 시작 | 10:00, 구역 내 0명부터 다리로 순차 진입 | 사용자 확정 |
| 종료 | 19:00, 월드 오브 라이트 시작 시각 | 사용자 확정 |
| 관측 길이 | 9시간, 개장 전 예열 없음 | 위 시간 기준 |
| 개인 예정 체류 | **대기를 포함한 120–240분** | 사용자 확정 |
| 체류 추출 | 개인별 균등분포 `Uniform(120, 240)`분 | 개발 기본 가정 |
| 유입 | 아래 시간별 계획 인원을 구간 안에 무작위 배분 | 합성 실험 입력 |

2026-11-11 실제 공식 화면에서 개장 10:00과 월드 오브 라이트 19:00을 확인했다. [운영시간](https://adventure.lotteworld.com/) · [공식 공연 일정](https://adventure.lotteworld.com/enjoy/performance/list). 퍼레이드는 어드벤처 1층 퍼레이드 코스에서 진행되며 일정은 바뀔 수 있다. 19시는 이 실험의 고정 종료 시각이다.

- 체류 시계는 **실제 다리 진입**부터 시작한다. 이동·대기·승하차·운행·휴식이 모두 포함되며 대기시간을 다시 더하지 않는다.
- 개인 복귀 기준은 `실제 진입 시각 + 추출 체류시간`이다. 19시로 잘라 예정 체류를 줄이지 않는다. 18시 진입자의 개인 복귀 기준이 20–22시여도 19시에 관측만 끝낸다.
- 미이용 시설을 우선하고 재탑승을 허용한다. 이전의 목표 탑승 2–4회는 확정하지 않았으므로 고정 퇴장 조건으로 사용하지 않는다. 시설을 한 번씩 이용했다는 이유로 예정 체류를 강제 종료하지 않는다.
- 개인 체류 한도 도달 시 새 탑승·대기를 중단하고 다리로 복귀한다. 운행 중이면 하차 후 복귀하므로 실제 체류는 하차·귀환 보행만큼 늘 수 있다. 19시가 먼저 오면 진행 중 상태를 보존한다.
- **19시는 관측 종료이며 폐장이 아니다.** 폐장 이벤트·전원 퇴장·강제 탑승 완료를 적용하지 않는다. 퍼레이드 사전 자리잡기·실내 이동은 이번 1차에 자동 추가하지 않는다.
- 완료 대기와 종료 시 진행 중인 대기 경과시간·미완료 여부를 별도로 집계한다. 잔류 인원을 자동 포기·실패로 처리하거나 완료 대기 평균만으로 전체 대기를 대표하지 않는다.

## 이전 계획: 연간 통계에서 유입량 계산

근거는 국회예산정책처 「재정경제통계 Brief 16호」(2025-07-24)의 **2024년 롯데월드 연간 입장객 5,256,920명**이다. [공식 원문 첫 쪽](https://nabo.go.kr/board/file/down.do?fid=33318657). 고정된 기준 연도의 실험이며 2026년 관측치나 최신 연간 집계라는 뜻은 아니다.

### 유입·재현 규칙

- 시간 구간은 시작 포함·끝 제외다. 인원 수는 각 행대로 고정하고 구간 안의 초 단위 시각을 균등 무작위로 뽑아 정렬한다. 분당 평균을 고정 생성 간격으로 사용하지 않는다. 19:00에는 새 방문객을 생성하지 않는다.
- 입장·개인 체류·선호 난수를 구분한다. 같은 설정·시드에서는 진행·되감기와 무관하게 같은 결과를 재현한다. 기본 비교 시드는 기존 20261104를 유지할 수 있다.
- 표는 **다리 경계 도착 수요**다. 몸체 공간이 없으면 실제 진입을 늦추고 계획/실제 시각을 구분한다. 19시까지 들어오지 못한 수요는 경계 밖 미진입으로 집계한다.
- 각 시점의 `실제 진입 = 실제 복귀 + 구역 내 잔류`, 종료 시 `계획 10,350 = 실제 진입 + 미진입 수요`를 점검한다. 인원을 삭제하거나 추가해서 맞추지 않는다.
- 기존 `daily_visitors`를 재사용한다면 관측 입력은 10,350명이다. 하루 기준 11,500명을 넣어 9시간에 재정규화하지 않는다. 시간별 고정 인원 입력은 아쿠아리움의 가우스 분포와 달라 별도 지원이 필요하다.
- 시간당 1,500명 * 평균 체류 3시간은 정상상태에서 약 4,500명 규모다. 변동 유입·초기 0명의 실제 피크 결과로 보고하지 않는다. 수천 명 동시 보행을 대상으로 성능을 검증하고 논리 인원을 잘라내지 않는다.

표는 공개 출처의 참고값이다. 반복 운행 시연에는 1회 운행을 10초 단위로 반올림한 [시연용 초기값](magic-island-research.md#시연용-초기값)을 사용한다. 각 값의 출처와 확인 수준은 [운영 조사](magic-island-research.md)에 있다.

- 대기 합류 → 승차 → 확인 → 운행 → 하차 → 다음 선택·복귀로 진행한다. 도착순 탑승, 빈 좌석 출발, 실제 보행 지연을 반영한다. 정원·차량을 초과하거나 사람을 좌석으로 순간 이동시키지 않는다.
- 출발은 최소 간격·승하차 완료·차량 가용·코스 구간 가용을 모두 만족해야 한다. 30초마다 새 차량을 생성하거나 공연의 정시 시작 규칙을 그대로 복제하지 않는다.
- 시연 엔진은 고정된 차량·편성을 순환 사용한다. 아트란티스는 두 승강장과 30초 가상 코스 구간 네 개를 사용하며, 복귀 차량은 승강장이 찼으면 코스 밖에서 대기한다. 시설별 공용 빨간 출구의 통과 간격은 1 내부 초다. 승강장은 설정 하차 시간과 마지막 출구 통과 조건을 모두 충족해야 비운다. [시설별 운행과 상태 계약](../lotteworld/docs/configuration.md#시설별-운행-설정)
- 제조사 승하차 합계에 안전 확인·하차 시간을 중복 가산하지 않는다. 분리할 때는 합계를 유지하고 분리 비율을 가정으로 기록한다.
- 공간 초기안은 다리·주 보행로 유효 폭 8m, 지선 5m, 대기 통로 폭 1.2m·앞뒤 간격 0.8m, 통로와 줄 사이 완충 1.5m, 시설 출구 3m다. 실측치·법정 기준이 아니다.
- 줄·탑승·하차 합류·이탈 공간을 공용 보행로와 분리한다. 각 시설의 대기 및 승하차 동선 주변을 전용 구역으로 두고, 해당 시설을 이용하는 방문객은 배정된 경로로 이동한다. 물리적 자리가 차면 합류를 중단하고 다른 시설을 선택한다. 통로 쪽 줄 연장·숨겨진 무제한 대기는 사용하지 않는다.
- 대기 구획은 1회 탑승 정원의 2.5배 이상을 수용하도록 자리 좌표를 검사하고 런타임에서 그 자리만 예약한다. 시설별 수용량은 110명 또는 130명이며 총 720명이다. 2.5배는 최소 공간 기준이며 최대 대기시간은 운영 지표와 연결해 측정할 항목이다. [물리적 대기열 검증](verification/magic-island-physical-queues-and-boarding.md)
- 배경 방문객은 입장 때 개인 선호 유형과 기본 대기 허용 시간을 배정받는다. 예정 체류 안에 입구에 도달할 수 있는 후보 가운데 시설 가중치, 개인 선호, 이동·대기 비용, 재탑승 감점을 반영해 목적지를 추첨한다. [행동 설정 계약](../lotteworld/docs/configuration.md#방문객-선호와-반복-이용)
- 현재 예상 대기는 첫 목적지를 고를 때, 하차 후, 기존 목적지에 갈 수 없을 때, 광장을 걷는 도중에 조회한다. 갈 만한 시설이 없으면 현재 위치에서 걸어서 도달할 수 있는 포장면의 좌표를 무작위로 고른다. 주변에 사람이 적은 후보에 조금 더 높은 가중치를 주고, 조회 시점은 방문객마다 다르게 잡는다. 개인의 선호와 대기 허용 시간, 남은 체류 시간, 이동 중인 인원까지 반영한 자리 수를 확인해 갈 수 있는 시설이 생기면 그 자리에서 대기열 입구로 향한다.
- 휴대폰 확인은 출구와 길목을 벗어난 보행 구간의 감속으로 표현하며 시점과 거리는 방문객마다 다르다. 시설 입구에서는 합류 가능 여부를 다시 확인하고, 대기줄에 합류하면 차례를 지켜 탑승한다. 하차한 방문객은 이용 횟수를 기록하고 예정 체류가 남으면 다음 시설을 고르며, 체류가 지났으면 퇴장한다. [행동 및 재현 검증](verification/magic-island-visitor-behavior.md)

## 개발 경계와 검증

- 매직아일랜드를 별도 시나리오로 추가하고 기존 아쿠아리움 지도·설정·기록을 보존한다. 지도 고정 로드·해양 선호·공연 전용 상태·아쿠아리움 UI 명칭을 구분한다.
- 기존 엔진의 개인 deadline을 폐장으로 자르는 처리와 폐장 후 1시간 horizon을 복사하지 않는다. 관측 종료·운행 종료·개인 복귀 기준을 분리한다.
- 결과에는 시나리오·지도/설정 해시·시드·출처/가정, 시간별 계획/실제 진입·복귀·잔류·미진입, 완료/진행 대기·탑승 완료·가동률·포기·보행 지연을 구분한다. 구체 API 형식은 구현 때 기존 API와 함께 정한다.
- `web-admin`의 가상 추천·절약 시간·장치 상태는 새 시뮬레이션 결과가 아니다. DB·인증·새 백엔드는 1차 필수 조건이 아니다.
- 입력 검증: 시간별·누적 합계, 관측 비중 90%, 피크 비중 40%, 19시 이후 제외, 시드 재현성을 확인한다.
- 기능 검증은 만석, 빈 좌석 출발, QR 세션 만료 시 자리 정리, 정원·차량 보존, 대기 중 체류가 만료된 방문객의 탑승·하차·퇴장을 확인한다. 18시 이후 입장자의 19시 상태 보존과 경계 진입 지연·미진입도 확인한다.
- 공간·성능 검증: 전체 보기의 시설 구별, 통로의 대기열 침범 방지, 양방향 다리, 40명 하차 직후 합류, 목표 인원에서 장시간 연속 실행을 점검한다. 되감기 UI는 기본 시연 요구사항에 넣지 않는다.

시설·지도 형상과 확인된 구현 상태는 계속 참고한다. 시간·인원·체류 값은 이전 시간표 계획의 기록이며 현재 연속 시연의 완료 조건은 최신 체크리스트를 따른다.

## 시나리오 선택과 독립 실행 기반 (1번 완료)

기존 아쿠아리움 전체는 `../aquarium/`, 새 롯데월드는 `../lotteworld/`에 분리했다. 각 폴더는 다른 시나리오 폴더 없이 실행할 수 있다. 개발 루트의 `run.py`·`run.ps1`은 `--scenario aquarium|magic-island`와 `--mode server|cli`로 독립 프로세스·작업 디렉터리를 선택한다. 기본 시나리오를 추정하지 않고 명시적 선택을 요구한다. 개별 폴더의 기존 진입점은 계속 사용할 수 있다.

매직아일랜드는 독립 지도·선호 설정을 사용한다. 서버는 미터 좌표의 지도와 별개로 배경 순환을 실행하며, 실행 상태는 `GET /api/state`에서 조회한다. [설정 계약](../lotteworld/docs/configuration.md) · [실행 명령](../lotteworld/README.md)


## 매직아일랜드 지도와 시설 표시 (2번 완료)

로컬 국문 가이드맵 4쪽의 섬·다리·성·시설 상대 배치를 직접 확인하고 독립 Three.js 장면으로 구성했다. 중앙의 푸른 첨탑 성, 왼쪽 위 자이로드롭, 오른쪽 위 자이로스윙, 오른쪽 아트란티스, 자이로드롭과 자이로스핀 사이의 혜성특급, 왼쪽 아래 자이로스핀, 아래쪽 아르카나라이드와 오른쪽 아래 진입 다리를 배치했다. 탑·곤돌라, 지지대·진자, 물길·고가 코스, 디스크·U자 레일, 열차·굽은 코스, 소형 차량·순환 레일로 시설을 구별한다. 혜성특급은 요구에 따라 지상에 보이는 추상 모형이며 실제 시설 층을 재현하는 지도가 아니다.

`lotteworld/configs/map.json`의 같은 미터 좌표로 섬 외곽, 시설·대기·하차·식재 구획, 참조 경로를 표시한다. E안의 해안선은 422개 표본점으로 나타낸다. 자이로드롭 방향은 둥근 머리를, 자이로스핀·자이로스윙과 아르카나라이드·아트란티스 방향은 진저브레드형 윤곽의 양팔과 양다리를 이룬다. 성 정문·앞 광장·진입 다리는 동일한 축을 따른다. 접합부의 양쪽 수면 홈은 다리 중심축에 대칭이며 폭 12m 데크는 해안선부터 시작한다. 남쪽 참조 경로는 새 홈을 피해 섬 안쪽으로 굽어 이어지고 폭 8m를 유지한다. `public_walkable`은 개인 반경과 해안·다리 경계, 시설·대기·하차·배경 건물 구획, 성·녹지·시설 전용 구역의 다각형을 반영해 포장 보행 공간을 판정한다.

시설 전용 구역 여섯 곳의 광장 쪽 경계는 지도 시안의 주황선을 따르고, 바깥쪽은 녹지나 섬 가장자리에 연결한다. 공용 보행과 광장 산책은 이 경계를 우회한다. 대기 입구의 공용 접근점까지는 광장 쪽에서 걸을 수 있고, 해당 시설의 대기 진입·승차·하차·이탈 경로만 전용 구역에 들어간다. 초록색 대기 입구와 빨간색 하차 표시의 좌표는 기존 위치를 사용한다.

두 웹은 북쪽에서 동쪽으로 이어지는 해안 녹지, 아르카나라이드 바깥의 남서쪽 해안 녹지, 혜성특급 옆 화단, 매직캐슬 동쪽 화단의 네 구역을 같은 3D 지도에 표시한다. 해안과 맞닿는 구간에서는 녹지가 섬 가장자리까지 닿도록 사이의 포장 띠를 채운다. 시설과 대기·하차 구획에는 포장 공간을 둔다. 자이로스윙 진입·하차와 아트란티스 하차 연결은 녹지 바깥 포장면으로 우회한다. 시설 입출구와 다리 좌표는 그대로 사용한다.

고정 시드로 구역별 격자 안에서 나무와 수풀 위치를 흩어 놓는다. 지정 식재 사각형 밖의 나무는 물가 가까이에 두고, 수풀은 둥근 잎 덩어리 세 개를 겹쳐 방문객 키의 약 40~55%로 표현한다. 지도 해시는 성과 녹지의 다각형, 변경한 동선을 포함한 현행 설정에서 계산한다. 호수에는 짧은 흰 물결을 드문드문 표시한다.

매직캐슬의 바닥은 본체·정문·탑의 외곽을 따라 약 552㎡의 평면으로 표시한다. 성 주변의 빈 면은 광장 포장으로 이어진다. 다리는 폭 12m의 실제 바닥을 표시하며 정문과 같은 축을 따른다. `plaza`는 광장 위치를 나타내는 구획이다.

화면의 접근·복귀 경로는 `navigation.mjs`가 넓은 포장 영역에서 찾는다. 2m 격자와 반경 0.25m, 장애물·해안·다리 경계를 반영해 경로를 탐색하고 통과 가능한 직선 구간을 합친다. 입출구의 짧은 접속부만 해당 지선으로 연결한다. 표시 거리는 이 경로의 합이며 수학적으로 정확한 연속 공간 최단 거리나 실제 현장 이동시간은 아니다. 설정의 연결 그래프와 `walking_route`는 연결성 검사에 유지하며 사람을 그 중심선에 가두지 않는다.

6개 시설의 대기줄은 반원 회전부와 양쪽 벨트를 사용하며 직선 구간과 회전부에 반경 0.345m·최소 중심 간격 0.92m의 자리를 배치한다. 직선 양 끝에는 0.92m 여백을 두고 진입 구간은 비워 둔다. 방문객은 초록 입구에서 대기 상태로 바뀌고 앞자리가 비면 황금색 탑승 진입점 방향으로 전진한다. 만료된 QR 세션이 차지한 자리는 옆 통로를 통해 정리한다. 하차한 방문객은 빨간 점을 한 명씩 1 내부 초 간격으로 통과한다. 배경 방문객은 빨간 점 뒤부터 시설·녹지와 간섭하지 않는 여러 동선으로 나뉘고, 전용 구역을 벗어난 공용 보행 지점에서 다음 목적지로 향한다. [보행·상태 계약](../lotteworld/docs/configuration.md#물리적-대기열과-승하차-보행)

자이로드롭은 이전 그림자 상단에 해당하는 중심 (96.6, 62.6)으로, 혜성특급은 자이로드롭과 자이로스핀 사이의 왼쪽 해안 방향 중심 (41, 124)에 배치했다. 2026-11-17 표시 이미지에 맞춰 혜성특급·자이로스핀은 세로 방향 대기 구획, 아르카나라이드는 시설 위쪽 대기 구획을 사용하며 세 시설의 입출구도 함께 이동했다. 자이로스핀은 호수 쪽 배치를 유지하며 대기 구획·입출구도 연계해 조정했다. 지도와 시설 상세에는 대기 자리 수를 표시하지 않는다. 모든 구획과 동선의 섬 내부 배치·간섭을 다시 검사했다. 현재 수용량과 저장 후 새로고침 절차는 [수용량·자동 반영 검증](verification/queue-capacity-and-reload.md)을 따른다.

드래그 회전·휠 확대·오른쪽 드래그 이동, 터치 회전·확대·이동, 전체 보기·위에서 보기·가림 줄이기·선택 시설 확대, 모형 클릭·키보드 목록 선택을 지원한다. 대기 인원·운행은 미집계다. `map_ready: true`와 `map_view: guide-map-3d`는 지도 준비를, `status: continuous_running`은 배경 순환 실행을 나타낸다.
