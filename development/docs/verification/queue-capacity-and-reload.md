# 대기 수용량·호수 방향 배치·저장 후 새로고침 검증

기준일: 2026-11-17. 대기 구획의 실제 정적 자리 배치와 개발 중 변경 반영을 보완했다. 서버의 실행 가능 상태는 계속 `runnable: false`이며 사람·운행 엔진 완료 기록은 아니다.

## 정적 대기 수용량

1회 탑승 정원은 [개발 명세](../design.md)의 값을 설정으로 옮겼다. 아트란티스는 보트 1대 8명 기준이며 여러 보트 전체 정원을 한 번에 곱하지 않는다. 혜성특급은 열차 1편성 26명이다. 기준은 `ceil(1회 정원 × 2.5)`다.

| 시설 | 1회 탑승 | 최소 대기 수용 | 배치한 자리 | 결과 |
| --- | ---: | ---: | ---: | --- |
| 자이로드롭 | 40명 | 100명 | 105명 | 충족 |
| 자이로스윙 | 40명 | 100명 | 105명 | 충족 |
| 자이로스핀 | 40명 | 100명 | 130명 | 충족 |
| 혜성특급 | 26명 | 65명 | 130명 | 충족 |
| 아트란티스 | 8명 | 20명 | 105명 | 충족 |
| 아르카나라이드 | 16명 | 40명 | 126명 | 충족 |

면적을 사람 수로 나눈 값이 아니라 [queue_capacity.py](../../lotteworld/lotteworld_sim/queue_capacity.py)가 직선 줄 위에 만든 자리 좌표의 개수다. 반경 0.3m, 중심 간격 0.8m, 줄 양 끝 여백 0.8m를 사용하고 진입·회전 구간에는 자리를 두지 않는다. 모든 자리의 몸체가 구획 안에 있고, 기둥·벨트와 겹치지 않으며, 서로 최소 간격을 지키는지 검사했다. 화면의 `queue.mjs`와 Python의 자리 좌표가 일치하는지도 브라우저에서 확인했다. 이 수치는 정적 공간 검증이며 실제 줄 이동·승하차 처리량을 검증한 뜻은 아니다.

## 호수 방향 이동

자이로드롭 중심은 이전 배치의 그림자 상단에 해당하는 (96.6, 62.6)으로 옮겼다. 실제 모형 크기는 유지하고 원형 기단을 포함하는 예약 구획만 22×22m로 맞췄다. 혜성특급은 표시 이미지의 파란 영역을 기준으로 왼쪽 해안 방향 중심 (41,124)으로 옮겼다. 기존 지상 코스 크기를 유지하고 해안 안에 배치했다. 자이로스핀은 호수 쪽 배치를 유지한다. 모두 가상 설계 좌표다.

대기 구획·입출구·참조 연결도 함께 조정했다. 섬 밖 배치·구획 간섭·참조 통행 폭·다리 연결 검사를 다시 통과했다. 식재는 11개이며 성 정면·다리 축은 유지했다.

## 곡선 벨트와 화면 표시

각 줄의 중심선은 반경 1.2m의 반원 회전부로 이어지고, 양쪽 벨트 경계는 중심선에서 0.6m 떨어져 연속된다. 회전부는 반원당 12개 선분으로 근사한다. 3D 벨트는 경계 전체를 하나의 리본 메시로 만들고 기둥은 호 길이에 따라 배치하여 꺾이는 부분에도 끊김이 없다. 출입구는 열어 둔다. 진입 구간과 회전 여백을 확보하면서 정적 수용량은 위 표와 같이 갱신했다.

지도 라벨은 ‘대기줄’만 표시한다. 시설 상세의 수용 인원·최소 인원·1회 정원 문구도 제거했다. 자리 수는 내부 공간 검증과 메타데이터에만 남긴다. 실시간 대기 인원은 아직 집계하지 않는다.

## 변경 반영

- HTML·CSS·JavaScript는 매 요청마다 최신 파일을 제공한다. 지도·운영·선호 JSON도 수정 후 다음 요청에서 다시 읽고 검증한다. 서버 종료 없이 저장 후 새로고침하면 반영된다.
- Python 변경은 기본 실행의 감시 프로세스가 감지해 같은 포트의 서버를 자동으로 다시 띄운다. 실행창과 실행 명령은 유지된다. `--no-reload`로 Python 감시만 끌 수 있다.
- 설정을 잘못 저장하면 422를 반환하고 올바르게 저장하면 같은 서버에서 복구한다. 기존 구버전 서버는 새 감시 기능을 적용하려고 한 번 다시 실행해야 한다.

## 검사

- `lotteworld/`의 Python 검사 17개: 수용량·몸체·간격·부족한 자리 거절, 호수 이동 후 공간, HTTP 설정 재읽기·오류 복구, Python 소스 변경 후 같은 포트의 새 서버 인스턴스, 기존 서버·CLI 검사.
- 개발 루트의 Python 검사 5개: 시나리오 선택·단독 복사·다른 시나리오 격리·동시 서버 검사.
- JavaScript 경로·대기줄 검사와 Chrome의 1600×1100·1024×900·390×844 검사. 시설별 내부 자리 좌표·연속 벨트 경계를 서버 결과와 대조하고, 지도와 시설 상세에 자리 수가 노출되지 않는지 확인했다.
- 브라우저 검사에서는 별도 운영 JSON을 저장하고 실제 페이지 새로고침 후 새 시드를 읽으며 서버 인스턴스가 그대로인지 확인했다. Python 감시 검사는 임시 복사본의 소스만 수정하고 검사 종료 시 자식 서버를 정리한다.
- 문법·문서 링크·`git diff --check` 통과. 실제 사용 명령은 [README](../../lotteworld/README.md)를 따른다.

혜성특급 위치 정정 후 지도 Python 검사 8개, JavaScript 광장·대기줄 검사와 Chrome 3개 화면 크기 검사를 다시 통과했다. 자이로드롭 → 혜성특급 → 자이로스핀의 세로 순서를 검사하며 자리 수 숨김도 유지한다.

## 2026-11-17 대기줄 진행 방향 통일

대기 구획과 초록·빨간 점의 위치를 유지하면서 접힌 줄의 횡방향을 시설에 맞춰 배향했다. 모든 줄은 초록 대기 입구에서 시작해 놀이기구에 더 가까운 경계의 황금색 ‘탑승 진입’에서 끝난다. 그 지점부터 시설 구획 경계까지 짧은 황금색 연결선을 표시한다. 대기줄 출구인 탑승 진입점과 이용 후 빨간 퇴장점은 서로 다른 의미다.

| 시설 | 탑승 진입점 [x,z] |
| --- | --- |
| 자이로드롭 | [93.4,80] |
| 자이로스윙 | [226.6,66] |
| 아트란티스 | [282.6,152] |
| 혜성특급 | [65,134.6] |
| 자이로스핀 | [100,218.6] |
| 아르카나라이드 | [146.6,249] |

Python과 JavaScript가 자리·벨트·탑승 진입점에 같은 좌표를 사용한다. 입구보다 시설에 가까운 끝점, 다른 구획을 침범하지 않는 탑승 연결, 몸체·벨트 간격·최소 수용 기준, 브라우저의 6개 탑승 표시와 화면 크기별 조작을 확인했다. Python 17개 검사와 JavaScript 검사, Chrome 3개 화면 크기 검사를 통과했다. 자리 수는 계속 숨긴다.

현재는 정적 표시만 구현했다. 이용객을 실제로 줄 끝까지 이동시키거나 탑승 후 숨기는 처리·탑승 인원 집계·하차 후 표시 동작은 구현 또는 확정하지 않았다. 후속 대기열·운행 단계에서 연결해야 한다.

## 2026-11-17 대기줄·탑승 진입 이름표 제거

지도 위의 ‘대기줄’·‘탑승 진입’ 이름표 생성 코드, 전용 스타일과 모바일 확대 배율별 숨김 분기를 제거했다. 대기줄 형상·방향, 초록 입구·황금색 탑승 진입점·빨간 퇴장점과 연결선은 유지한다. 브라우저 검사는 두 이름표가 생성되지 않는지 확인한다.
