# Magic Pass 사용자 웹 디자인

Magic Pass는 매직아일랜드 시연 참여자가 현장 QR로 접속해 놀이기구 선호를 정하고, 현재 시설 현황에 따른 추천을 받아 시뮬레이션 속 캐릭터의 이동을 보는 모바일 웹이다. [소프트웨어 계획](software-plan.md) · [구현 체크리스트](implementation-checklist.md)

## 공통 테마

저녁의 놀이공원을 모티프로 짙은 보라 바탕, 아이보리 카드, 금빛 입장권 심벌을 사용한다. 입장권의 모서리가 파인 실루엣과 가운데 별을 로딩 화면과 모바일 상단에 반복한다. 시뮬레이션과 운영자 대시보드도 상단 바와 패널에 같은 Magic Pass 워드마크, 입장권 심벌과 강조색을 사용한다. 전체 지도와 운영 지표의 배치는 시뮬레이션 웹 설계를 따른다. [시뮬레이션 웹](simulation-web.md)

| 요소 | 디자인 기준 |
| --- | --- |
| 짙은 보라 `#20143B` | 로딩 배경, 헤더, 수락 버튼과 주요 텍스트 |
| 아이보리 `#F7F3ED`와 `#FFFAF3` | 페이지는 짙은 아이보리, 선호·추천 카드와 시뮬레이션·운영자 패널은 밝은 아이보리 |
| 카드 테두리 `#DDD2C4` | 두 카드의 경계에 같은 테두리와 옅은 그림자 적용 |
| 강조 보라 `#56349B` | 선호 조작과 지도 경로 강조 |
| 금빛 `#F3CB79` | 입장권, 로딩 표시, 수락 버튼 화살표, 지도 위 내 캐릭터 강조 |
| 글자와 형태 | 세 화면의 서비스명은 Great Vibes 필기체 워드마크로 통일한다. 로딩 문구는 Noto Serif KR 명조체를 사용하고, 화면 조작과 지표에는 공통 시스템 글꼴을 쓴다. 두 웹 서체는 시연 서버에서 제공한다. 카드 모서리는 16px, 버튼은 10px를 기준으로 한다. |

색과 함께 항상 글자 또는 형태로 상태를 구분한다. 지도에서 내 캐릭터는 캐릭터 모형과 발밑의 금빛 원으로 표시하고, 추천 목적지는 별 표식과 시설명으로 표시한다.

모바일 첫 화면 시안의 외곽 녹지, 둥근 수관, 청록색 물 위의 짧은 흰 물결을 공용 3D 지도에 반영한다. 사용자 웹과 시뮬레이션 웹에서 같은 섬 윤곽과 식재를 볼 수 있다. [지도 설정](../lotteworld/docs/configuration.md#지도-형상-계약-2번)

## QR 진입과 로딩

현장 QR을 열면 짙은 보라 바탕 위로 금빛 입장권이 나타난다. 그 아래 **Magic Pass** 워드마크와 **‘기다림을 줄이는 마법’** 한 줄을 가까이 붙여 가운데 정렬한다. 두 줄에 옅은 금빛을 사용하고 ‘마법’에 입장권과 같은 금빛을 사용한다.

입장권과 서비스명이 2초에 걸쳐 한 번 나타난다. 모션 축소 설정에서는 정적인 입장권을 표시한다.

세션 연결과 첫 화면 데이터 준비를 시작하며, 로딩 화면을 최소 2초 동안 표시한다. 첫 접속에서는 기본 순위를 자동 저장하고 그 순위에 따른 추천을 표시한다. 3D 지도 준비가 늦어지면 선호·추천 카드부터 표시하고 지도 자리에서만 로딩 상태를 보여 준다. 유효한 세션을 다시 열면 저장한 순위와 추천 또는 이용 상태를 복구한다.

### 연결 오류 화면

첫 연결에 실패하거나 세션 만료·실행 불일치로 상태를 이어갈 수 없으면, 화면 중앙의 단색 카드에 금빛 티켓과 별, ‘접속이 잠시 끊겼어요’, ‘다시 연결’ 버튼을 표시한다. 첫 연결의 네트워크 오류·시간 초과와 세션 재연결이 필요한 경우에는 ‘인터넷 연결을 확인한 뒤 다시 시도해 주세요.’를 안내한다. 이용 도중 일시적으로 조회가 지연되면 마지막으로 받은 상태를 표시한다.

## 모바일 첫 화면

짙은 보라색 헤더에 서비스명과 ‘매직아일랜드’를 배치한다. Magic Pass 워드마크는 시뮬레이션 헤더와 같은 줄 높이 비율과 세로 보정을 사용해 티켓 옆에 가운데 정렬한다. 작은 금빛 티켓의 별은 티켓의 가로·세로 중심에 둔다. 그 아래 **선호 순위 → 추천 놀이기구 → 3D 지도**를 한 열에 배치하며, 세 영역의 위치는 수락 전후에도 유지한다.

| 영역 | 표시와 조작 |
| --- | --- |
| 선호 순위 | 표지판 안내 대상 세 시설을 1~3순위로 함께 표시한다. 각 행 오른쪽에 점 여섯 개(2열×3행) 손잡이를 둔다. 손잡이를 끄는 동안 해당 행을 강조하고 이웃 행을 지나면서 순위를 바꾼다. 바뀐 순서는 손을 떼는 순간 자동 저장한다. 키보드는 손잡이에 초점을 두고 위·아래 방향키를 누르면 순위가 한 칸씩 바뀌고 자동 저장된다. |
| 추천 놀이기구 | 왼쪽의 ‘추천 놀이기구’ 아래에 시설명을, 오른쪽의 ‘예상 대기 시간’ 아래에 분 단위 값을 큰 글씨로 표시한다. 그 아래에 ‘수락하고 출발’을 배치한다. 새 순위가 저장되면 추천과 지도 경로를 함께 갱신한다. 끄는 중이거나 저장·갱신이 진행 중이면 이전 추천의 수락을 비활성화한다. |
| 3D 지도 | 추천 카드 아래에 지도를 바로 배치한다. 추천이 정해지면 캐릭터의 현재 위치에서 해당 시설 입구까지의 최단 보행 경로를 자동 표시한다. 내 캐릭터는 모형과 발밑의 금빛 원으로 표시한다. 회전·확대 중 화면 중심을 내 캐릭터에 고정하며, 수락 확정 후에는 같은 경로를 따라 움직이는 캐릭터를 보여 준다. 스크린 리더에는 ‘시뮬레이션 지도’로 안내한다. |

기본 QR의 선호 대상은 자이로스핀·혜성특급·자이로드롭이다. 첫 화면에는 시설 순위와 추천 시설명·예상 대기·수락, 지도와 현재 진행 상태만 남긴다. 캐릭터 ID, 좌표, 장문의 조작 설명과 추천 계산 근거는 화면의 기본 정보에서 뺀다. 보상 UI와 지급 로직은 후속 작업이며, 지급 기준은 서버가 유효한 추천 수락을 확정한 시점이다. [공통 데이터 계약](contracts/recommendation-v1.md)

### 모바일 배치 기준

- 세로 화면 390×844 CSS px을 기준으로 하고 320×520 CSS px 이상의 표시 영역에서도 헤더와 세 영역을 기본 글자 크기로 스크롤 없이 볼 수 있게 한다. 짧은 세로 화면에서는 헤더와 카드 간격을 줄인다. 확인에는 브라우저 주소창과 안전 영역을 제외한 표시 영역을 사용한다.
- 너비 640 CSS px 이상과 너비 560 CSS px 이상의 짧은 가로 화면에서는 선호·추천 카드 옆에 4:3 지도를 배치한다. 지도는 화면 너비와 높이 안에서 4:3을 유지하며 최대한 크게 표시한다.
- 본문은 좌우 여백 12~16px, 세로 영역 간격 8~14px, 두 열 사이 간격 16px을 기준으로 한다. 순위 손잡이와 수락 버튼의 터치 영역은 최소 44×44px을 기준으로 한다. 손잡이 바깥에서는 일반적인 세로 스크롤을 유지한다.
- 정상 상태에서 지도에는 최소 160px을 배정한다. 한 열로 표시되는 화면에서는 추천 카드 아래 남는 높이를 지도가 채운다. 공간이 부족하면 여백부터 줄인다. 큰 글자 설정, 브라우저 확대, 긴 오류 문구에서는 세로 스크롤을 허용해 내용을 읽고 버튼을 누를 수 있게 한다.

## 추천과 지도 상태

| 상황 | 화면 동작 |
| --- | --- |
| 순위 자동 저장 성공 | 첫 진입과 순위 변경 시 서버가 현재 시뮬레이션의 시설 운영·대기열을 조회한다. 저장한 선호, 그 시점의 예상 대기 시간, 현재 위치에서 각 입구까지의 최단 보행 거리를 함께 평가해 추천한다. 대기 시간은 시뮬레이션 시간 기준으로 ‘5분’처럼 표시한다. |
| 순위 자동 저장 실패 | 순위 목록에 ‘순위를 저장하지 못했어요’와 ‘다시 시도’를 표시한다. 마지막으로 바꾼 순위가 저장되고 새 추천이 도착할 때까지 수락을 비활성화한다. |
| 대기 미집계·갱신 지연·추천 없음 | 알려진 0분과 대기 미집계를 구분한다. 유효한 추천을 제공할 수 없으면 ‘지금 추천할 기구가 없어요’와 ‘추천 새로고침’을 표시한다. 갱신이 지연된 값으로 출발할 수 없도록 한다. |
| 수락 요청 중·추천 만료 | ‘출발 요청 중’으로 바꾸고 중복 입력을 막는다. 추천이 만료됐으면 갱신 후 새 추천을 확인하게 한다. |
| 수락 후 이동과 대기 | 버튼 자리에 ‘이동 중’ 또는 ‘대기 중’을 표시한다. 줄에 합류하면 추천 카드에서 ‘예상 대기’와 ‘대기 순서’를 나란히 배치한다. 줄과 차량 상태에서 추정한 시간은 시뮬레이션 분으로, 내 순번은 ‘N번째’로 같은 줄에 표시한다. 짧은 가로 화면에서는 두 값을 시설명 아래 한 줄에 배치한다. |
| 탑승부터 하차까지 | 버튼 자리에는 ‘탑승 중’, ‘이용 중’, ‘하차 중’ 등 한 가지 상태를 표시한다. 이 구간에서는 예상 대기 시간을 숨긴다. 이용 중에는 선호 순위를 읽기 전용으로 표시한다. |
| 하차 완료 | 이번 바퀴에서 아직 타지 않은 이용 가능한 기구 중에서 저장한 선호 순위, 그 시점의 시뮬레이션 예상 대기 시간, 이동 거리를 반영해 다음 추천을 자동 표시한다. 바퀴 도중에 그런 후보가 없으면 이미 탄 기구를 다시 평가하고 방금 탄 기구를 뒤로 미룬다. 다음 경로는 같은 캐릭터가 하차 후 도착한 공공 보행로에서 시작한다. |
| 새 바퀴 | 세 기구의 하차를 모두 마치거나 실제로 선호 순위를 바꾸면 새 바퀴를 시작한다. 방금 탄 기구를 첫 추천에서 제외하고, 나머지 이용 가능한 기구를 저장된 선호 순위, 현재 예상 대기 시간, 이동 거리로 평가한다. 직전 기구를 제외한 뒤 후보가 없으면 시뮬레이션 대기열을 다시 조회한다. |
| 지도 연결 실패 | 지도 영역에 ‘지도를 불러오지 못했어요’를 표시한다. 세션과 추천 서버를 사용할 수 있으면 선호 조정과 추천 수락은 유지한다. |

## 공통 서버 연동과 확인 항목

- QR은 `/user?sign_id=magic-island-west`로 연결한다. 서버 발급 쿠키로 세션을 찾고, 기존 `/api/user/*` 요청으로 선호 조회·저장과 추천을 처리한다. [로컬 실행 및 API](../lotteworld/README.md#qr-사용자-진입과-선호-입력)
- 새 캐릭터는 서쪽 안내판에서 입구 다리 쪽으로 향하는 앞부분에 배치한다. 안내판 주변 반경 12m의 2m 격자에서 공공 보행 가능 여부, 0.75m 여유와 안내판까지의 보행 연결을 확인해 비어 있는 자리를 고른다.
- 자동 저장은 한 번에 하나의 요청을 보낸다. 저장 중 순위를 다시 바꾸면 최신 순위를 기억하고, 앞선 저장이 확정된 뒤 서버가 반환한 세션 버전으로 제출한다. 추천 카드와 경로에는 마지막으로 선택한 순위에 해당하는 응답을 적용한다.
- 하차 완료 시 다음 추천을 자동 요청한다. 응답을 기다리는 도중 순위를 바꾸면 마지막으로 정한 순위를 저장한 뒤 그 결과를 표시한다. 추천 조회에 실패하면 ‘추천 새로고침’으로 다시 시도할 수 있다.
- 추천 수락 후 위치·진행 상태는 서버가 확정한다. 두 웹은 기존 지도·시설 자원과 공통 서버의 실행 문맥, `character_id`, 상태 버전을 공유한다. 입구에 자리와 보행 간격이 있으면 QR 캐릭터는 바로 줄에 들어간다. 공간이 확보될 때까지는 입구 앞에서 기다린다. 이용 중에는 서버에서 제공하는 대기·탑승·하차 상태를 표시한다. [시뮬레이션 웹](simulation-web.md) · [공통 데이터 계약](contracts/recommendation-v1.md)
- 사용자 웹이 보이는 동안 세션을 주기적으로 조회한다. 마지막 접속 신호 후 실제 시간 5분 안에 같은 브라우저로 돌아오면 기존 캐릭터와 진행 중인 대기 순서를 이어간다. 5분 동안 접속 신호가 없으면 자동 종료하고, 다음 QR 진입에서 새 세션을 시작한다.
- 구현 검증 시 모바일 브라우저 주소창을 펼친 상태에서 세 영역과 주요 버튼이 보이는지 확인한다. 별도 휴대폰의 QR 세션 분리, 갱신 지연·만료, 새로고침 후 상태 복구, 수락한 캐릭터의 위치와 상태가 두 웹에서 일치하는지도 확인한다.

로컬 사용자 웹은 Magic Pass 로딩·모바일 레이아웃과 순위 자동 저장을 제공한다. 수락 전에는 시뮬레이션에서 계산한 시설별 예상 대기를 보여 준다. 줄에 합류한 뒤에는 내 대기 순서와 차량 상태에서 계산한 예상 시간을 보여 준다. 두 지도는 같은 캐릭터가 이동·대기·탑승·하차하는 상태와 다음 시설로 출발하는 위치를 공유한다. [QR 사용자 웹 검증](verification/qr-user-entry-and-preferences.md)
