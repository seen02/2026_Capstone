# 캡스톤 프로젝트 주제 구체화

작성일: 2026-09-15
수정일: 2026-09-21

## 검토 배경

팀의 개발 경험과 5분 최종 발표에서의 전달력을 고려해 제안했던 8개 주제를, 교내 2025-1·2025-2·2026-1 캡스톤디자인 결과자료집과 비교했다. 기존 작품과의 유사성을 줄이고 목적을 명확히 하기 위해 다음 4개 후보로 좁혔다.

이후 **의자에 앉은 자세를 분석하고 앱으로 모니터링하는 주제**를 추가해, 현재 검토 후보는 총 5개다. 이 후보는 **작업 흐름을 고려한 휴식 타이밍 코치와 사용자가 켜고 끌 수 있는 진동 피드백**을 통합하는 방향으로 발전시켰다. 교내 스마트 시트·보행 분석·학습 모니터링 작품과의 비교도 아래에 반영했다.

- 제외: 웹캠 운동 폼 비교, 교통약자 경로 안내, 서버 장애 재현·시각화 도구.
- 보수적으로 제외: 스마트 대여·반납함. 차별화 여지는 있지만 교내 대여 플랫폼·무인 분실물 관리 작품을 함께 떠올리게 할 수 있다.
- 유지: 사각지대 충돌 경고, 소리·진동 설비 이상 탐지, AI 조립 보조 작업대, 백테스트 오류 점검.

유사성 평가는 제공된 세 자료집의 작품 설명을 기준으로 하며, 미수록 작품이나 실제 코드까지 비교한 표절 판정은 아니다. 아래 범위는 제안 단계이며 실제 성능이 검증된 결과는 아니다.

## 1. 주차장 출구 우회전 차량을 위한 보행자 접근 경고 장치

### 목적과 대상

건물 주차장에서 보도로 진출하는 차량이 출구 좌우에서 접근하는 보행자를 미리 인지하도록 돕는다.

대상 장소를 **벽이나 기둥 때문에 시야가 제한되는 주차장 출구 한 곳**으로 고정한다. 설치 카메라는 운전자에게 가려진 보도와 차량 진입 구역을 관측한다.

### 작동 흐름

1. 차량이 출구 접근 구역에 들어오면 경고 준비 상태가 된다.
2. 카메라가 보행자의 위치·이동 방향·속도를 추정한다.
3. 차량과 보행자가 보도 교차 구역에 비슷한 시점에 도달할 것으로 판단되면 경고한다.
4. 운전자 앞 표시등에 **‘좌측 보행자 접근’ 또는 ‘우측 보행자 접근’**을 표시한다.

핵심은 사람의 존재보다 **차량과 보행자의 이동이 겹치는 상황**을 구분하는 것이다. 사람이 출구에서 멀어지거나 차량이 충분히 떨어져 있으면 경고를 줄인다.

### 구현 범위

- **최소 결과물:** 고정 카메라, 방향별 LED 표시판, 접근 궤적·경고 기록 화면.
- **AI의 역할:** 사람·차량 탐지와 추적. 충돌 가능성 판단은 위치·속도 기반 계산으로 구성한다.
- **임베디드 역할:** 방향별 표시등 제어와 현장 경고 출력.
- **범위 제한:** 출구 한 곳의 낮 시간 조건부터 검증한다. 차량 자동 제동과 일반 도로 적용은 포함하지 않는다.

### 발표 시연과 검증

모형 출구와 저속 카트를 이용해 ‘보행자 접근 / 멀어짐 / 차량 미접근’ 세 상황을 비교한다.

- 단순 사람 감지 방식 대비 불필요한 경보 횟수.
- 위험 상황 누락 횟수.
- 교차 구역 도달 전 확보한 경고 시간.

### 교내 선행작과의 차이

보호장비 착용이나 낙상 감지가 아니라, **두 이동 대상의 예상 도착 시점을 비교하고 운전자에게 방향을 알려주는 장치**다.

관련 선행작: 2025-2 PDF p.21 「산업현장 안전 모니터링 시스템」, 2026-1 PDF p.11 「요양원 침대 낙상 위험 감지 모니터링 시스템」.

## 2. 소형 환기팬의 설치 풀림·회전 이상을 감지하는 부착형 센서 장치

### 목적과 대상

실습실·창고 등의 소형 환기팬에 센서를 부착해, 정상 운전과 다른 상태를 관리자가 빠르게 확인하도록 한다.

‘모든 공장 설비의 고장 예측’에서 범위를 줄여 **소형 환기팬 한 종류의 상태 감시**에 집중한다. 고장 원인을 정확히 진단하거나 남은 수명을 예측하는 것은 초기 목표에 포함하지 않는다.

### 작동 흐름

1. 팬 외함에 진동 센서와 마이크를 부착한다.
2. 정상 팬의 속도별 소리·진동을 수집한다.
3. 작동 중 신호가 정상 패턴에서 얼마나 벗어나는지 계산한다.
4. 이상이 지속되면 **‘점검 필요’**를 표시하고 해당 시간의 신호를 저장한다.

핵심 질문은 **“사람이 옆에서 떠드는 것과 팬 자체의 이상을 구별할 수 있는가?”**다. 이 질문에 답하면 소리와 진동을 함께 쓰는 이유가 분명해진다.

### 구현 범위

- **최소 결과물:** 팬 한 대, 부착형 센서 모듈, 상태 표시등, 정상·이상 신호 비교 화면.
- **AI의 역할:** 정상 운전 패턴을 학습하는 이상 탐지 모델.
- **임베디드 역할:** 소리·진동 수집, 데이터 전송, 상태 표시.
- **범위 제한:** 실제 열화 고장을 확보하지 못하면 결과를 **‘재현한 이상 조건 탐지’**로 명시한다.

### 발표 시연과 검증

정상 운전 → 주변 소음 추가 → 안전하게 재현한 장착 불안정·회전 이상 조건 순으로 전환한다.

- 소리만 사용 / 진동만 사용 / 두 센서 결합의 오경보·탐지율 비교.
- 다른 날 수집한 데이터로 평가해 같은 수집 세션에만 맞는 결과인지 확인.
- 이상 발생부터 경고까지의 지연 측정.

### 교내 선행작과의 차이

전력 사용량이나 PC 자원을 분석하는 서비스와 달리, **실물 회전 장치에서 수집한 두 센서 신호로 점검 필요 여부를 판단**한다.

관련 선행작: 2025-2 PDF p.28 「AIoT 기반 지능형 에너지 관리 시스템」, 2026-1 PDF p.10 「공공 PC 자원 이상 탐지 시스템」.

### 팀 적합성

센서 분석, 데이터 처리, 대시보드, 비교 실험으로 역할을 나누기 좋다. 현재 팀 경험과 정량적인 검증 가능성을 함께 고려하면 우선 추천하는 주제다.

## 3. 교육용 자동차 조립 키트의 부품 누락·순서 오류를 알려주는 작업대

### 목적과 대상

메이커 교육이나 조립 실습에서 초보자가 잘못된 단계로 넘어가기 전에 오류를 발견하도록 한다.

대상은 **큰 부품 6~8개로 구성된 자동차 키트 한 종류**로 정한다. 예를 들어 차체 → 차축 → 바퀴 → 상부 덮개 순서로 조립하며, 정상 상태를 카메라에서 구분할 수 있는 키트를 선택한다.

### 작동 흐름

1. 작업대 위 부품과 현재 조립 상태를 카메라가 확인한다.
2. 화면에 지금 수행할 단계와 필요한 부품을 표시한다.
3. 사용자가 부품을 조립하고 검사 영역에 놓으면 결과를 판별한다.
4. **‘왼쪽 바퀴가 빠졌습니다’ 또는 ‘차축을 먼저 설치하세요’**처럼 수정할 내용을 보여준다.

초기에는 손동작 전체를 끊임없이 해석하기보다 **각 단계가 끝난 상태를 검사**하도록 설계해 구현 난이도를 통제한다.

### 구현 범위

- **최소 결과물:** 상단 카메라, 고정 작업대, 키트, 단계 안내·오류 표시 화면.
- **AI의 역할:** 부품 종류와 조립 상태 인식. 조립 순서는 명시적인 규칙으로 관리한다.
- **임베디드 역할:** 부품 트레이의 무게 센서로 부품을 꺼냈는지 보조 확인하고 필요한 칸의 LED를 켠다.
- **범위 제한:** 내부에 가려진 결합 상태나 나사의 조임 강도까지 검사하지 않는다.

### 발표 시연과 검증

바퀴 누락이나 순서 오류를 일부러 만든 뒤 안내에 따라 수정한다.

- 오류 종류별 탐지율.
- 잘못된 경고 횟수.
- 안내 사용 전후의 최종 조립 오류 수.

### 교내 선행작과의 차이

일반 객체 인식이 아니라, **‘지금 단계에서 있어야 하는 부품과 상태’를 판단하고 다음 행동을 안내**한다. 제공된 세 자료집에서는 조립 단계·부품 누락·순서 오류를 판단하는 작업대에 직접 대응하는 작품을 찾지 못했다.

## 4. 개인 퀀트 개발자를 위한 백테스트 체결 오류·미래정보 참조 점검 도구

### 목적과 대상

개인 개발자가 높은 수익률을 확인했을 때, 그 결과에 실제로 불가능한 거래 조건이 섞여 있는지 점검하도록 한다.

입력은 임의의 전략 코드 전체가 아니라 **정해진 형식의 가격 데이터·매매 신호·거래 기록 CSV**로 제한한다.

### 핵심 검사 항목

| 검사 대상 | 구체적인 예 | 표시할 결과 |
|---|---|---|
| 신호 생성·체결 시점 모순 | 오늘 종가를 보고 만든 신호를 오늘 시가에 체결한 것으로 처리 | 불가능한 거래 행과 시간 관계 표시 |
| 미래정보 참조 | 해당 시점에는 발표되지 않은 지표를 사용 | 데이터의 이용 가능 시각과 신호 시각 비교 |
| 거래 비용·체결 지연 누락 | 수수료 없이 신호가 발생한 가격에 항상 거래 | 비용·다음 시점 체결 적용 전후 성과 비교 |

### 구현 범위

- **최소 결과물:** CSV 업로드, 오류 거래 목록, 문제 시점 차트, 조건 수정 전후 성과 화면.
- **판정 방식:** 명시적인 시간·비용·체결 규칙으로 검사한다.
- **AI의 역할:** 선택 사항. 오류 판정은 규칙으로 하고, AI는 오류 설명을 쉽게 풀어주는 정도로 활용한다.
- **범위 제한:** 데이터의 발표·이용 가능 시각이 제공되지 않으면 미래정보 참조 여부를 확정할 수 없다고 표시한다. 실거래 연동은 포함하지 않는다.

### 발표 시연과 검증

의도적으로 시간 오류를 넣은 전략을 업로드하면 문제가 있는 거래가 강조되고, 수정 후 성과가 어떻게 달라지는지 보여준다.

- 정답을 알고 있는 오류 사례를 만들어 탐지율과 오탐을 확인한다.
- 정상 거래가 오류로 표시되지 않는지 확인한다.
- 비용·체결 조건 변경에 따른 계산 결과를 별도 기준 계산과 비교한다.

### 교내 선행작과의 차이

금융뉴스를 분석하거나 투자 종목을 추천하는 것이 아니라, **전략 성과를 계산한 과정이 타당한지 검증**한다.

관련 선행작: 2025-2 PDF p.52 「금융뉴스 기반 핵심 토픽 분석기」. 금융 데이터·차트라는 분야는 공통이지만 목적과 핵심 기능은 다르다.

## 5. 작업 흐름을 고려한 착석 습관·휴식 코칭 스마트 의자 및 앱

### 주제 개요

**의자 압력 센서로 착석 상태와 지속 시간을 분석하고, 실제 자리 비움과 사용자의 알림 미루기를 반영해 휴식 시점을 안내하며, 선택적으로 진동 피드백을 제공하는 시스템**이다.

기존의 착석 자세 분석·앱 모니터링에 **‘착석 습관·휴식 타이밍 코치’와 ‘앱을 보지 않아도 반응하는 진동 피드백 의자’**를 하나의 사용 흐름으로 결합한다. 진동 피드백은 앱에서 사용자가 직접 **ON/OFF**할 수 있다.

### 목적과 대상

책상에서 오래 공부하는 학생이나 작업하는 사용자가 **자신의 착석 습관을 확인하고, 작업 상황에 맞춰 자세를 바꾸거나 휴식하도록** 돕는다.

해결할 문제는 세 가지다. 한쪽으로 치우친 상태를 오래 유지해도 알아차리기 어렵고, 고정 주기의 휴식 알림은 방금 쉬고 돌아온 상황을 반영하지 못하며, 앱 화면만으로 제공하는 피드백은 작업 중 놓치기 쉽다.

의자 좌판과 등받이에 센서를 부착하고, 측정한 압력 분포를 앱으로 전송해 현재 착석 상태와 시간별 기록을 보여준다. 초기 대상은 **센서를 부착한 의자 한 종류와 사용자별 기준 자세를 등록한 환경**으로 제한한다.

### 핵심 기능

| 기능 | 판단에 사용하는 정보 | 사용자에게 제공할 결과 |
|---|---|---|
| 착석 자세 분석·모니터링 | 좌판·등받이 압력 분포, 개인별 기준, 상태 지속 시간 | 현재 착석 상태, 상대 압력 분포, 좌우 치우침·등받이 접촉 시간 기록 |
| 작업 흐름을 고려한 휴식 타이밍 코치 | 연속 착석 시간, 자리 비움 지속 시간, 자세 변화, 사용자가 설정한 알림 미루기 | 실제 자리 비움을 반영한 휴식 안내, 알림 미루기, 착석·자리 비움 및 알림 반응 기록 |
| 진동 피드백 | 치우침 지속 여부, 휴식 알림 시점, 진동 ON/OFF 설정 | 앱을 보지 않아도 인지할 수 있는 짧은 진동, 자세 변화에 따른 피드백 종료 |

### 휴식 타이밍 코치의 동작

- 사용자가 연속 착석 알림 기준, 휴식으로 처리할 최소 자리 비움 시간, 알림 미루기 시간을 설정한다. 설정값은 서비스 동작 기준이며 의학적으로 최적의 휴식 간격이라고 주장하지 않는다.
- 자리 비움이 확인되면 착석 시간 누적을 멈춘다. 짧은 자리 비움은 복귀 후 기존 누적 시간을 이어가고, 설정한 최소 시간 이상 비웠다면 새로운 착석 구간을 시작한다. 앱에는 관측한 자리 비움 시간을 기록한다.
- 자세 변화와 장시간 착석을 따로 판단한다. 좌우 치우침이 해소되면 해당 자세 알림은 종료하지만, 의자에서 자세만 바꾼 것을 자리 비움 휴식으로 처리하지 않는다.
- 작업을 바로 멈추기 어려우면 사용자가 앱에서 **‘나중에 알림’**을 선택한다. 미루는 동안 휴식 앱 알림과 휴식 진동을 함께 보류하고, 시간이 끝났을 때 계속 착석 중인지 다시 확인한다.
- 자리를 비운 동안에는 자세·휴식 알림을 보내지 않는다. 알림 뒤 자리 비움이 있었는지, 미뤘는지 등을 기록해 일별 보고서에 표시한다.
- 초기의 ‘작업 흐름 고려’는 **센서로 관측한 착석·자리 비움과 사용자의 미루기 입력**을 뜻한다. 압력 센서만으로 집중도, 회의 여부, 업무 중요도를 추정하지 않는다.

### 진동 피드백과 ON/OFF 설정

- 의자의 좌우에 진동 모터를 배치하고, 한쪽 치우침이 일정 시간 지속되면 해당 방향을 짧게 진동시킨다. 휴식 안내는 자세 알림과 구분되는 진동 패턴을 사용한다.
- **앱 설정에 ‘진동 피드백 ON/OFF’ 스위치를 제공한다. OFF 상태에서는 자세 알림과 휴식 알림을 포함한 모든 진동 출력을 중단한다.**
- 진동 중 OFF로 바꾸면 현재 진동도 중단한다. 설정은 저장하고, 의자에 적용됐는지 확인해 앱에 표시한다. 연결이 끊겨 전달되지 않은 설정은 ‘적용 대기’로 구분한다.
- 진동을 꺼도 착석 분석, 시간 기록, 앱 알림은 계속 사용할 수 있다. 앱 알림 설정과 진동 설정은 별도로 관리한다.
- 기준 범위로 돌아오거나 자리를 비우면 해당 자세의 진동 알림을 종료한다. 진동은 짧은 펄스로 제공하고, 같은 상태의 반복 알림에는 대기 시간을 둔다.
- 초기 구현에서는 연결이 끊기면 진동을 중단하고, 재연결 후 저장된 설정과 현재 상태를 확인한 뒤 알림을 재개한다.

### 작동 흐름

1. 좌판의 좌우·앞뒤와 등받이에 압력 센서를 배치한다. 초기에는 좌판 4개·등받이 2개 정도를 출발점으로 삼고 실험으로 위치를 조정한다.
2. 사용자가 기준 자세와 좌우로 기울어진 자세를 짧게 유지해 개인별 기준 데이터를 등록한다.
3. 센서값과 압력 비율·변화량으로 **기준 자세 / 좌측 치우침 / 우측 치우침 / 등받이 비접촉 / 자리 비움**을 구분한다. 서로 동시에 나타날 수 있는 치우침과 등받이 접촉 여부는 별도 상태로 표시한다.
4. 앱에 현재 상태, 센서 위치별 상대 압력, 연속 착석 시간과 상태별 누적 시간을 표시한다.
5. 치우친 상태가 설정 시간 이상 지속되면 자세 확인 알림을 보내고, 진동이 ON이면 해당 방향에 짧은 진동을 제공한다.
6. 연속 착석 시간이 기준에 도달하면 자리 비움 기록과 알림 미루기 상태를 확인해 휴식을 안내한다. 진동이 ON이면 휴식 패턴도 출력한다.
7. 사용자가 자세를 바꾸거나 자리를 비우거나 알림을 미루면, 그 반응을 반영해 알림 상태와 시간 기록을 갱신한다.

핵심은 **착석 분석 → 상황에 맞춘 알림 → 사용자의 반응 확인 → 기록 갱신**으로 이어지는 흐름이다. 개인별 기준과 상태 지속 시간을 고려하고, 사용자가 피드백 시점과 진동 사용 여부를 선택하도록 한다.

### 구현 범위

- **최소 결과물:** 압력 센서·좌우 진동 모터가 부착된 의자, 센서 수집·전송 및 진동 제어 모듈, 자세·휴식 코칭 모바일 앱.
- **AI의 역할:** 수집한 압력 패턴으로 착석 상태를 분류한다. 먼저 압력 비율에 따른 규칙 기반 판정을 구현하고, 학습 모델을 적용했을 때 성능이 개선되는지 비교한다.
- **임베디드 역할:** 압력 센서값 수집, 빈 의자 기준 보정, 잡음 완화, 블루투스 등을 통한 앱 전송, 진동 모터 제어 및 ON/OFF 명령 적용.
- **앱의 역할:** 사용자별 기준 등록, 실시간 상태·압력 분포 시각화, 상태별 시간 기록, 휴식 시점 판단, 알림 미루기, 진동 ON/OFF, 일별 착석·자리 비움·알림 반응 기록 확인. 연결이 끊어지면 마지막 측정값을 현재 상태로 표시하지 않고 연결 상태를 안내한다. 연결 단절 구간은 자리 비움이나 휴식으로 간주하지 않고 측정 공백으로 기록한다.
- **알림 판단:** 지속 시간·자리 비움·미루기 상태를 명시적인 규칙으로 처리한다. 자세 분류에 쓰는 AI와 휴식 알림 규칙을 나눠 검증한다.
- **범위 제한:** 압력 센서만으로 목·척추의 정확한 각도나 거북목 여부를 판단하지 않는다. 등받이에 닿지 않은 상태 자체를 잘못된 자세로 단정하지 않고, 관측한 상태로 표시한다. 초기 목표는 착석 습관의 확인이며 질환 진단이나 교정 효과 검증은 포함하지 않는다.

### 발표 시연과 검증

관객이 의자에 앉아 다음 흐름을 체험한다. 발표에서는 자세·휴식·자리 비움 판정 시간을 줄인 **시연 모드**임을 표시한다.

1. 기준 자세에서 좌우로 치우치면 앱의 상태와 압력 분포가 바뀐다.
2. 치우침을 유지하면 진동이 발생하고, 기준 범위로 돌아오면 해당 알림이 종료된다.
3. 앱에서 **진동 OFF**로 바꾼 뒤 같은 상황을 재현하면 진동 없이 앱 상태·기록만 갱신된다. 다시 ON으로 켜면 이후 알림에서 진동이 동작한다.
4. 연속 착석에 따라 휴식 안내가 나오면 ‘나중에 알림’으로 미룬다. 이후 설정 시간 이상 자리를 비웠다가 돌아오면 새 착석 구간이 시작되는 모습을 보여준다.

- 기준 자세·좌우 치우침의 분류 성능과 등받이 접촉·자리 비움 판정 성능을 각각 확인한다.
- 짧게 몸을 움직였을 때 발생하는 불필요한 알림 횟수와 지속 상태에서의 알림 누락 횟수를 측정한다.
- 자세 변화부터 앱 표시까지의 지연과 실제 측정 시간 대비 기록 시간의 오차를 확인한다.
- 데이터는 사용자·수집 세션 단위로 나눠 평가한다. 연속된 측정값을 무작위로 섞어 학습·평가에 함께 넣지 않는다.
- 개인별 기준 등록 전후, 규칙 기반 판정과 학습 모델의 성능을 비교해 개인화와 AI 적용의 필요성을 확인한다.
- 고정 주기 휴식 타이머와 비교해 자리 비움 중·휴식 직후·미루기 중 발생하는 불필요한 알림 수를 측정한다.
- 앱 알림만 사용하는 조건과 앱·진동을 함께 사용하는 조건에서 알림 인지 시간, 자세 변경·자리 비움까지 걸린 시간, 사용자가 느낀 방해 정도를 비교한다. 참가자별 조건 순서를 바꿔 순서 효과를 줄인다.
- 진동 OFF 상태에서 출력이 없는지, 진동 중 OFF 명령으로 멈추는지, 재연결 후 설정이 유지되는지 확인한다. 진동 작동 자체가 압력값에 미치는 영향도 확인한다.

앞서 확인한 세 학기 자료집의 관련 작품과 다음 항목을 비교한다. 페이지는 표지를 포함한 PDF 뷰어 기준이다.

제공된 자료집에서 착석 자세 분류·휴식 타이밍·진동 선택을 모두 결합한 작품은 확인하지 못했다. 다만 각 기능 자체의 독창성을 주장하기보다 **고정 타이머 대비 불필요한 알림 감소와 앱 단독 대비 진동 피드백의 반응·방해 정도**를 검증해 차이를 설명한다.

### 팀 적합성

브레인스토밍에 나온 자세 추적 앱 관심사와 연결되며, 센서·진동 제어, 자세 분류·데이터 분석, 앱·알림 설정, 기록 저장·통신으로 역할을 나눌 수 있다. 의자에 앉아 자세를 바꾸고 진동을 켜고 끄는 참여형 시연이 가능하다. **센서 기반 상태 구분 → 앱 기록 → 휴식 규칙 → 진동 제어·ON/OFF → 비교 실험** 순서로 구현한다.

| 참여형 시연과 교내 차별성 | 자동차 조립 보조 작업대 | 관객이 오류를 만들고 안내에 따라 수정하는 과정을 보여줄 수 있음 |
| 학기 중 부담과 완성 가능성 | 백테스트 점검 도구 | 하드웨어 없이 입력 형식과 검사 규칙을 제한해 개발 범위를 통제할 수 있음 |
| 생활 속 활용과 앱·센서 결합 | 착석 습관·휴식 코칭 스마트 의자 및 앱 | 자세 분석·휴식 안내·진동 ON/OFF를 직접 체험하고 알림 방식별 반응을 비교할 수 있음 |
