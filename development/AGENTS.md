# 작업 지침

- 모든 사용자 대상 문구는 한국어로 작성한다. 답변뿐 아니라 도구 호출의 승인 요청 제목·설명·사유(justification)도 한국어로 작성하고 전송 전에 확인한다. 명령어·파일 경로·코드·제품명은 원문을 유지한다.
- 프로젝트 전체의 팀 공유 문서(README·설계·검증·인계 문서 포함)에는 대화 상대의 개인 이름·호칭이나 개인화된 응답 지침을 기록하지 않는다. 요구사항은 특정 개인을 지칭하지 않고 프로젝트 기준으로 서술한다.

## 현재 시뮬레이션 개발 기준

- 최종 소프트웨어 범위와 통합 제안은 `docs/software-plan.md`를 따른다. 3D 시뮬레이션, QR 선호·추천·예상 대기 화면, 표지판 영상 수신·인원/밀집도 분석 및 추천 서버, 표지판별 영상·시설 현황 관리자 대시보드를 포함한다. 시뮬레이션·관리자 앱 통합은 제안이며 확정되지 않았다.
- 2026-11-11 기준 매직아일랜드 1차 개발의 기준 문서는 `docs/design.md`, 출처 문서는 `docs/magic-island-research.md`다. 현재 실행 가능한 아쿠아리움 기록은 `aquarium/docs/design.md`에 보존한다.
- 구현 순서와 진행 상태는 `docs/implementation-checklist.md`를 따른다. 체크 항목 하나를 새 채팅 하나의 작업 범위로 삼고 관련 검증과 문서 갱신을 마친 뒤 체크한다.
- 매직아일랜드 관측 구간은 `10:00–19:00`이며 종료 기준은 야간 `월드 오브 라이트` 시작이다. 19시를 폐장으로 처리하지 않는다.
- 개인 예정 체류는 대기를 포함한 `120–240분`이다. 실제 진입부터 측정하고 19시로 체류 한도를 잘라내지 않는다.
- 개발 기본 입력은 구역 하루 기준 11,500명의 90%인 계획 진입 10,350명이다. 시간별 표와 무작위 배분은 `docs/design.md`를 따른다. 연간 통계 외의 계수·시간대 분포는 가정이며 실제 다리 통행 통계가 아니다.
- 1차는 지도·보행·유한 대기열·반복 탑승이다. 6개 시설은 아트란티스·자이로드롭·자이로스윙·자이로스핀·혜성특급·아르카나라이드이며 쁘띠빵빵을 사용하지 않는다. 제품 연동과 추천 효과 평가는 최종 소프트웨어의 후속 단계다. 비상 대피는 별도 범위다.
- 기존 아쿠아리움 코드·설정과 독립 정적 `web-admin`의 가상 데이터를 보존하고 새 시나리오와 구분한다. 문서 갱신만으로 런타임 적용 또는 기능 완료를 보고하지 않는다.

- 작업 완료 답변에 캡처 이미지를 보내지 않는다. 사용자가 별도로 요청한 경우에만 제공한다.

## 커밋 컨벤션

- 커밋 제목은 `type(scope): 변경 내용` 형식으로 작성한다. `scope`는 기능 또는 모듈을 나타내는 짧은 영어 소문자 이름으로 반드시 포함하고, 변경 내용은 한국어로 작성한다.
- 기능 추가는 `feat`, 버그 수정은 `fix`, 문서는 `docs`, 동작 변경 없는 구조 개선은 `refactor`, 테스트는 `test`, 기타 유지보수는 `chore`를 사용한다.
- 기능 단위로 커밋하며 제목은 실제 변경 내용을 구체적으로 표현한다.
- 범위 예시: `config`, `simulation`, `map`, `playback`, `project`.
- 예시: `feat(simulation): 페르소나 관람과 공연 대기 시뮬레이션 구현`, `docs(project): 실행 방법과 설계 및 개발 작업 기준 정리`.

## 시나리오별 실제 작업 경로

- 기존 아쿠아리움 코드·설정·문서·테스트·정적 시안·실행 스크립트는 `development/aquarium/`에 모았다. 이후 아쿠아리움 변경은 이 폴더에서 한다.
- 롯데월드 전용 코드는 `development/lotteworld/`이며 아쿠아리움 모듈을 직접 import하거나 해양 설정·화면을 가져오지 않는다. 선택 진입점은 개발 루트 `run.py`·`run.ps1`이다.
- 매직아일랜드 1–2번인 설정 기반과 3D 안내도 표시를 구현했다. 혜성특급도 지상에 표시하며, 섬 내부 대부분은 넓은 포장 보행 광장으로 정의하고 녹지는 12개 작은 식재 구획으로 둔다. 안내도에 맞춰 성 정면·앞 광장·사선 다리를 같은 직선 축으로 연결하고 주 섬·메이플 돌출부·수면 홈을 구분한다. 다음 미완료 항목은 3번이다. 관리자 앱 통합 등 전체 계획의 미정 사항은 추후 결정한다. 유입·보행·운행 엔진을 구현하기 전에는 지도 준비 상태를 시뮬레이션 실행 완료로 표시하지 않는다.
