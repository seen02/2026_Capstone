# Magic Pass 사용자 웹 디자인

2026-11-20 디자인 초안. Magic Pass는 매직아일랜드 시연 참여자가 현장 QR로 접속해 놀이기구 선호를 정하고, 현재 시설 현황에 따른 추천을 받아 시뮬레이션 속 캐릭터의 이동을 보는 모바일 웹이다. [소프트웨어 계획](software-plan.md) · [구현 체크리스트](implementation-checklist.md)

## 공통 테마

저녁의 놀이공원을 모티프로 짙은 보라 바탕, 아이보리 카드, 금빛 입장권 심벌을 사용한다. 입장권의 모서리가 파인 실루엣과 가운데 별을 로딩 화면과 모바일 상단에 반복한다. 시뮬레이션 웹에도 추후 같은 워드마크, 강조색, 경로·캐릭터 표식을 적용할 수 있다. 전체 지도와 운영 지표의 배치는 시뮬레이션 웹 설계를 따른다. [시뮬레이션 웹](simulation-web.md)

| 요소 | 디자인 기준 |
| --- | --- |
| 짙은 보라 `#20143B` | 로딩 배경, 헤더, 주요 텍스트 |
| 아이보리 `#F7F3ED`와 흰색 `#FFFFFF` | 모바일 바탕과 입력·추천 카드 |
| 행동 보라 `#56349B` | 수락 버튼과 추천 경로 |
| 금빛 `#F3CB79` | 입장권, 로딩 표시, 지도 위 내 캐릭터 강조 |
| 글자와 형태 | 로딩과 모바일 헤더의 서비스명은 Great Vibes 필기체 워드마크로 통일한다. 로딩 문구는 Noto Serif KR 명조체를 사용하고, 모바일 화면의 한글은 시스템 고딕을 사용한다. 카드 모서리는 16px, 버튼은 10px를 기준으로 한다. |

색과 함께 항상 글자 또는 형태로 상태를 구분한다. 지도에서 내 캐릭터는 금빛 원과 ‘나’, 목적지는 별 표식과 시설명으로 표시한다.

## QR 진입과 로딩

현장 QR을 열면 짙은 보라 바탕 위로 금빛 입장권이 나타난다. 그 아래 **Magic Pass** 워드마크와 **‘기다림을 줄이는 마법’** 한 줄을 가까이 붙여 가운데 정렬한다. 두 줄에 옅은 금빛을 사용하고 ‘마법’에 입장권과 같은 금빛을 사용한다.

입장권 주변의 빛은 짧게 한 번 움직인다. 모션 축소 설정에서는 정적인 입장권을 표시한다.

세션 연결과 첫 화면 데이터 준비를 시작하며, 응답이 빠르면 0.6초 내외의 짧은 전환을 목표로 한다. 첫 접속에서는 기본 순위를 자동 저장하고 그 순위에 따른 추천을 표시한다. 3D 지도 준비가 늦어지면 선호·추천 카드부터 표시하고 지도 자리에서만 로딩 상태를 보여 준다. 세션 요청이 실패하면 ‘다시 연결’을 제공한다. 유효한 세션을 다시 열면 저장한 순위와 추천 또는 이용 상태를 복구한다.

## 모바일 첫 화면

짙은 보라색 헤더에 서비스명과 ‘매직아일랜드’를 배치한다. 서비스명 옆의 작은 금빛 티켓은 별을 티켓의 가로·세로 중심에 둔다. 그 아래 **선호 순위 → 추천 놀이기구 → 3D 지도**를 한 열에 배치하며, 세 영역의 위치는 수락 전후에도 유지한다.

| 영역 | 표시와 조작 |
| --- | --- |
| 선호 순위 | 표지판 안내 대상 세 시설을 1~3순위로 함께 표시한다. 각 행 오른쪽에 점 여섯 개(2열×3행) 손잡이를 둔다. 손잡이를 끄는 동안 해당 행을 강조하고 이웃 행을 지나면서 순위를 바꾼다. 바뀐 순서는 손을 떼는 순간 자동 저장한다. 키보드는 손잡이에 초점을 두고 위·아래 방향키를 누르면 순위가 한 칸씩 바뀌고 자동 저장된다. |
| 추천 놀이기구 | 서버 추천 한 곳의 이름, **예상 대기 시간**, ‘수락하고 출발’을 표시한다. 새 순위가 저장되면 추천과 지도 경로를 함께 갱신한다. 끄는 중이거나 저장·갱신이 진행 중이면 이전 추천의 수락을 비활성화한다. |
| 3D 지도 | 추천 카드 아래에 지도를 바로 배치하고 내 캐릭터에는 ‘나’, 목적지에는 시설명을 표시한다. 스크린 리더에는 ‘시뮬레이션 지도’로 안내한다. 추천이 생기면 경로를 미리 표시하고, 수락 확정 후에는 캐릭터가 출발하는 모습을 자동으로 따라간다. 수동으로 지도를 조작하면 ‘내 위치’로 따라가기를 재개할 수 있다. |

기본 QR의 선호 대상은 자이로스핀·혜성특급·자이로드롭이다. 첫 화면에는 시설 순위와 추천 시설명·예상 대기·수락, 지도와 현재 진행 상태만 남긴다. 캐릭터 ID, 좌표, 장문의 조작 설명과 추천 계산 근거는 화면의 기본 정보에서 뺀다. 보상 UI와 지급 로직은 후속 작업이며, 지급 기준은 서버가 유효한 추천 수락을 확정한 시점이다. [공통 데이터 계약](contracts/recommendation-v1.md)

### 모바일 배치 기준

- 세로 화면 390×844 CSS px을 기준으로 하고 320×720 CSS px에서도 헤더와 세 영역을 기본 글자 크기로 스크롤 없이 볼 수 있게 한다. 확인에는 브라우저 주소창과 안전 영역을 뺀 실제 표시 높이를 사용한다.
- 본문은 좌우 여백 12~16px, 영역 간격 8~12px로 구성한다. 순위 손잡이·수락·지도 복귀의 터치 영역은 최소 44×44px을 기준으로 한다. 손잡이 바깥에서는 일반적인 세로 스크롤을 유지한다.
- 정상 상태에서 지도에는 최소 160px을 배정한다. 공간이 부족하면 여백부터 줄인다. 큰 글자 설정, 브라우저 확대, 긴 오류 문구에서는 세로 스크롤을 허용해 내용을 읽고 버튼을 누를 수 있게 한다.

## 추천과 지도 상태

| 상황 | 화면 동작 |
| --- | --- |
| 순위 자동 저장 성공 | 서버가 시설 운영·대기열 합류 가능 여부를 확인하고, 저장한 선호와 유효한 예상 대기·이동 거리를 기준으로 고른 시설을 표시한다. 대기 시간은 ‘예상 대기 5분’처럼 표시한다. 로컬 모의 데이터에는 ‘모의’를 붙인다. |
| 순위 자동 저장 실패 | 순위 목록에 ‘순위를 저장하지 못했어요’와 ‘다시 시도’를 표시한다. 마지막으로 바꾼 순위가 저장되고 새 추천이 도착할 때까지 수락을 비활성화한다. |
| 대기 미집계·갱신 지연·추천 없음 | 알려진 0분과 대기 미집계를 구분한다. 유효한 추천을 제공할 수 없으면 ‘지금 추천할 기구가 없어요’와 ‘추천 새로고침’을 표시한다. 갱신이 지연된 값으로 출발할 수 없도록 한다. |
| 수락 요청 중·추천 만료 | ‘출발 요청 중’으로 바꾸고 중복 입력을 막는다. 추천이 만료됐으면 갱신 후 새 추천을 확인하게 한다. |
| 수락 확정 | 추천 카드의 버튼 자리를 ‘이동 중’, ‘대기 중’, ‘탑승 중’, ‘하차 중’, ‘이용 완료’ 등 서버 진행 상태로 전환한다. 이용 중에는 선호 순위를 읽기 전용으로 표시한다. |
| 지도 연결 실패 | 지도 영역에 ‘지도를 불러오지 못했어요’를 표시한다. 세션과 추천 서버를 사용할 수 있으면 선호 조정과 추천 수락은 유지한다. |

## 공통 서버 연동과 확인 항목

- QR은 `/user?sign_id=magic-island-west`로 연결한다. 서버 발급 쿠키로 세션을 찾고, 기존 `/api/user/*` 요청으로 선호 조회·저장과 추천을 처리한다. [로컬 실행 및 API](../lotteworld/README.md#qr-사용자-진입과-선호-입력)
- 자동 저장은 한 번에 하나의 요청을 보낸다. 저장 중 순위를 다시 바꾸면 최신 순위를 기억하고, 앞선 저장이 확정된 뒤 서버가 반환한 세션 버전으로 제출한다. 추천 카드와 경로에는 마지막으로 선택한 순위에 해당하는 응답을 적용한다.
- 추천 수락 후 위치·진행 상태는 서버가 확정한다. 두 웹은 기존 지도·시설 자원과 공통 서버의 실행 문맥, `character_id`, 상태 버전을 공유한다. 같은 캐릭터가 목적지의 대기줄 입구로 이동하며, 이용 중에는 서버에서 제공하는 대기·탑승·하차 상태를 표시한다. [시뮬레이션 웹](simulation-web.md) · [공통 데이터 계약](contracts/recommendation-v1.md)
- 구현 검증 시 모바일 브라우저 주소창을 펼친 상태에서 세 영역과 주요 버튼이 보이는지 확인한다. 별도 휴대폰의 QR 세션 분리, 갱신 지연·만료, 새로고침 후 상태 복구, 수락한 캐릭터의 위치와 상태가 두 웹에서 일치하는지도 확인한다.

현재 로컬 웹에는 저장 버튼을 이용한 선호 저장, 모의 추천 수락, 두 지도에서의 캐릭터 이동·대기·탑승·하차 표시가 구현되어 있다. 이 문서는 신규 테마와 모바일 배치, 순위 자동 저장, 시설 현황 연동 시 표시할 상태를 정의한다. [기존 QR 사용자 웹 검증](verification/qr-user-entry-and-preferences.md)
