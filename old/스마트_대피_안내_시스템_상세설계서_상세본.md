# 스마트 대피 안내 시스템 상세설계서

영화관 적용 · 프로젝트 계획서 v6 기준 · 2026. 10. 07.

## 1. 설계 범위와 전체 구성

영화관의 통로 상태에 따라 안내 방향을 바꾸는 ESP32 표지판 3대와, 이를 시험하는 PC 대피 시뮬레이터를 함께 구성한다. 시뮬레이터는 가상 관람객을 이동시키고 통로별 위험·혼잡 값을 만든다. 안내 방향은 실제 표지판에서 계산하며, 계산한 결과를 다시 화면의 이동에 반영한다.

| 구성 요소 | 역할과 연결 |
| --- | --- |
| 대피 시뮬레이터 | HTML·CSS·JavaScript. 영화관 지도, 인원 이동, 차단 사건과 비교 결과 표시 |
| 입력·연동 프로그램 | Python. 담당 구역별 USB 입력, 실제 장치 보고 수집, 로컬 시험 기록 |
| 표지판 S1·S2·S3 | ESP32·C/C++. 상태 관리, ESP-NOW 정보 공유, 경로 계산, RGB LED 출력 |
| 중앙 관리 프로그램·G | 별도 수집 장치 G와 연결하여 장치 상태 관찰·중앙 기록·연결 감시 |

### 1.1 동작 흐름

① 화면의 화재·인원 상태 → ② 담당 표지판에 USB 입력 → ③ 표지판 간 무선 공유 → ④ 각 ESP32의 경로 계산·LED 적용 → ⑤ 실제 적용 결과 보고 → ⑥ 화면의 다음 이동 결정. 중앙 관리 장치는 이 흐름의 필수 경유지로 사용하지 않는다.

### 1.2 모형과 배선

모형은 1:50 기준의 외곽 640×480mm, 받침 800×600mm로 구성한다. 표지판 3대의 USB와 G의 USB를 개별 연결한다. LED 패널은 외부 5V 전원, ESP32는 USB 전원을 사용하고 필요한 공통 접지를 연결한다. 데이터는 GPIO18에서 레벨 변환·보호 저항을 거쳐 패널 DIN으로 보낸다. GPIO25의 확인 LED는 입력 수용 시점을 측정하는 용도로 둔다.

중앙 장치 G의 전원을 끄는 조작이 표지판 전원이나 USB 허브 전원을 끊지 않도록 분리한다. 입력 장애 시험은 해당 포트의 송신만 정지하여 보드 재부팅과 구분한다.

## 2. 영화관 공간과 통로 데이터

지상 1층 영화관 일부 구역을 32×24m의 가상 공간으로 모델링한다. 로비 앞 J, 서측 L, 동측 R에 표지판을 설치하고, EL·ER은 외부 출구 통과 경계로 사용한다.

![영화관 평면도: 갈림길 3개, 출구 2개](<C:/컴퓨터공학 종합설계/대피_건물_구조도/건물_평면도.png>)

그림 1. 화면과 모형에 공통으로 사용하는 영화관 평면도.

| 통로 | 계산 방향 | 길이 / 폭(m) | 담당 |
| --- | --- | --- | --- |
| e1 | J → L | 16 / 3.0 | S1 |
| e2 | J → R | 20 / 3.0 | S1 |
| e3 | L → EL | 8 / 2.4 | S2 |
| e4 | R → ER | 8 / 2.4 | S3 |
| e5 | L → R | 16 / 2.4 | S2 |

좌표는 북서쪽을 원점으로 한 m 단위로 둔다. J=(14,19), L=(8,9), R=(24,9), EL=(0,9), ER=(32,9)이다. 통로 면적은 길이×폭으로 계산한다.

계산은 표의 지정 방향만 허용한다. S1·S2는 좌우 안내, S3는 ER 방향 안내 또는 X·? 표시를 사용하며 R→L 되돌아가기는 모델에 포함하지 않는다. 지도 설정은 building-map-v6.json에서 PC·장치용으로 함께 생성하고 같은 지도 ID·해시인지 확인한다.

## 3. 대피 시뮬레이터 설계

초기 인원은 상영 전 로비의 가상 관람객 60명으로 둔다. 상영관과 좌석은 영화관 공간을 설명하는 요소이며, 좌석에서 로비까지의 이동이나 열·연기 확산은 계산하지 않는다. 화재 사건은 지정 통로를 차단하는 입력으로 표현한다.

| 항목 | 동작 규칙 |
| --- | --- |
| 시간·보행 | 논리 시간 간격 0.1초, 기본 속도 1m/s. 실제 표지판 연동은 1배속 |
| 출발·진입 | 로비에서 초당 최대 2명 출발. 같은 통로 진입은 도착 순서대로 처리 |
| 출구 | EL·ER 각각 초당 0.5명 통과. 출구 앞 대기는 접근 통로 인원에 포함 |
| 차단 | 새 진입 금지. 이미 차단 통로 안에 있던 인원은 위치에서 정지·미대피 처리 |
| 인원 보존 | 통로 이동+갈림길 대기+출구 도착 인원의 합을 매 갱신마다 60명으로 확인 |
| 종료 | 최대 180초. 미대피 인원이 남으면 완료시간 대신 미완료로 기록 |

### 3.1 공통 사건표

| 상황 | 입력 사건 |
| --- | --- |
| F00 | 화재 차단 없음. 인원 이동에 따른 혼잡 변화 관찰 |
| F01 | 20초에 서측 1관 영사 장비 화재를 표시하고 e3 차단 |
| F02 | 20초에 동측 3관 영사 장비 화재를 표시하고 e4 차단 |

### 3.2 비교 모드와 일시정지

안내 없음 모드는 거리 기준으로 가까운 출구를 선택한다. 다음 통로의 차단을 해당 갈림길에서 확인하면 3초 대기 후 알고 있는 차단을 제외해 다시 선택한다. 표지판 연동·중앙 단절 모드는 해당 지점의 실제 장치 보고를 따른다. 세 모드의 초기 인원·화재·보행·출구 규칙은 동일하게 둔다.

일시정지는 인원 이동과 예정 사건의 논리 시간만 멈춘다. 정지 중인 인원 분포도 새로운 관측으로 계속 전달하고 장치의 만료 검사는 유지한다. 입력 자체를 끊는 조작은 별도의 장애 시험으로 제공한다. 이동 속도와 출구 처리율은 비교를 위한 모델 설정값이다.

## 4. 장치 입출력과 무선 통신

입력·연동 프로그램은 HELLO의 장치 ID로 USB 포트를 확인한 뒤 S1에는 e1·e2, S2에는 e3·e5, S3에는 e4만 보낸다. 각 보드는 담당 통로 이외의 입력과 PC 방향 명령을 거부한다. USB 입력은 115200bps의 줄 단위 JSON, 한 프레임 1024바이트 이하로 설계한다.

| 메시지 | 전달 경로 | 주요 항목 |
| --- | --- | --- |
| HELLO·동기화 | PC ↔ 담당 장치 / 장치 ↔ 장치 | 장치·설치·지도 ID, 지도 해시, 부팅·입력 세대 |
| SENSOR_RISK | PC → 담당 USB | 입력 세대, 위험 관측 순번, 통로 ID, CLEAR/BLOCKED, 품질 |
| SENSOR_CROWD | PC → 담당 USB | 실험 ID, 분포 ID, 관측 순번, 통로별 인원, 품질 |
| RISK_STATE·CROWD_STATE | 담당 표지판 → 다른 표지판·G | 원천 ID, 부팅 세대, 순번, 관측 키, 담당 구역 상태 |
| ACK | 수신 장치 → 송신 장치 | 수용한 관측 키 또는 거부 이유 |
| REPORT | 표지판 → 자기 USB·G | 표시, 다음 통로, 변경 이유, 사용 상태 버전, 보고 순번 |
| CENTRAL_HEARTBEAT | 중앙·G ↔ 표지판 | 중앙 연결 감시용 신호 |

### 4.1 발행과 수신

통로 상태는 1초마다 새 관측 순번으로 발행하고 위험 변경은 즉시 전송한다. 무선 프레임은 바이트 순서·정수 단위를 고정해 200바이트 이내로 직렬화한다. C 구조체의 메모리를 그대로 전송하지 않고 위험과 혼잡 메시지를 나누어 담당 최대 2개 통로를 담는다.

등록된 S1·S2·S3·G를 같은 채널의 피어로 구성하여 원천 표지판이 다른 표지판에 직접 전송한다. 위험 변경의 ACK가 없으면 150·400·800ms에 제한 재전송한다. 재전송은 원래 관측 키를 유지한다. G에 대한 재시도가 표지판 간 전송을 막지 않도록 목적지별 큐를 분리한다.

수신 처리에서는 길이·원천·순번을 확인하고 큐에 넣는다. 경로 계산과 LED 갱신은 별도 처리 단계에서 수행한다. ACK는 데이터 수용 응답이고, 실제 안내 적용 여부는 REPORT와 LED를 함께 확인한다.

## 5. 상태 관리와 정보 만료

각 표지판은 통로별 위험 상태와 혼잡도를 별도로 저장한다. 새 입력의 원천·세대·순번을 확인하여 중복, 역순 또는 이전 실행의 데이터를 현재 상태에 덮어쓰지 않는다. 재전송·ACK·보고·중앙 연결 신호는 센서 대체 관측의 유효시간을 연장하지 않는다.

| 정보 | 유효시간과 처리 | 안내 반영 |
| --- | --- | --- |
| 통행 가능(CLEAR) | 새 관측 없이 3초 경과 → UNKNOWN | 해당 통로를 경로에서 제외 |
| 차단(BLOCKED) | 입력 중단 후에도 차단 유지 | 담당 원천의 확인된 새 CLEAR로 해제 |
| 혼잡 | 필요한 원천 중 가장 오래된 관측이 5초 초과 → 만료 | 전체 혼잡 비용을 끄고 거리 기준 사용 |
| 실제 장치 보고 | 새 보고 없이 3초 경과 → 보고 단절 | 해당 갈림길에서 가상 인원 대기 |
| 중앙 연결 | 1초 감시 신호, 3초 미수신 → 단절 표시 | 표지판의 위험·혼잡 상태는 별도로 유지 |

### 5.1 일관된 혼잡 분포

시뮬레이터는 같은 논리 시점의 인원 집계에 하나의 분포 ID를 붙인다. 표지판은 세 원천의 같은 실험 ID·분포 ID가 모인 경우에만 새 혼잡 비용을 적용한다. 일부 값만 도착하면 이전의 완성 분포를 유효시간 안에서 사용한다. 위험 변경은 혼잡 분포가 완성될 때까지 기다리지 않는다.

### 5.2 재부팅·초기화·새 실험

원천 보드가 재부팅되면 새 부팅 세대를 확인하고 현재 입력을 다시 동기화한다. 동기화되지 않은 과거 통행 가능 상태를 정상으로 복구하지 않는다. 입력 세대가 바뀔 때도 현재 입력 확인 절차를 거친다. 알려진 차단은 새 해제 입력을 확인하기 전까지 유지한다.

인원 초기화는 새 실험 ID와 관람객 위치를 준비하되 현재 화재 상태와 연결 장애는 유지한다. 새 실험을 준비할 때는 ① 담당 보드에 화재 해제 입력 ② 수용 확인 ③ 새 인원 실행 준비 ④ 세 장치의 새 실행 보고 확인 순으로 진행한다. 중앙 복구 시에는 현재 보고부터 수집하고 캐시된 옛 상태를 재배포하지 않는다.

## 6. 경로 계산과 LED 표시

### 6.1 통로 비용과 A*

차단·미확인 통로를 먼저 제외한다. 나머지 통로의 비용은 길이에 혼잡 가중치를 더해 산정한다. 통로 면적 A는 길이×폭, 인원 N은 시뮬레이터의 해당 통로 집계값으로 둔다.

밀도 ρ=N/A, 혼잡값 q=min(ρ/1.0, 3)  
통로 비용=길이×(1+αq)  
α=2(혼잡 정보 유효), α=0(혼잡 정보 결측·만료)  
휴리스틱 h=현재 노드에서 EL·ER까지 직선거리 중 작은 값

1명/㎡는 비용 정규화 값이며 안전 기준 밀도를 뜻하지 않는다. 비용은 경로 비교 점수로 사용한다. 구현 시 비용은 1000배 후 올림, 휴리스틱은 1000배 후 내림한 정수로 저장한다. 각 간선의 휴리스틱 일관성을 검사하고 실패 시 h=0으로 처리한다.

계산 순서: 상태 버전 고정 → 유효 통로 구성 → f=g+h가 작은 노드 확장 → 출구 후보 비교 → 경로 복원 → 상태 버전 재확인 → 표시 정책 적용. 비용 동률은 출구 ID와 간선 ID 순으로 결정한다. 계산 중 상태가 바뀌면 이전 결과를 버리고 새 상태로 다시 계산한다.

### 6.2 방향 변경과 표시

혼잡만 변하면 새 후보 비용이 기존의 85% 이하이고 같은 다음 통로 후보가 5초 유지되며 직전 방향 변경 후 5초가 지났을 때 전환한다. 현재 경로의 위험·미확인 발생은 바로 경로를 무효화한다. 이용 가능한 경로가 새로 생겼을 때도 기다리지 않고 표시한다.

| 표시 | 의미 |
| --- | --- |
| 초록 화살표 | 수신한 위험·혼잡 정보로 선택한 다음 방향 |
| 화살표+노랑 점 | 위험 정보는 유효하나 혼잡 정보가 부족하여 거리 기준 사용 |
| 빨강 X | 알려진 차단 때문에 출구까지의 경로가 없음 |
| 노랑 ? | 위험 정보 부족 또는 지도 오류로 경로를 확정할 수 없음 |

### 6.3 고정 입력의 기대값

| 조건 | S1 / S2 / S3 |
| --- | --- |
| 모든 통로 통행 가능·통로 인원 0명 | 왼쪽 / 왼쪽 / 오른쪽 |
| e3에 30명·다른 통로 0명·차단 없음 | 안정화 후 오른쪽 / 오른쪽 / 오른쪽 |
| e3 차단·혼잡 없음 | 오른쪽 / 오른쪽 / 오른쪽 |
| e3·e4 모두 차단 | X / X / X |

## 7. 화면, 중앙 관리와 실행 구조

화면 상단에는 모드·화재 상황·논리 경과시간을, 중앙에는 평면도·인원·차단 통로를 표시한다. 옆에는 S1·S2·S3의 실제 방향·마지막 보고 경과시간·판단 이유를, 하단에는 도착·대기·미대피 인원과 사건 기록을 둔다. 중앙 연결, 구역 입력, 무선 원천 정보, 실제 보고 연결을 각각 표시한다.

### 7.1 실제 장치 결과의 반영

ESP32는 LED 적용 후 REPORT를 보내고, 변화가 없어도 1초마다 새 보고 순번을 보낸다. PC는 지도 해시·실험 ID·장치 ID와 수신 경과시간을 확인한 뒤 next_edge를 해당 갈림길의 다음 이동으로 사용한다. X·? 또는 보고 만료 시 대기한다. 차단 통로 진입 검사는 공통 이동 규칙에서 별도로 수행하며 PC의 예측 경로로 실제 출력을 대신하지 않는다.

### 7.2 중앙 단절 시험의 구성

중앙 관리 프로그램과 G만 중지한다. 시뮬레이터·입력·연동 프로그램·표지판 USB와 전원·ESP-NOW는 유지한다. 인원 실행과 상태 순번도 유지한 채 새 e3 혼잡, 새 e4 차단을 담당 보드에 각각 입력하여 다른 표지판의 갱신을 확인한다. 중앙 프로그램과 입력 프로그램은 별도 프로세스 및 종료 수단을 둔다.

### 7.3 프로그램과 기록

| 영역 | 구현 범위 |
| --- | --- |
| 화면·시뮬레이션 | 지도 렌더링, 인원 이동, 사건표, 조작 화면, 실제 보고 반영 |
| 로컬 입력·연동 | 장치 ID·USB 포트 확인, 구역 입력, 보고 수집, 로컬 API·CSV/JSON 저장 |
| ESP32 펌웨어 | 입력 검사, 상태 저장, 피어 전송, 경로 탐색, 방향 정책, LED·REPORT |
| 중앙 관리 | G 연결, 장치 관찰과 중앙 기록. 로컬 입력 경로와 분리 |

실험 ID·지도 해시·모드·사건 시각·입력 원천과 순번·사용 상태 버전·선택 통로·표시·보고 수신 시각·연결 변경을 기록한다. 중앙 기록이 중지되어도 입력·연동 프로그램의 로컬 시험 기록은 유지한다. 화면 자료와 실행 자원은 PC에 포함하여 인터넷 없이 실행한다.

시작 순서: 지도·포트 설정 확인 → 표지판·G 연결 → 입력·연동 프로그램 실행 → 장치 동기화 → 화면·중앙 관리 실행 → 새 실험 준비. 로그 저장 실패는 화면에 알리되 ESP32의 경로 계산을 중단시키지 않는다.

## 8. 시험 설계와 요구사항 대응

제출 요구사항 R01–R12를 아래의 입력과 확인 결과에 연결한다. 예상 경로는 펌웨어의 출력을 복사하지 않고 허용 경로를 열거하여 계산한다. 실행 조건과 원시 로그를 함께 보관하고 미실행·실패·통과를 구분한다.

| 요구사항 | 시험 입력·방법 | 확인 기준 |
| --- | --- | --- |
| R01 지도 | 지도·모형·각 보드 설정 대조 | 갈림길 3·출구 2, 통로·표지판 위치·해시 일치 |
| R02 이동 | F00·F01·F02 실행 | 항상 총 60명. 차단 새 진입 0건, 미대피 분리 |
| R03 입력 | 담당·타 담당 통로와 방향 명령 전송 | 담당 입력만 수용. 1초 갱신·위험 즉시 전송 |
| R04 공유 | e3는 S2, e4는 S3에만 새 입력 | 다른 보드가 원천 무선 정보로 갱신 |
| R05 경로 | 차단 32조합×인원 3분포×출발점 3개 | 288개 경로·비용 기대값 일치 |
| R06 전환 | 15% 개선·5초 유지 경계와 새 차단 | 혼잡 전환 조건 준수. 위험에는 대기 조건 미적용 |
| R07 연동 | LED·REPORT·다음 이동 동시 관찰 | 출력·보고·이동 일치. 3초 보고 단절 시 대기 |
| R08 만료 | 입력 정지·중복·역순·재부팅 | CLEAR 3초·혼잡 5초 만료, BLOCKED 유지 |
| R09 중앙 | G OFF·중앙 중지 후 새 혼잡·위험 | 입력·무선·LED·화면 연동 유지 |
| R10 비교 | 세 모드에 동일 사건표 적용 | 도착·대기·미대피·변경 기록, 180초 미완료 표시 |
| R11 지연 | 장치별 위험 30회·혼잡 전환 촬영 | 95백분위 1.5초 이내 목표·누락 기록, 혼잡 7초 목표 |
| R12 반복 | 인터넷 차단·30분·세 모드 10회 | 예상 외 재부팅·인원 오류 없음 |

### 8.1 지연 측정과 비교 결과

화면 입력 적용 표시와 세 LED를 같은 영상에 담아 위험 입력부터 실제 표시까지 측정한다. 입력 확인 LED로 구간을 구분하고 PC 로그의 입력→보고 시간도 별도로 기록한다. 장치별 30개 값을 정렬한 29번째 값으로 95백분위를 구한다. 누락은 성공 표본에서 제외해 숨기지 않고 별도로 집계한다.

288개 경로 시험의 인원 분포는 전 통로 0명, e3 30명, e4 30명의 세 가지로 둔다. 나머지 인원은 로비에서 대기한다. 대피 비교 결과에는 모델 설정과 실험 조건을 함께 표시하여 어떤 안내 선택이 출구 이용과 대기에 영향을 주었는지 살펴볼 수 있도록 한다.
