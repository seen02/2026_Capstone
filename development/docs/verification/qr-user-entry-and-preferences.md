### 짧은 모바일 화면 재검증

320×568에서는 지도 하단이 표시 영역을 벗어났고, 667×375에서는 지도 전체가 첫 화면 아래로 밀렸다. 짧은 화면의 여백과 지도 높이를 조절하고, 가로 화면에서는 카드 옆에 지도를 배치했다.

Microsoft Edge 모바일 에뮬레이션에서 화면을 연 뒤 크기를 바꿨다. 320×520·320×568·320×720·360×640·390×844 세로와 667×375·844×390 가로에서 헤더, 순위, 추천, 지도가 스크롤 없이 보였다. 순위 손잡이와 수락 버튼은 높이 44px 이상을 유지했다. 320×480에서 글자를 키우면 세로 스크롤로 지도 하단까지 볼 수 있었고, 667×375에서 QR 로딩 문구도 화면 안에 표시됐다.

### 넓은 화면 비율 재검증

640px 이상 화면과 짧은 가로 화면에서 카드와 지도를 나란히 배치하고 지도 비율을 4:3으로 맞췄다. Microsoft Edge에서 600×420·640×700·667×375·768×800·844×390·1024×768·1440×900·1440×375 크기로 바꾸며 지도 비율과 첫 화면의 가로·세로 가림 여부를 확인했다. 320×520·390×844 세로에서는 세 영역이 한 열에 표시됐다.

### 추천 카드 표시 재검증

Microsoft Edge에서 320×520부터 1024×768까지 다섯 화면 크기를 확인했다. 추천 시설명과 예상 대기 시간이 각 제목 아래 큰 글씨로 표시됐고, 수락 버튼과 지도가 표시 영역에 들어왔다. 사용자 카드의 ‘모의’ 표기를 제거한 뒤에도 응답에 `source.kind: mock`가 포함됐다. 순위 변경 후 자이로스핀 5분에서 혜성특급 8분으로 갱신됐고, 테스트 응답의 대기 0초는 0분으로 표시됐다.

추천 카드를 따뜻한 아이보리로 바꾸고 수락 버튼에는 헤더의 짙은 보라와 입장권의 금빛 화살표를 적용했다. 320×520 화면에서 지도까지 한 화면에 보였고, 버튼과 대기 시간의 글자 대비가 4.5대 1 이상임을 확인했다. 순위 저장 중에는 수락 버튼이 비활성화되고 추천 갱신 후 다시 활성화됐다.

카드 스타일을 통일한 뒤 320×520·390×844·667×375에서 선호와 추천 카드에 같은 흰색 바탕, 테두리, 그림자가 적용되고 아이보리 페이지 바탕과 구분되는 것을 확인했다.

### 지도 아래 여백 재검증

390×844·430×932 세로 화면에서 지도 아래 여백은 10px, 320×520에서는 6px이었다. 가로 화면에서는 지도 비율 4:3을 유지했고, 1366×768과 1920×1080에서 지도 아래 여백은 10px이었다. 9가지 표시 크기에서 화면 넘침이 없었고, 지도 확대 후 목적지 경로 보기와 내 캐릭터 복귀가 동작했다.

### 순번 기반 대기 시간과 하차 후 재출발

QR 세션 API 검사 8개와 시설 운행 검사 10개를 통과했다. 같은 차량의 탑승 가능 순번과 다음 차량을 기다려야 하는 순번을 구분했고, 줄에서 기다리는 동안 예상 시간 값이 갱신되는 것을 확인했다. 세 시설의 하차 후 공공 연결점에서 세 대기줄 입구까지 9개 경로를 검증했다. 하차 후 같은 캐릭터와 위치로 다음 추천을 받고 두 번째 이용을 수락했다. 두 번째 이용 중 첫 수락 요청을 재전송해도 현재 이용은 유지됐다.

모바일 브라우저 통합 검사에서는 대기 중 순번과 예상 시간, 탑승·이용·하차 상태를 확인했다. 하차 직후 순위를 변경해 자이로드롭으로 새 추천을 받은 뒤 하차한 지점에서 두 번째로 출발했다.

대기 상태 응답을 사용해 예상 대기 ‘10분’과 대기 순서 ‘128번째’가 320×520·390×844·560×375·667×375·1024×768에서 같은 줄에 표시되고 카드와 지도가 화면에 들어오는 것을 확인했다. 탑승 상태로 바뀌면 두 값이 함께 숨겨졌다.

### 하차 후 자동 추천

모바일 브라우저에서 하차 상태로 다시 접속하면 저장된 순위로 추천을 자동 조회했다. 하차 후 자동 조회를 지연시킨 상태에서 순위를 연달아 바꾸자 마지막 순위가 한 번 저장됐고, 이전 조회 결과를 화면에 표시하는 대신 새 추천과 대기 값을 표시했다. 자동 조회가 실패하면 ‘추천 새로고침’으로 다시 조회할 수 있었다.

배경 방문객 240명·12배속 검증 서버에서 모바일 브라우저 통합 검사를 통과했다. 혜성특급 하차 후 버튼을 누르지 않아도 저장된 순위로 추천이 표시됐고, 자이로드롭을 1순위로 옮기면 추천이 갱신되어 하차 위치에서 두 번째로 출발했다.

현재 지도와 모의 추천 경로표의 해시를 맞추고 경로 생성기의 일치 검사를 통과했다. 시설 운영·대기 값은 그대로 보존했으며, 로컬 추천 API가 다시 정상 응답했다.

### 2초 로딩과 지도 중심 고정

입장권·워드마크 애니메이션이 각각 2초이고 로딩 화면이 최소 2초 동안 표시되는 것을 확인했다. 사용자 지도에서 이름표와 연결선, 캐릭터 복귀 버튼을 제거했다. 목적지 경로 보기와 확대 중 카메라 중심이 캐릭터에 고정됐다. 320×520·390×844·667×375에서 세로 카드 간격은 각각 8px·약 14px·8px이었고 지도가 표시 영역 안에 들어왔다.

### 추천 시점의 시뮬레이션 예상 대기

첫 추천, 하차 직후의 추천, 하차 후 선호를 변경해 받은 추천의 `wait_seconds`를 같은 시뮬레이션 시각의 `/api/state` 시설별 `estimated_wait_sim_s`와 대조했다. 세 값이 각각 해당 시설의 시뮬레이션 값과 일치했다. 선호 순위를 유지한 채 1순위 시설의 입구로 오는 인원을 늘리자 새 추천은 다른 시설로 바뀌었다.

QR 세션 9개, 개발용 모의 추천·공통 정책 10개, 시설 운행 10개 검사를 통과했다. 로컬 시연 서버 `8767`의 첫 QR 추천 응답에서도 `source.kind: simulation`을 확인했다.

배경 방문객 240명·8배속 검증 서버에서 Microsoft Edge 모바일 에뮬레이션으로 첫 화면과 하차 후 자동 추천을 확인했다. 두 경우 모두 추천 카드에 API의 예상 대기 시간을 분 단위로 표시했고, 하차 후 순위를 변경해 갱신된 추천으로 다시 출발했다.

### 직전 이용 시설의 추천 우선순위

혜성특급이 저장된 1순위인 세션에서 탑승을 마치자 다른 기구가 추천됐다. 하차 후에도 혜성특급을 1순위로 유지한 채 나머지 순위를 바꾸면 다른 기구의 추천이 갱신됐다. 추천 정책 검사에서는 직전 이용 시설만 유효한 후보일 때 해당 시설이 다시 추천되는 것을 확인했다.

Microsoft Edge 모바일 에뮬레이션에서 혜성특급 하차 후 다른 기구가 자동으로 표시되고, 같은 캐릭터로 다시 출발하는 흐름을 확인했다.

### 아직 타지 않은 시설 우선 추천

같은 QR 세션에서 두 시설의 하차를 완료하고 같은 쿠키로 재진입한 뒤 추천을 조회했다. 아직 타지 않은 세 번째 시설의 추천과 현재 시뮬레이션 예상 대기가 반환됐다. 정책 검사에서는 이미 탄 두 시설이 선호 1·2순위여도 세 번째 시설이 선택됐다. 미이용 후보끼리 선호 순위나 대기 시간이 바뀌면 추천이 달라졌고, 미이용 후보가 추천 조건을 만족하지 않거나 모든 시설을 이용한 경우 재이용이 가능했다.

### 새 바퀴 시작

실제 시뮬레이션에서 세 시설의 하차를 모두 마치면 새 바퀴의 첫 추천에서 직전 시설이 제외되고, 다른 시설의 최신 예상 대기가 반환됐다. 바퀴 도중 선호 순위를 바꾸면 이미 이용한 시설도 새 후보가 됐고 직전 시설은 계속 첫 추천에서 제외됐다. 순위 변경 없이 재저장한 경우 바퀴의 진행 기록이 유지됐다.

추천 정책 13개와 QR 세션 통합 검사 10개를 통과했다. Microsoft Edge 모바일 에뮬레이션에서 새 바퀴 첫 추천에 후보가 없는 응답을 주입해, 사용자 조작 없이 재조회하고 후보가 생기면 추천 카드를 표시하는 것을 확인했다.

### 지도 왼쪽 위 버튼 제거
