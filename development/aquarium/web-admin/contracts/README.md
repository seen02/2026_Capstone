# API 계약 예정 영역

2026-11-11 최신 시뮬레이션 기준은 [매직아일랜드 개발 명세](../../../docs/design.md)다. 관측 10:00~19:00, 계획 유입 10,350명, 개인 예정 체류 120~240분(대기 포함)을 적용한다. 기존 Python API는 있으나 이 정적 시안과의 제품 계약·연동은 아직 없으며 1차 범위에도 포함하지 않는다. 아래 표는 향후 계약 후보이고 구현됐다는 뜻이 아니다.

현재 이 시안과 연결된 API 구현·확정 스키마는 없다. 아래는 디자인에서 도출한 후보 경계이며 실제 구현 때 기존 `aquarium_sim/server.py` 응답을 먼저 검토한다. 관측 종료와 폐장을 구분하고 실제 진입 시각부터 대기 포함 체류를 계산한다.

| 후보 자원 | 목적 | 주의 |
|---|---|---|
| zones / zone state | 구역 메타·인원·정원·대기·갱신시각 | 정적 정의와 관측 상태를 구분 |
| route recommendations | 선호 구역·가용 시간에 대한 경로 | 총시간·대기·산정 근거·유효시각 필요 |
| ride operations | 놀이시설별 대기·승하차·운행·차량·회차 상태 | 대기 정원·탑승 정원·차량 수·출발 간격을 분리 |
| arrivals / experiment state | 시간별 계획·실제 진입, 복귀·잔류·미진입, 종료 상태 | 19시 종료의 진행 대기를 포기·완료로 바꾸지 않음 |
| performances (기존 시안) | 아쿠아리움 공연 시간표·회차 상태 | 새 놀이시설 반복 운행 또는 퍼레이드 관람 기능으로 해석하지 않음 |
| operations summary | 운영 지표와 시계열 | 조회 범위·집계 간격·정의 필요 |
| signs | 장치 연결·표시 상태 | 조회와 제어 권한을 구분 |
| alerts | 혼잡 이벤트와 확인 상태 | 규칙·중복·처리 상태 정의 |

연동 시 `fixtures/`의 직접 참조를 데이터 서비스 계층으로 교체한다. UI와 API의 상태 모델을 명시적으로 변환하고, 로딩·빈 데이터·오류·오래된 데이터 상태를 별도로 구현한다. 추천은 서버에서 계산하며 UI에 고정한 절약 시간을 사용하지 않는다. 현재 프로젝트의 `/api/signs`는 모니터링용이므로 제어 API가 있다고 가정하지 않는다.
