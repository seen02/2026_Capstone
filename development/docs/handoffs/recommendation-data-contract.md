# 추천·시뮬레이션 공통 데이터 계약 인계

## 목표와 완료 조건

다음 작업은 추천 서버와 롯데월드 시뮬레이션이 공유할 **데이터 계약을 작성하는 것**이다. 기존 시설·좌표·경로 구조를 확인하고, 필수 필드·자료형·단위·예시, 상태 전이, 데이터 출처·시각·미집계 처리와 모의 상태를 실제 시뮬레이션 상태로 대체할 경계를 문서화한다. [체크리스트](../implementation-checklist.md)의 공통 데이터 계약 항목을 기준으로 관련 문서를 갱신하고 완료 여부를 판단한다. 추천 서버나 엔진 구현 완료를 주장하지 않는다.

## 결정과 제약

- 추천 로직·서버를 시뮬레이션 엔진 전체보다 먼저 개발한다. 먼저 공통 계약을 정하고, 모의 대기 상태로 추천을 검증한 뒤 시뮬레이션 상태를 연결한다. 모의·실제 시뮬레이션·영상 관측 출처를 구분한다.
- 공통 QR에 접속한 사용자마다 세션과 가상 캐릭터를 연결한다. 자이로스핀·혜성특급·자이로드롭 사이 표지판 주변에서 시작하며 정확한 좌표는 미정이다. 위치는 GPS가 아닌 시뮬레이션 좌표다.
- 시설별 선호 순위, 가상 위치, 예상 대기와 이용 가능 상태를 고려해 다음 시설 한 곳과 이유를 추천한다. 수락하면 캐릭터가 이동하고, 시뮬레이션상 이용 완료 후 체험 보상을 지급하며 다음 추천을 제공한다. 다중 사용자와 수락으로 인한 혼잡 영향도 후속 범위다.
- 전체 시뮬레이션·영상 분석·실제 탑승 인증은 아직 구현되지 않았다. 기존 아쿠아리움 시나리오와 롯데월드 코드를 독립적으로 유지한다. 프로젝트 지침 `development/AGENTS.md`를 따른다.

## 연결 지점

- `development/docs/implementation-checklist.md`: QR 시연·추천 연동 체크리스트와 기존 시뮬레이션 작업.
- `development/docs/software-plan.md`: 시연 흐름, 공통 계약, 기존 제품 설계 및 구현 순서.

## 검증과 남은 문제

이번 대화에서는 관련 코드·문서와 Git 상태를 읽어 확인했으며 구현이나 테스트 실행은 하지 않았다. 이동·대기·탑승 엔진 및 실제 대기시간은 미구현이다. 추천 점수·동점 처리·운영 불가 및 미집계 처리, 임의 좌표 경로 계산 방식, 표지판 정확한 좌표, 재시작·동시 수락 처리와 세션 수명 등은 계약 작성 시 기존 구조에 맞춰 판단하거나 미정으로 명시한다. 시연에 필요한 휴대폰 네트워크 접속은 별도 구현이 필요하다.
