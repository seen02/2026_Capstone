# 매직아일랜드 기능별 개발 체크리스트

기준일은 2026-11-24다. [최신 개발 명세](design.md)를 구현하기 위한 작업 목록이다. **체크 항목 하나를 새 채팅 하나의 작업 범위**로 삼는다. 로컬 시연에서 시뮬레이션 1–8번, 운영자 대시보드, QR 사용자 웹과 실시간 추천·수락·이동 연동을 구현했다. 다음 검증은 배포, 실제 휴대폰 접속과 9번 장시간 연속 실행이다.

이 목록은 공통 서버·사용자 웹·시뮬레이션 웹과 엔진의 작업을 구분한다. 영상 기반 분석과 관리자 대시보드를 포함한 전체 범위와 순서는 [최종 소프트웨어 계획](software-plan.md)을 따른다.

## 공통 서버·사용자 웹·시뮬레이션 웹 개발

세 구분은 화면과 계산의 담당을 나타낸다. QR 추천 서버는 연속 시연 엔진에서 시설 운영과 대기열 상태를 읽는다. 각 체크 항목의 소유 범위와 완료 여부를 따로 확인하며 화면만 구현해 서버·엔진이 완료됐다고 표시하지 않는다.

### 공통 서버·데이터

- [x] **공통 데이터 계약** — 시설 ID·지도 버전, 사용자 세션·가상 위치, 선호 순위, 시설 운영·대기 상태, 추천과 수락·이동·이용·보상 상태를 정의한다. 시뮬레이션 실행 ID·시각 및 데이터 출처를 구분한다. **완료 기준:** 기존 설정·지도·경로 코드와 대조한 계약 문서에 필수 필드, 자료형·단위, 예시, 상태 전이와 미집계 처리가 있고, 검증용 예제와 엔진 상태에 공통 추천 입력 형식을 사용한다. 실제 구현되지 않은 API를 완료된 것처럼 표시하지 않는다.

  문서: [공통 데이터 계약 v1](contracts/recommendation-v1.md), [검증 기록](verification/recommendation-data-contract.md). 기존 지도에서 계산한 경로를 포함한 모의/시뮬레이션 입력과 추천·수락·수락 보상·이용 완료 JSON 예제를 대조했다. 시뮬레이션 입력과 workflow는 구조 검증용 가정이며 실행 결과가 아니다.
- [x] **실시간 추천·수락 API** — 세션의 선호와 현재 위치, 시뮬레이션 대기열을 사용해 추천한다. 수락 시 서버가 추천과 실행 상태를 검증하고, 같은 요청을 재전송하면 기존 수락 결과를 반환한다. [API와 실행 안내](../lotteworld/README.md#qr-사용자-진입과-선호-입력) · [검증 기록](verification/qr-user-entry-and-preferences.md)
- [ ] **추천 수락 보상 API** — 서버가 유효한 수락을 확정하면 보상을 한 번 지급하고 지급 기록을 조회한다.

### 사용자 웹

요구사항: [사용자 웹](user-web.md). 참여자가 자신의 추천·보상·캐릭터 상태를 확인하는 모바일 화면이다.

- [x] **QR 사용자 진입과 선호 입력** — 브라우저별 세션과 캐릭터를 발급하고, 서쪽 안내판 `[123, 111]`m에서 입구 다리 쪽의 빈 보행 위치에 배치한다. Magic Pass 로딩 후 자이로스핀·혜성특급·자이로드롭의 기본 순위와 시뮬레이션 대기열을 반영한 추천을 보여 준다. 드래그나 방향키로 순위를 바꾸면 자동 저장하고 추천과 경로를 갱신한다. 같은 쿠키로 캐릭터와 순위를 복구하며, 세션을 이어갈 수 없으면 다시 연결 카드를 표시한다. [로컬 실행 방법](../lotteworld/README.md#qr-사용자-진입과-선호-입력) · [검증 기록](verification/qr-user-entry-and-preferences.md)
- [x] **추천·수락·다음 추천 화면** — 추천 시설과 예상 대기, 수락 버튼을 표시한다. 줄에 합류하면 순번과 예상 대기를 갱신하고, 하차 후 실제 하차 위치에서 다음 추천을 자동으로 표시한다. [모바일 브라우저 검증](verification/qr-user-entry-and-preferences.md)
- [x] **자기 캐릭터 중심 3D 지도** — 내 캐릭터의 위치·추천 목적지·경로와 수락 후 이동을 표시한다. 브라우저 모바일 에뮬레이션에서 카메라 중심과 캐릭터 위치의 일치, 추천 경로와 출발 흐름을 확인했다. [지도 검증](verification/qr-user-entry-and-preferences.md)
- [ ] **보상 지급 표시** — API가 확정한 보상 지급 상태와 결과를 표시한다.

### 시뮬레이션 웹·공통 연동

요구사항: [시뮬레이션 웹](simulation-web.md). 전체 방문객·줄·시설 운행과 QR 사용자 캐릭터를 관찰하는 화면이다. 엔진 자체의 구현은 아래 3–9번에서 관리한다.

- [x] **전체 공간 3D 시연 화면** — 시간 표시·재생바 없는 맵 중심 화면에 엔진의 방문객·대기열·운행 상태를 연결했다. [화면 연동 검증](verification/magic-island-continuous-demo-ui.md)
- [x] **추천 수락과 엔진 이동 연동** — 로컬 시연에서 같은 `context`·`character_id`로 이동·대기열 합류·탑승·하차를 처리한다. QR 캐릭터를 대기열과 차량 정원에 반영하고 두 화면에서 같은 진행 상태를 확인했다. [공유 상태 검증](verification/qr-user-entry-and-preferences.md)
- [x] **운영자 대시보드와 시뮬레이션 탭** — `/operator`에서 시설별 운행·대기·혼잡, 방문객 흐름과 안내판 정보를 표시한다. 탭 전환 중 지도 시점과 시설 선택을 유지한다. [동작과 화면 검증](simulation-web.md#운영자-대시보드-탭)
- [ ] **현장 안내판 영상 연동** — 대시보드의 재생 영역에 서버의 영상 URL과 장치 연결 상태를 연결한다. 안내판 선택과 미연결 화면은 구현했다.

위치는 시뮬레이션의 가상 좌표다. 로컬에서는 한 서버에서 시뮬레이션 `/`, 운영자 대시보드 `/operator`, QR 사용자 웹 `/user?sign_id=magic-island-west`를 제공한다.

## 연속 시연 엔진과 지도 개발

공통 기준은 **종료 시각을 정하지 않은 연속 실행, 6개 시설, 동일 사용자 상태를 공유하는 두 3D 화면**이다. 배경 방문객의 초기·목표 인원, 개인 체류와 빈자리 보충 간격은 연속 시연 설정에서 관리한다. 각 항목에는 필요한 검증과 관련 문서 갱신을 포함한다.

- [x] **1. 시나리오 선택과 설정 분리** — 기존 아쿠아리움과 매직아일랜드의 지도·운영·선호 설정을 구분하고 서버·실행 진입점에서 선택할 수 있게 한다. **완료 기준:** 아쿠아리움이 기존대로 실행되고, 새 시나리오 설정을 독립적으로 불러오며 잘못된 설정을 검출한다. 이후 기능을 연결할 기반까지 작업한다.

  구현 위치는 `aquarium/`·`lotteworld/` 독립 프로젝트와 루트 `run.py` 선택 진입점이다. [설정 계약](../lotteworld/docs/configuration.md) · [검증 기록](verification/scenario-isolation.md)

- [x] **2. 매직아일랜드 3D 지도와 시설 표시** — 안내도에 대응하는 주 섬·메이플 돌출부·호수·6개 시설의 상대 배치와 입체 특징을 구성하고 성 정면·앞 광장·사선 다리를 같은 직선 축으로 연결한다. 성 바닥 둘레의 포장 광장을 보행 공간으로 연결하고, 해안 녹지와 내부 화단을 보행 제한 구역으로 적용한다. 혜성특급은 지상 모형으로 표시한다. **완료 기준:** 전체 보기에서 시설·동선을 구별하고 같은 미터 좌표의 3D 형상과 보행 공간 판정을 사용한다. 다리에서 입출구까지의 연결, 회전·확대·이동·시점 복귀·가림 처리와 모형 선택을 확인한다. 최종 대기 자리 수는 4번에서 검증한다.

  구현: `lotteworld/web/map3d.js`·`rides.mjs`, `configs/map.json`·`map_geometry.py`. `public_walkable`이 포장면을 정의하고 `navigation.mjs`가 화면에 표시할 보행 경로를 찾는다. 여섯 대기 구획은 4번에서 구현한 실제 자리와 보행 경로를 표시한다. [3D 지도 검증](verification/magic-island-map3d.md) · [설정 계약](../lotteworld/docs/configuration.md)

  시연 화면은 3D 지도에 화면 대부분을 할당하고 시설을 선택할 때만 상세 패널을 연다. 참조 동선과 시설 확대는 패널에서 각각 조작한다. [시뮬레이션 웹 요구사항](simulation-web.md#기본-시연-화면과-시설-선택)

- [x] **3. 연속 유입·개인 체류·퇴장** — 수동 종료까지 개인별 체류에 따라 퇴장시키고 빈자리를 보충한다. `GET /api/state`의 현재 체류·누적 진입·누적 퇴장으로 보존식을 확인할 수 있다. 240명과 1,500명 조건에서 인원 보존·상한을 확인하고, 배경 순환 중 두 QR 세션이 분리되는 것도 확인했다. 현재 배경 방문객 기본값은 1,500명이다. [연속 시연 설정](../lotteworld/configs/continuous.json) · [검증 기록](verification/magic-island-continuous-arrivals.md)

- [x] **4. 물리적 대기열과 승하차 보행** — 여섯 시설의 실제 자리 합류·전진·이탈, 승차 지점 접근, 전용 하차 보행과 공공 광장 합류를 구현했다. 만석이면 다른 시설로 이동하며, 하차한 방문객은 빨간 출구를 한 명씩 1 내부 초 간격으로 통과한다. 대기 자리 720개와 자리 중복 방지, 난간·예약 구획의 간섭, 체류 만료 후 다리 퇴장을 검증했다.

  시설별 대기 구획은 1회 탑승 정원의 2.5배 이상을 수용한다. 자리 예약·보행 상태는 `/api/state`에서 확인할 수 있다. [공간·런타임 검증](verification/magic-island-physical-queues-and-boarding.md) · [설정·상태 계약](../lotteworld/docs/configuration.md#물리적-대기열과-승하차-보행)

- [x] **5. 회차 단위 놀이시설 운행** — 자이로드롭·자이로스윙·자이로스핀·아르카나라이드의 승차·확인·운행·하차를 자동 반복한다. 선두 대기객 순서, 정원 이내 빈 좌석 출발, 장치 재사용과 탑승 중 체류가 만료된 방문객의 하차·다리 퇴장을 확인했다. 자이로드롭 만석 회차에서 마지막 방문객의 빨간 출구 통과까지 다음 승차가 지연된다. [시간의 근거와 조절 범위](magic-island-research.md#시연용-초기값) · [검증 기록](verification/magic-island-ride-operations.md)

- [x] **6. 아트란티스·혜성특급 차량 운영** — 아트란티스 8인승 보트 8대·승강장 2곳과 혜성특급 26인승 열차 1편성·승강장 1곳을 운용한다. 차량을 재사용하며 정원·승강장·코스 점유 상한을 지키고, 코스 점유와 승강장 만석이 각각 출발을 지연시키는 것을 확인했다. `/api/state`의 `rides`에서 차량별 승강장과 코스 구간, 배정 승객을 조회한다. [시설별 운행·상태 계약](../lotteworld/docs/configuration.md#시설별-운행-설정) · [검증 기록](verification/magic-island-ride-operations.md)

- [x] **7. 방문객 선호와 반복 이용 행동** — 개인 선호, 남은 체류, 이동과 예상 대기를 시설 선택에 연결했다. 갈 시설이 없으면 광장을 걸으며 대기열을 다시 확인한다. 대기 중 체류 기한이 지나면 해당 회차의 하차를 마치고 퇴장한다. 이미 이용한 시설도 다시 고를 수 있으며, 같은 시드의 결과를 상태 조회 빈도와 무관하게 재현했다. [행동 설정 계약](../lotteworld/docs/configuration.md#방문객-선호와-반복-이용) · [검증 기록](verification/magic-island-visitor-behavior.md)

- [x] **8. 연속 시연 화면과 운영 지표 연결** — 3D 지도의 보행·대기열·차량 상태와 운영자 탭의 시설·방문객 집계를 같은 실행에 연결했다. 두 웹에서 같은 QR 캐릭터와 실시간 추천 경로를 표시한다. [화면 연동 검증](verification/magic-island-continuous-demo-ui.md) · [최신 QR 검증](verification/qr-user-entry-and-preferences.md)

- [ ] **9. 장시간 연속 실행과 성능 검증** — 실제 시간으로 2시간 이상 실행하며, 여러 휴대폰의 세션 분리와 QR 이용 진행, 화면 간 상태 일치, 인원·차량 보존, 응답 시간·메모리·지도 표시 성능을 확인하고 결과를 기록한다. 시연 후보 1,300명과 현 기본값 1,500명은 동일 시드·배속에서 시설별 대기열·예상 대기·응답 시간과 함께 비교한다. 기본 인원 변경은 비교 후 결정한다.

## 배포와 실기기 확인

- [ ] **시연 서버 배포** — AWS 권한과 배포 환경을 확인하고 하나의 서버에서 세 화면과 공통 API에 HTTPS로 접속할 수 있는지 검증한다.
- [ ] **실제 휴대폰 QR 접속** — 배포 URL의 QR을 스캔해 진입하고, 순위 저장·추천 수락·캐릭터 지도 조작·재접속을 확인한다. 다중 휴대폰과 장시간 검증은 9번에서 진행한다.

각 항목은 해당 기능의 완료 기준을 확인한 뒤에만 체크한다. 기능을 마치고 새 채팅으로 인계할 때는 프로젝트의 인계 절차를 따른다.

최종 소프트웨어의 현장 영상 수신, 인원·밀집도 분석과 추천 효과 평가는 [전체 계획](software-plan.md)의 후속 연동 단계에서 진행한다.
