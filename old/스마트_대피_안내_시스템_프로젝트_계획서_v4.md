# 혼잡도를 반영하는 분산형 스마트 대피 안내 시스템 계획서 v4

작성일: 2026년 10월 6일  
문서 버전: 4.0 · 표지판 없는 대피 → 실제 ESP32 연동 → 중앙 통신 단절 시 ESP-NOW 시연  
과목명: 컴퓨터공학 종합설계  
팀명 / 팀원 / 지도교수 / 제출일: 제출 시 기입

**스마트 표지판 없는 재난 대피 시뮬레이션과 실제 ESP32 표지판을 연동한 대피 시뮬레이션을 비교하고, 마지막에는 중앙 통신이 끊겨도 ESP-NOW로 표지판끼리 새 위험을 공유하는 교육용 스마트 대피 안내 시스템**을 개발한다. 청중이 먼저 상황에 대응하는 안내의 필요성을 느끼고, 실제 하드웨어의 역할과 공유기·인터넷 연결에 의존하지 않는 분산 통신을 차례로 확인하도록 구성한다.

v4는 v3의 장치 구성·위험 우선·분산 계산 원칙을 유지하면서 발표를 **표지판 없는 기준 대피 → 실제 ESP32 표지판과 연결한 대피 → 중앙 통신 단절 후 ESP-NOW 자율 대응**의 3단계로 개정했다. 본문은 실행 계획이고, 별첨 A·B·C는 과제 계획서·요구사항명세서·상세설계서다. 실제 건물의 대피 안전성이나 대피 시간 개선을 입증하는 계획은 아니다.

## 0 v4의 주요 수정과 문서 이용 방법

| 항목 | v3 | v4 |

본 계획에서 **대피 시뮬레이션은 가상 인원의 이동과 재난 조건을 보여주는 단순 2D 모델**을 뜻한다. P1에는 안내 없는 기준 대피와 실제 표지판 안내를 따르는 최소 이동 모델을 포함한다. 기존 고정 인원 분포는 경로 규칙의 단위 시험과 네 장면 교차 검증에 계속 사용한다. 정교한 군중 행동·다양한 이동 정책·가상 대피 시간의 통계 비교는 P2 선택 확장이다.

이번 개정은 시연 계획과 그에 필요한 연동·검증 요구사항의 수정이다. 시뮬레이터·펌웨어·실물 시험을 완료했다는 뜻은 아니다. v2의 `스마트_대피_안내_시스템_Mockup_v2.html`은 이번 입력에 포함되지 않은 기존 검토용 자료이며, 정식 산출물은 C7과 T15–T19로 별도 확인한다.

## 1 과제 목표와 범위

### 1.1 문제 정의

고정된 안내 방향은 복도 차단이나 특정 출구 주변의 인원 집중을 반영하기 어렵다. 본 과제는 사전에 등록한 복도 구조와 위험·혼잡 상태를 결합하여, 갈림길의 공용 표지판이 다음 이동 방향을 갱신하는 과정을 구현한다. 상태 수집, 무선 공유, 장치별 계산, 표시와 검증 기록의 연결이 설계의 중심이다.

검증할 질문은 “새 위험을 받은 표지판이 해당 구간을 제외하는가?”, “같은 위험 조건에서 혼잡 비용의 변화가 합리적인 우회로 선택으로 이어지는가?”, “정보가 끊기면 무엇을 유지하고 무엇을 미확인으로 표시하는가?”다. 실제 사람의 행동·화재 확산·시설 피난 성능은 기본 실험의 측정 대상이 아니다.

### 1.2 필수와 선택 범위

| 단계 | 포함 기능 | 완료 근거 |
|---|---|---|
| P0 핵심 연결 | 표지판 2대의 위험 버튼 직접 공유, 로컬 경로 계산, 실제 방향·X 표시 | 입력과 LED가 함께 보이는 영상, 소스·원천 로그 |
| P1 제출 시제품 | 컴퓨터 독립 시뮬레이터, 표지판 3대·G 1대, 고정 분포 시험과 최소 대피 이동 모델, 밀도·혼잡 비용, 만료·복구, 실제 보고·기록, 3단계 시연·읽기 전용 관찰 연결 | 별첨 B 필수 요구사항과 T01–T19 수용 시험 |
| P2 선택 확장 | 정교한 군중 이동과 정책 효과의 통계 비교, 입력 기록 재생, 실제 위치 측정, 별도 조작기 | P1 완료 뒤 별도 시험 결과 |

P0는 중간 점검용이며 P1 완료와 같지 않다. P1은 SIM_BASELINE 기준 대피, HIL_TEST 실제 표지판 연동, HIL_OFFLINE 중앙 단절 시연을 모두 포함하며, 어느 단계든 빠지면 P1 통과로 판정하지 않는다. P1이 최종 목표다. 실제 자동 위치 측정이 수업 필수 조건이면 1주차에 지도교수와 확인하여 요구사항·일정·예산을 변경한다. 모의 인원 입력을 실제 구역 측정으로 보고하지 않는다.

기본 공간은 갈림길 J·L·R, 출구 EL·ER, 방향이 있는 복도 5개다. 가상 ID 60명을 구역 또는 출발 대기에 배정한다. 임의의 위험·인원 조합에서도 경로 모듈이 계산하며 시연 버튼에 화살표 결과를 하드코딩하지 않는다.

### 1.3 범위 밖과 기대 결과

실제 화재 감지의 신뢰도, 전 건물 통신, 자동 메시 중계, 양방향·다층 동선, 전체 관객 위치, 개인별 경로 배분, 상용 소방 설비 연동, 배터리 백업, AI 군중 인식은 P1에 포함하지 않는다. 한 표지판은 한 시점에 한 방향만 보여주므로 인원을 개인별로 두 경로에 나누는 기능도 없다.

기대 결과는 안내 없는 기준 대피에서 문제를 관찰하고, 같은 재난 조건에서 실제 표지판의 안내를 따르는 대피를 비교하며, 중앙 통신 단절 이후에도 새 위험에 대응하는 분산 장치의 역할을 수치와 영상으로 설명하는 것이다. 대피 시간이 반드시 줄거나 실제 시설의 안전성이 확보되었다고 주장하지 않는다.

## 2 시스템 구조와 대표 동작

### 2.1 전체 구조

```mermaid
flowchart TB
  C[공통 지도·인원·재난 시나리오] --> B[1단계 SIM_BASELINE·표지판 없는 대피]
  C --> H[2단계 HIL_TEST·실물 안내에 따른 대피]
  H -->|가상 인원 조건| A[중앙 집계·기록]
  A <-->|USB| G[ESP32 게이트웨이 G]
  G <-->|혼잡·보고| S[ESP32 표지판 S1·S2·S3]
  R[물리 위험 스위치] --> S
  S --> P[표지판 간 ESP-NOW 직접 공유·각자 경로 계산]
  S -->|실제 REPORT| O[읽기 전용 관찰·시뮬레이션 표시]
  O --> H
  P --> F[3단계 HIL_OFFLINE·G 단절 후 새 위험에 대응]
```

그림 1. 1단계에는 ESP32와 가상 스마트 표지판의 동적 안내를 사용하지 않는다. 2단계에는 각 ESP32가 결정한 현재 안내를 컴퓨터가 읽어 가상 인원 이동에 반영한다. 3단계에는 G 전원을 끄고 중앙 조건 전달을 중단한 상태에서 표지판끼리 직접 위험을 공유한다. G는 방향을 결정하지 않는다. 각 표지판은 G와 별도의 전원을 사용한다.

### 2.1.1 세 단계와 실제 하드웨어 연동

| 구분 | SIM_BASELINE: 안내 없는 기준 대피 | HIL_TEST: 실제 표지판 연동 | HIL_OFFLINE: 중앙 단절 |
|---|---|---|---|
| 실행 | 노트북 로컬 프로그램, ESP32·G 없이 동작 | 로컬 시뮬레이션·중앙 집계·G·표지판 3대 | 로컬 시뮬레이션·표지판 3대, G 전원 OFF |
| 대피 안내 | 사전 지정한 익숙한/가까운 출구 경로, 새 위험·혼잡에 따른 동적 안내 없음 | 각 표지판의 실제 REPORT에 따른 방향 | ESP-NOW로 새 위험을 공유한 각 표지판의 실제 방향 |
| 입력 | 공통 초기 인원·고정 재난 사건 | 같은 초기 조건·사건, 가상 인원과 물리 위험 스위치 | 단절 후 새 물리 위험, 중앙 혼잡 입력은 만료 |
| 화면 | 인원 이동·혼잡·차단 앞 대기, 동적 화살표 없음 | 지도·실제 LED 확대·REPORT·이동 반영 | 중앙 단절·관찰 연결 상태·혼잡 미확인·새 위험 반영 |
| 목적 | 상황에 대응하는 안내의 필요성 | 실제 표지판이 대피 시뮬레이션의 판단에 참여함을 확인 | 공유기·인터넷과 중앙 조건 전달 없이도 위험 공유·판단 지속 |

독립 SIM의 알고리즘 시험 화면은 기존 가상 표지판 계산을 유지하되 1단계 발표 화면에서는 사용하지 않는다. 기준 대피의 인원은 사전 선택한 경로를 따르며 차단 앞에서 정지한다. 실제 표지판 연동 시에는 갈림길의 최신 실제 REPORT를 읽어 다음 방향을 정한다. PC의 예측 화살표를 ESP32에 명령으로 전송하지 않는다.

중앙이 끊긴 뒤에도 화면과 하드웨어를 연결하기 위해 S1의 USB 직렬 출력을 **읽기 전용 관찰 연결**로 사용한다. S2·S3는 자신의 REPORT를 ESP-NOW로 S1에도 전송하고, S1은 자기 보고와 수신 보고를 원천·순번 그대로 PC에 출력한다. 관찰 프로그램은 인원·위험·방향 명령을 보내지 않는다. 이 연결은 발표 화면을 위한 관찰 경로이며 중앙 제어 복구로 사용하지 않는다. 관찰 연결을 제거해도 표지판 간 위험 공유와 LED 판단은 계속되어야 한다.

모드 전환 시 가상 위험·타이머·보고를 실제 장치에 자동 복사하지 않는다. 실제 위험 해제·지도·연결 상태를 확인하고 인원을 같은 초기 조건으로 재설정한 뒤 시나리오를 시작한다. 준비가 확인되지 않으면 ‘실물 시연 준비 중’으로 표시한다. 3단계로의 전환은 2단계의 실제 상태를 유지한 채 중앙 연결만 끊는다.

### 2.2 실험 그래프

```mermaid
flowchart LR
  J[J·S1] -->|e1: 10m / 40㎡| L[L·S2]
  J -->|e2: 12m / 48㎡| R[R·S3]
  L -->|e3: 10m / 20㎡| EL[출구 EL]
  L -->|e5: 12m / 24㎡| R
  R -->|e4: 12m / 24㎡| ER[출구 ER]
```

그림 2. 실제 건물 도면이 아닌 비순환 방향 그래프다. e1·e3·e4에는 각각 S1·S2·S3의 위험 입력을 연결한다. e2·e5는 실험에서 고정 통행 가능으로 설정한 간선이며 센서가 안전을 검증했다는 뜻은 아니다.

S1에서 e1은 왼쪽, e2는 오른쪽이다. S2에서 e3은 왼쪽, e5는 오른쪽이다. S3에서 e4는 오른쪽이다. 모든 장치가 같은 지도 해시와 방향 매핑을 사용한다. 비순환 제한은 장치별 정보·유지 이력이 달라도 경로 순환이 생기지 않게 하는 실험 조건이다. 실제 양방향 공간에는 추가 설계가 필요하다.

### 2.3 대표 조건과 계산 결과

| 조건 | 입력 | 안정화 후 예상 표시 S1 / S2 / S3 |
|---|---|---|
| 정상 | 간선 인원 0, 출발 대기 60, 위험 해제 | 왼쪽 / 왼쪽 / 오른쪽 |
| 왼쪽 혼잡 | 30개 가상 ID를 e3로 배정, 대기 30 | 오른쪽 / 오른쪽 / 오른쪽 |
| 오른쪽 차단 | 혼잡 유지, e4 차단 | 왼쪽 / 왼쪽 / X |
| 양쪽 출구 접근 차단 | e3·e4 차단 | X / X / X |

‘정상’의 인원 0은 빈 복도 조건이지 건물 전체 0명이 아니다. 이 표의 경로 시험은 사람의 이동을 기다리지 않고 고정 배정을 변경한다. 발표의 대피 이동 장면은 6절과 C7의 최소 이동 모델을 사용한다. 각 분포는 총 60개 ID를 유지하며 조건 변경은 로그에 남긴다. 위험 해제와 인원 초기화는 별도 조작이다.

### 2.4 실물 모드의 장애 시 유지 범위

| 장애 | 유지 | 제한 |

### 3.3 역할

A는 배선·전원·ESP32 통신과 표시, B는 경로·집계·서버, C는 SIM 화면·가상 표지판·시험·시연을 담당한다. A와 B가 메시지·상태 규칙을 함께 검토하고, B와 C가 공통 시나리오·독립 기준값·SIM과 실제 보고의 구분을 맞춘다. SIM 개발은 하드웨어 제작과 병행하며, 기존 24–32인시 작업과 v4 최소 이동·관찰 연결의 추가 산정 작업은 B·C에 배정한다. A는 G OFF 상태의 직접 공유와 관찰 제거 시험을 담당한다. 주 1회 2시간 통합 시험은 위 인시에 포함한다. 한 사람이 시험 결과를 작성하면 다른 사람이 영상·로그와 대조한다.

## 4 실행 가능성·예산·범위 조정

### 4.1 실행 가능성 판단

계산량보다 장치 상태와 표시의 일치가 주요 난점이다. 작은 그래프, 동일 보드, 단일 홉, USB 게이트웨이, 고정 인원 조건으로 이를 집중 검증한다. 별도 조작기·앱·측위 장치·배터리 제작을 기본에서 빼면 학생 팀이 통합과 증거 확보까지 접근할 수 있다. 다만 기간·인시·대여 장비가 확보되어야 성립하는 조건부 계획이다.

‘서버가 계산한 화살표를 ESP32에 보내는 방식’으로 바꾸면 기본 통신 시연은 쉬워지지만 본 과제의 분산 계산 목표가 달라진다. 일정 부족 때도 이를 조용히 대체하지 않고 변경 사유를 기록한다. 표지판 수를 2대로 줄인 경우도 P1 전 항목 완료로 표기하지 않는다.

### 4.3 실제 위치 입력을 추가하는 경우

위치 자동 측정이 반드시 필요하면 Android 한 기종·BLE 비콘 3개·전경 앱으로 구역 수준을 시험한다. 최소 2주·40–70인시와 비콘·공유기 등 별도 예산 5만–12만원을 추가 편성한다. OS 권한·스캔 동작과 구역 보정을 먼저 확인한다.[R2] 이 수치는 확정 견적이나 개발 시간 보장이 아니다.

보정과 별도 세션으로 구역별 20회 정지 판별, 경계 통과 20회를 평가한다. 미판정을 오류로 포함하고 구역별 혼동·전환 지연을 제시한다. 한 대의 결과를 전체 관객 집계로 일반화하지 않는다. 수동 구역 선택은 입력 시험에는 유용하지만 자동 측위로 분류하지 않는다.

정적 3분포는 D0=모든 간선 0명·대기60, DL=e3 30명·대기30, DR=e4 30명·대기30이다. 기대 경로는 모든 단순 경로를 열거한 독립 도구로 생성한다. 상태 유지 이력이 있는 표지판은 당장 최단 경로로 바뀌지 않을 수 있으므로 72벡터 시험과 시간 전이 시험을 분리한다.

지연은 동기화되지 않은 ESP32 시계를 빼지 않고 같은 촬영 프레임의 입력 확인 LED와 출력으로 측정한다. 각 장치 30개의 정렬된 지연 중 29번째 값을 최근접 순위 95백분위로 사용한다. 누락이 하나라도 있으면 지연만으로 통과하지 않으며 누락 시험을 실패로 기록한다. 하드웨어가 없는 SIM·목업에서는 해당 항목을 ‘미실행’으로 유지한다.

위험 지연 시험은 매회 DL 분포에서 세 장치가 모두 오른쪽을 표시하는 것을 확인한 뒤 S3의 물리 스위치로 e4를 차단한다. S1·S2는 왼쪽, S3는 X로 바뀌므로 세 장치의 출력 변화를 관측할 수 있다. 해제 후 다시 안정된 오른쪽 상태를 확인하고 다음 회차를 시작한다.

### 5.2 선택 성능 비교

P2에서 사람 이동을 추가하면 거리 비용과 혼잡 비용만 다르게 하여 비교한다. “시드 10개”라고만 적지 않고, 난수의 용도를 출발 시각·초기 위치로 한정하여 생성 규칙과 시드를 저장한다. 또는 난수 없이 고정된 10개 입력 분포를 공개한다. 조건·출구 처리율·속도·차단 시각은 두 정책에 동일하게 적용한다.

결과는 최대 구역 인원, 평균·최대 대기, 미대피 인원, 방향 변경 수, 가상 완료 시간으로 보고한다. 180초 내 미완료는 남은 인원과 함께 표시하고 완료 실행만 평균내지 않는다. 예상 최단 경로가 아니라 각 노드에서 실제로 채택한 현재 다음 방향을 따라 이동시킨다. 과밀 구역 수치가 초기조건부터 같은 최대치라면 단순 최대값 대신 사건 이후 최대치·초과 구간 시간 등 사전 지정한 지표를 사용한다.

이동 중 차단 구역에 남은 사람은 정지·미완료로 처리하는 단순 모델이므로 실제 화재 행동 모형이 아니다. 혼잡 정책이 손해를 보이는 조건도 함께 보고한다. P2를 생략하더라도 P1의 최소 이동·실물 연동·중앙 단절 시연과 정적 경로·시간 전이·장치 검증은 필수다.

## 6 부스 및 발표 시연 계획

### 6.1 전시 구성과 청중에게 전달할 흐름

```mermaid
flowchart LR
  A[1단계 표지판 없는 재난 대피] --> B[상황에 대응하는 안내의 필요성]
  B --> C[2단계 실제 ESP32 표지판 연동]
  C --> D[실제 안내에 따라 가상 인원의 이동 변화]
  D --> E[3단계 중앙 통신 단절 후 새 위험 발생]
  E --> F[ESP-NOW 직접 공유·각 표지판 재계산]
```

그림 3. **안내 없는 대피에서 문제를 먼저 보여주고, 실제 표지판이 있는 대피로 차이를 확인한 뒤, 중앙 연결이 없어도 새 상황을 반영하는 모습으로 마무리한다.** 첫 단계에는 가상 스마트 표지판이나 동적 우회 화살표를 보여주지 않는다. 실제 표지판은 사전에 준비해 두고 두 번째 단계에서 소개한다.

모니터에는 2D 지도·가상 인원·구역 인원·차단 구간·대기 상태를 표시한다. 2·3단계에는 실물 LED 확대 영상, 실제 보고·수신 경과·변경 이유를 함께 배치한다. 실제 표지판 S1·S2·S3의 라벨과 지도 위치를 일치시키고 약 2m 부스 거리 및 발표 확대 화면에서 읽을 수 있게 한다. 배선은 지지대 뒤로 고정한다.

화면 상단에는 ‘SIM_BASELINE: 스마트 표지판 없는 대피’, ‘HIL_TEST: 실제 ESP32 표지판 연동’, ‘HIL_OFFLINE: 중앙 단절·ESP-NOW 직접 통신’을 문자로 표시한다. 가상 인원이라는 점과 실제 하드웨어 보고라는 점을 함께 밝힌다.

### 6.2 1단계: 스마트 표지판 없는 재난 대피

ESP32·G를 사용하지 않는 컴퓨터 시뮬레이션으로 시작한다. 가상 인원은 사전에 정한 익숙한/가까운 출구 경로로 이동한다. 한쪽 통로에 인원이 집중되는 상황과 이후 해당 출구 접근 통로가 차단되는 재난 사건을 보여준다. 동적 안내가 없으므로 차단을 만난 인원은 정지하고, 우회 가능한 통로가 있어도 자동으로 다른 출구를 안내받지 못한다.

이 단계는 안내 부재의 영향을 설명하는 단순 기준 모델이다. 실제 사람은 스스로 우회할 수 있다는 점을 설명하고, 이 모델의 정지 행동을 실제 재난 행동의 예측으로 제시하지 않는다. 스마트 표지판이 반드시 더 좋은 결과를 내도록 초기 인원이나 출구 처리율을 단계별로 바꾸지 않는다.

발표 멘트: “먼저 상황에 따라 바뀌는 표지판 없이 대피해 보겠습니다. 익숙한 출구 쪽으로 인원이 몰리고 통로가 막혔을 때, 다른 길을 알려주는 안내가 필요합니다.”

### 6.3 2단계: 실제 ESP32 표지판과 대피 시뮬레이션 연동

실물 소개 후 지도·채널·전원·USB·G heartbeat·세 표지판 REPORT를 확인한다. 물리·시험 위험을 명시적으로 해제하고 초기 인원·출구 처리율·이동 속도·재난 사건 시점을 1단계와 동일하게 설정한다. 새 실행 ID의 반영을 확인한 뒤 시작한다. SIM 상태를 실제 장치에 자동 이식하지 않는다.

| 조작 | 실제 하드웨어 동작 | 화면과 가상 인원에서 확인할 내용 |
|---|---|---|
| 동일 초기 조건으로 시작 | 세 ESP32가 자신의 위치에서 경로 계산·화살표 표시 | 실제 REPORT의 방향을 읽고 갈림길에서 다음 경로 선택 |
| 같은 혼잡 상황 입력 | G가 인원 조건 전달, 각 표지판이 혼잡 비용으로 계산 | 조건 충족·5초 유지 뒤 LED 변경, 이후 갈림길에 도착한 인원의 방향 변화 |
| 같은 재난 시점에 위험 스위치 ON | 담당 원천이 위험을 직접 공유, 차단 경로 제외 | 새 실제 보고를 받아 이동 반영, 차단 앞 정지·안내 불가도 표시 |

컴퓨터는 지도와 가상 인원을 제공하고, 실제 표지판이 대피 방향을 결정한다. 화면 예측값을 실물 화살표처럼 표시하거나 PC가 만든 방향을 ESP32로 보내지 않는다. REPORT와 카메라 LED를 함께 대조한다. 최신 보고가 없으면 해당 갈림길의 인원은 대기하며, 마지막 방향을 최신인 것처럼 계속 사용하지 않는다.

고정 분포의 정상→왼쪽 혼잡→오른쪽 차단→양쪽 차단은 별도 규칙 검증·추가 설명에 사용한다. 이동 시연의 인원 분포는 시간에 따라 달라지므로 고정 분포 표의 방향과 무조건 같다고 단정하지 않는다. 비교 화면에는 동일 시점의 혼잡·대기·미대피 인원과 실제 방향 변화 근거를 제시한다.

발표 멘트: “같은 재난 조건에 실제 ESP32 표지판을 연결했습니다. 화면 속 사람이 갈림길에서 따르는 방향은 실제 표지판이 계산한 결과입니다. LED가 바뀌고, 그 안내가 시뮬레이션의 이동에도 반영됩니다.”

### 6.4 3단계: 중앙 통신 단절 후 ESP-NOW로 새 위험 반영

1. 두 번째 단계의 실제 상태를 유지한 채 **G 전원을 끄고 중앙 조건 전달을 중단**한다. 표지판 3대는 독립 전원을 유지한다. 화면에 중앙 단절을 표시하고 5초 혼잡 만료를 확인한다. 명확한 방향 변경을 보여주기 위한 고정 분포 보조 장면은 G를 끄기 전에 e3·e4 위험 해제·거리 기준 S1 왼쪽을 확인해 준비한다.
2. 공유기·인터넷 연결 없이 같은 고정 채널의 등록 피어 통신을 유지한다. ESP32의 Wi-Fi 무선 기능 자체는 켜 둔다. ESP-NOW는 Wi-Fi 무선을 쓰지만 공유기에 접속할 필요가 없는 직접 통신이다.[R1]
3. **단절한 뒤 새 위험을 발생**시킨다. e3 담당 S2의 물리 위험 스위치를 켜서 왼쪽 출구 접근 통로를 차단한다. 단절 전에 받은 결과를 계속 보여주는 것으로 시연을 대신하지 않는다.
4. S2가 RISK_STATE를 S1·S3에 ESP-NOW로 직접 전달하고, 각 표지판이 새 위험을 반영해 계산한다. e1·e4가 통행 가능하고 혼잡이 만료된 보조 장면의 안정화 후 S1은 오른쪽, S2는 오른쪽, S3는 오른쪽을 표시한다. 핵심은 단절 이후의 새 사건으로 S1이 왼쪽에서 오른쪽으로 바뀌는 것이다.
5. 읽기 전용 관찰 USB로 실제 REPORT를 받아 화면과 가상 인원의 다음 이동에 반영한다. 화면에는 ‘중앙 단절 / 관찰 USB 연결 / 혼잡 미확인’을 각각 표시한다. 관찰 연결도 제거하면 화면 갱신은 멈추지만 표지판끼리의 위험 공유·계산·LED는 계속 동작해야 한다. 별도 수용 시험과 영상으로 이를 확인한다.

이 단계에서 실시간으로 갱신하는 것은 **표지판의 물리 입력으로 들어온 위험 상태**다. 중앙에서 생성하던 인원·혼잡 정보는 5초 후 만료되어 거리 기준으로 전환하며 품질 저하를 표시한다. 중앙이 끊겼는데도 새 인원 조건이 전달되는 것처럼 설명하지 않는다. 관찰 화면의 위험 표시는 최신 원천 메시지에 근거하며 예측으로 실제 상태를 덮어쓰지 않는다.

발표 멘트: “이제 중앙 연결을 끊고 새 위험을 발생시키겠습니다. 표지판끼리 ESP-NOW로 위험을 공유하고 각자 안내 방향을 바꿉니다. 공유기나 인터넷 연결이 없어도 표지판 간 소통은 이어집니다.”

7분 발표는 문제 45초, 구조 1분15초, 3단계 시연 3분, 검증 1분15초, 한계와 활용 45초로 구성한다. 60초만 가능한 경우 기준 대피 10초·실물 연동 20초·중앙 단절과 새 위험 25초·메시지 5초로 압축하고 준비는 사전에 완료한다. 단절 후 상태 반영이 늦어지면 실제 수신을 기다리거나 해당 단계의 실물 녹화를 사용한다.

종료 후 G 복구→물리 스위치 해제→시험 위험 해제 확인→표지판 현재 상태·지도 확인→인원 초기화→새 실행 보고 확인 순서로 복구한다. 두 명이면 화면·설명과 실물 스위치·연결 감시를 분담한다. 실제 화재·연기나 암실은 만들지 않는다.

### 6.6 실패 대응과 당일 점검

발표 30분 전 세 단계를 한 번 실행한다. 기준 대피의 독립 실행, 실물 REPORT로 이동이 바뀌는지, G OFF 후 새 위험이 공유되는지, 관찰 USB가 제어 입력을 보내지 않는지 확인한다. 지도 해시·채널·포트·독립 전원·스위치·LED 가독성·케이블 고정과 절전·팝업을 점검한다.

세 단계의 예비 영상을 각각 녹화하고 모드·촬영 사실을 표시한다. 실물 영상에는 G OFF·단절 후 스위치 입력·LED 변화를 함께 담고 원래 지연을 보존한다. 라이브가 10초 이상 반응하지 않으면 한 번 확인하고 해당 단계의 녹화로 전환한다. 목업 녹화를 실제 하드웨어 증거로 사용하지 않는다. 로컬과 USB에 파일·영상·설정을 준비한다.

# 별첨 A 과제 계획서

과제명: 혼잡도를 반영하는 분산형 스마트 대피 안내 시스템  
버전: 4.0  
과목명: 컴퓨터공학 종합설계  
팀명 / 팀원 / 지도교수 / 제출일: 제출 시 기입

## A1 과제 목적 및 필요성

실내 대피 안내는 통로 차단과 특정 구역의 인원 집중 등 변화하는 조건을 반영할 필요가 있다. 본 과제는 영화관을 단순화한 실험 그래프에서 위험 경로를 제외하고 혼잡 비용을 고려하여 안내 방향을 갱신하는 시스템을 설계·구현한다.

ESP32 표지판들이 상황을 공유하고 각자 자신의 위치에서 경로를 계산하게 하여, 임베디드 입력·무선 통신·그래프 알고리즘·상태 관리·웹 시각화를 통합한다. 경로가 없거나 필요한 정보가 만료된 경우도 별도의 상태로 표현한다.

기본 범위는 안내 없는 기준 대피, 최소 이동 모델과 실제 표지판 3대의 연동, 중앙 단절 후 ESP-NOW 직접 위험 공유 시연이다. 고정 인원 분포는 경로 검증에 사용한다. 발표는 기준 대피→실물 연동→중앙 단절의 순서로 진행한다. 실제 화재 감지·관객 측위·건물 전체 피난 안전성은 검증하지 않는다. 결과물은 분산 안내 규칙과 장애 대응을 비교하는 교육용 시제품이다.

## A2 사용기술 및 설계

### A2.1 기술과 구조

| 기술 | 용도 |
|---|---|
| ESP32·C/C++·ESP-NOW | 위험 스위치 수집, 단일 홉 공유, 각 표지판 경로 계산 |
| 방향 그래프·Dijkstra | 위험·미확인 간선 제거 후 거리·혼잡 비용 비교 |
| Python·FastAPI·pyserial·SQLite | 가상 ID 집계, USB 게이트웨이 연결, 기록·API |
| HTML·CSS·JavaScript·SVG | 독립 2D 시뮬레이션, 가상 표지판, 상황 조작, 실제 보고, 모드별 시연 화면 |
| RGB LED·레벨 변환·별도 5V 전원 | 화살표·X·? 및 품질 저하 표시 |

```mermaid
flowchart LR
  A[공통 초기 인원·재난 조건] --> B[표지판 없는 기준 대피]
  B --> C[실제 ESP32 안내를 반영한 대피]
  C --> D[중앙 단절 후 ESP-NOW 직접 공유]
```

그림 A1. 안내의 필요성을 먼저 보여주고, 실제 하드웨어의 역할과 중앙 단절 시의 자율 대응으로 이어진다. 실제 모드의 방향은 각 ESP32가 결정하며 PC는 실제 보고를 읽어 가상 이동에 반영한다. 관찰 연결은 제어 입력을 보내지 않는다. 위험 메시지는 인원 실행 ID와 분리한다.

### A2.2 설계 내용

갈림길 3개·출구 2개·복도 5개를 등록한다. 구역별 가상 ID 수를 면적으로 나눠 밀도를 계산하고, 위험·미확인 간선을 제외한 경로에 거리와 혼잡 비용을 적용한다. 혼잡에 의한 방향 변경에는 15% 비용 개선과 5초 지속·최소 유지 조건을 적용한다. 새 위험으로 현재 경로가 무효가 되면 대기 없이 재계산한다.

표지판 3대가 각각 위험 원천 역할도 수행하고 G 1대가 USB와 무선 사이를 연결한다. 위험 정상 보고는 3초, 혼잡은 5초 만료 기준을 둔다. 위험은 자동 해제하지 않으며, 혼잡이 만료되면 거리 기준과 품질 저하를 표시한다. 웹 예측과 실제 장치 보고는 구분한다.

### A2.3 수행 계획과 가능성

3인·8주·기존 230–320인시를 기준으로 하되 v4 최소 이동·관찰 연결·추가 시험의 작업량을 재산정한다. 1–2주차 두 장치 위험 직접 공유와 SIM 기본 계산, 3–4주차 SIM 네 장면·세 장치·모드 전환 통합, 5–6주차 양쪽 비교·검증·결함 수정, 7–8주차 전시·문서·리허설을 수행한다. 노트북·모니터 대여 전제의 배정 예산은 361,000원이다. 최소 대피 이동·실물 안내 반영·중앙 단절은 필수이며, 자동 위치 측정과 정교한 군중 모델은 별도 확장으로 둔다.

72개 정적 경로 벡터, 위험 수신·처리 이후 차단 경로 선택 0건, 실제 LED 반영 지연 장치별 95백분위 1.5초 이하를 목표로 한다. 누락·만료·초기화·복구·30분 연속 동작도 검증한다. 목표 성능은 구현 후 측정한다.

## A3 기대효과 및 활용방안

위험 우선과 혼잡 회피의 관계를 상황 조작으로 설명하고, 분산 장치의 정보 갱신과 실패 대응을 실습할 수 있다. 경로 알고리즘과 실제 출력 사이의 지연·누락을 기록하여 소프트웨어와 하드웨어 통합 검증 경험을 얻을 수 있다.

부스와 발표는 표지판 없는 대피→실제 ESP32 연동→중앙 단절 후 ESP-NOW의 3단계, 3분 시연을 기본으로 한다. 발표 시간에 따라 90초로 축약하며 각 단계의 예비 녹화를 구분하여 준비한다. 후속 과제로 실제 구역 측정·이동 모델·양방향 공간을 검토할 수 있다. 실제 대피 시간 단축이나 현장 안전성 향상은 본 실험만으로 입증된 효과로 제시하지 않는다.

## B2 시스템 기능

지도·방향 매핑 검증, 위험 스위치와 TEST 요청, ID 중복 제거와 밀도 계산, ESP-NOW 상황 공유, 원천별 최신성 관리, 로컬 경로 계산, 방향 안정화, 화살표·X·? 표시, 웹 실제 보고, 인원 초기화, 기록 내보내기를 제공한다.

발표 흐름은 안내 없는 기준 대피→준비 확인→동일 조건의 실물 연동→중앙 단절 후 새 위험 공유다. 별도 알고리즘 교차 검증에는 SIM과 HIL_TEST의 동일 네 장면을 사용한다. 알고리즘 교차 검증의 대표 흐름은 준비 → 정상 → 왼쪽 혼잡 → 오른쪽 차단 → 양쪽 차단 → 명시적 위험 해제 → 인원 초기화다. 위험 ON 상태에서 인원 초기화를 실행해도 해당 차단은 남아야 한다.

## C1 서론(개요)

본 문서는 노트북 단독 기준 대피와 알고리즘 SIM, G 1대·표지판 3대의 실물 연동, G OFF 이후 읽기 전용 관찰과 ESP-NOW 직접 통신으로 구성되는 P1 구현 계약을 정의한다. 표지판은 위험 입력 원천과 경로 계산 장치 역할을 함께 수행한다. 서버는 가상 ID 집계·시험 요청·기록을 맡고, G는 USB/ESP-NOW 변환만 수행한다.

v2의 위험/인원 영역 분리를 유지하고, v3에서 SIM 상태와 실제 장치 상태를 추가로 분리한다. 표시 상태는 장치의 현재 입력을 근거로 하며 전체 시설에 대한 안전 판단을 뜻하지 않는다. 동일 지도·설정의 작은 비순환 공간을 전제로 한다.

| e4 | R→ER | 12 | 24 | S3 |
| e5 | L→R | 12 | 24 | STATIC_TEST_CLEAR |

지도 JSON에는 노드·출구·간선·면적·위험 원천·표지판 방향 매핑을 저장한다. 정규화한 파일의 해시를 장치와 서버에 함께 배포한다. STATIC_TEST_CLEAR는 실험 가정이다. J→L→R→출구의 단방향 순서를 검증하고 순환 입력을 거부한다.

### C3.2 ID 집계

입력은 `run_id, person_id, person_seq, zone_id`다. zone_id는 e1–e5, WAIT_J/WAIT_L/WAIT_R, EVACUATED_EL/ER, UNKNOWN 중 하나다. WAIT는 노드의 대기 인원, EVACUATED는 출구 도착 인원이며 둘 다 복도 밀도에서 제외한다. 60개의 가상 ID를 한 구역에만 배정한다. 최신 순번만 수용하고 구역 변경은 이전 제거와 새 추가를 원자적으로 처리한다. 분포 프리셋도 60개 ID를 생성한 뒤 같은 집계 경로를 거친다.

수신이 5초 이상 없는 ID는 UNKNOWN으로 이동하고 마지막 구역에 미확인 수를 표시한다. UNKNOWN이 있으면 혼잡 스냅샷의 품질을 PARTIAL로 둔다. 표시하는 숫자는 “확인된 인원”과 “미확인”을 나누고 마지막 구역을 0명이라고 확정하지 않는다. 고정 분포 시험과 이동 시연 모두 1초마다 새 순번으로 ID별 현재 구역을 보고한다. 이동 시연은 가상 인원의 현재 구역을 집계하며 G OFF 뒤에는 중앙 혼잡 전달을 중단한다.

완성 스냅샷은 모든 구역의 counts·품질을 담고 1초마다 새 crowd_version으로 발행한다. 소스가 멈추면 G가 과거 값을 새 버전으로 다시 발행하지 않는다. 어느 구역이든 PARTIAL/STALE이면 계산 전체의 혼잡 항을 끄고 품질 저하를 표시한다. 여러 구역의 오래된 값과 최신 값을 임의로 섞지 않는다.

### C3.3 경로 비용

```text
rho[e] = confirmed_count[e] / area[e]
q[e] = min(rho[e] / 1.0, 3)
cost[e] = length[e] * (1 + alpha * q[e])
alpha = 2       # 유효한 혼잡 반영
alpha = 0       # 거리 비교 또는 혼잡 미확인
BLOCKED / UNKNOWN 간선은 비용과 무관하게 제거
```

비용은 단위 없는 비교 점수로 정의한다. 밀도 기준 1명/㎡는 정규화 값이며 위험 밀도 기준이 아니다. 소수 계산 후 정수 밀리단위로 반올림한다. 동률은 출구 ID, 간선 ID 사전순으로 결정한다.

D0에서 J→L→EL=20, J→R→ER=24다. e3 30명·20㎡이면 e3 비용40, 왼쪽 직행50, 오른쪽24가 된다. e4 차단 시 오른쪽 후보를 제거하고 왼쪽으로 안내한다. e3도 차단되면 출구 경로가 없다.

## C4 경로·표시 상태

### C4.1 계산과 유지

각 표지판은 동일한 지도·로컬 상태를 사용하여 출구까지 Dijkstra를 수행한다. 현재 저장된 전체 경로를 새 입력으로 다시 검증하고, 그중 어느 간선이든 차단·미확인이면 후보 유지 시간과 무관하게 즉시 무효화한다.

혼잡 변화만 있을 때 후보 비용이 현재 전체 경로 비용의 85% 이하이고, 같은 다음 간선 후보가 5초 지속되며, 마지막 방향 변경 뒤 5초가 지났을 때 변경한다. 후보가 달라지거나 개선 조건이 깨지면 후보 타이머를 초기화한다. 같은 다음 간선이면 출력은 유지하면서 저장 경로·비용 근거를 갱신한다.

유효한 기존 경로가 없는 경우에는 즉시 유효 대안을 표시한다. 혼잡 만료 시 즉시 거리 기준으로 계산하고, 혼잡 복구 뒤에는 5초 규칙을 다시 적용한다. 차단 해제 후 기존 안내가 유효하면 더 좋은 대안에 5초 규칙을 적용한다. 모든 타이머는 단조 증가 시각을 사용한다.

각 표지판이 현재 유지 중인 다음 방향은 한 개의 일관된 전역 최적 경로와 다를 수 있다. 웹에서는 “계산상 후보 경로”와 “지점별 현재 안내”를 별도로 표시한다. P1 실물 연동 이동 모델은 지점별 최신 실제 REPORT의 현재 방향을 따른다. 기본 비순환 그래프에서는 다른 유지 이력으로도 순환은 없지만 최적 비용은 보장하지 않는다.

### C4.2 표시와 장애

| 상태 | 조건 | 출력 |
|---|---|---|
| SYNC | 부팅 초기 확인·지도 오류 | 노랑 ?·상태 확인 중 |
| GUIDE | 유효 경로와 혼잡 | 초록 방향 |
| DEGRADED | 유효 위험 경로는 있으나 혼잡 만료/부분 관측 | 초록 방향+노랑 모서리 점 |
| NO_ROUTE | 미확인 간선을 허용해도 차단 때문에 경로 없음 | 빨강 X |
| UNKNOWN | 현재 경로 없고 미확인 간선을 허용하면 경로 존재 | 노랑 ? |
| OFFLINE | 상위 링크가 정상인데 G가 특정 표지판 보고를 3초 받지 못함 | 웹 상태. 전원 단절 확정이 아니라 보고 미수신 |

위험 미확인 간선을 쓰지 않는 유효 대안이 있으면 그 대안을 안내한다. UNKNOWN을 임시 허용한 그래프는 X/? 원인 분류에만 사용하고 안내에는 쓰지 않는다. 이미 알려진 BLOCKED는 원천이 끊겨도 유지한다.

부팅 초기 동기화는 3초를 상한으로 수행한다. 지도·자기 위치가 유효하면 미응답 원천은 UNKNOWN 간선으로 두고 C4의 경로 규칙을 적용한다. 한 원천의 미응답만으로 모든 출력을 무기한 SYNC에 묶지 않는다. G·중앙 USB가 끊기면 G 경유 보고에는 ‘중앙 연결 단절·마지막 보고’를 표시하며 개별 표지판 전원 OFF로 단정하지 않는다. 별도 관찰 USB의 새 보고는 수신 경로와 시각을 표시한다. 관찰도 끊기면 실제 상태 갱신을 멈추고 해당 지점의 연동 이동을 대기시킨다.

```mermaid
flowchart LR
  A[SYNC] -->|현재 원천 확인| B[GUIDE]
  B -->|혼잡 만료| C[DEGRADED]
  C -->|혼잡 복구·안정화| B
  B -->|모든 유효 경로 차단| D[NO_ROUTE · X]
  B -->|필요 위험 미확인| E[UNKNOWN · ?]
  D -->|해제 확인| B
  E -->|현재 상태 확인| B
```

그림 C1. 대표 전이도다. 모든 상태에서 지도 오류·재부팅은 SYNC로 이동한다. DEGRADED에서도 위험 변화에 따라 X/?로 바뀔 수 있다. 인원 초기화는 위험 상태 자체를 SYNC나 CLEAR로 변경하지 않는다.

## C5 메시지·최신성·복구

### C5.1 통신 계약

등록 피어 S1·S2·S3·G는 같은 고정 채널에서 개별 유니캐스트로 통신한다. 설치별 PMK/LMK와 source_id↔MAC 매핑을 설정한다. 위험 원천은 다른 표지판과 G에 직접 발행한다. G는 모든 표지판에 혼잡을 전달하고 표시 보고를 수집한다. S2·S3는 REPORT를 관찰 담당 S1에도 보내고, S1은 자기 보고·수신한 REPORT·RISK_STATE를 원천·세대·순번을 보존해 USB로 출력한다. S1의 관찰 출력은 로컬 읽기 전용 표시 프로그램으로 연결하며 CROWD·TEST_SET·방향 명령의 입력은 허용하지 않는다. G와 S1의 USB는 별도 포트로 구분한다. S1은 다른 표지판의 위험이나 방향을 대신 결정하지 않으며 자동 무선 중계는 없다.[R1]

공통 헤더는 protocol_version·type·installation_id·map_hash·source_id·boot_epoch·seq·payload_length다. 인원 메시지만 run_id·crowd_version을 추가한다. 위험 메시지에 인원 run_id 조건을 걸지 않는다. 길이 상한 200바이트, 정수 폭·바이트 순서·단위를 고정하고 C 구조체 메모리를 그대로 보내지 않는다.

| 메시지 | 송수신 | 내용 |
|---|---|---|
| HELLO / SYNC_REQUEST / SYNC_REPLY | 장치↔원천 | 부팅 세대·challenge·현재 전체 상태 |
| RISK_STATE | S1/S2/S3→나머지 표지판·G | 담당 간선 physical/test/effective, 원천 순번 |
| TEST_SET | G→담당 원천 | 요청 ID·시험 latch ON/OFF. 직접 위험 상태를 사칭하지 않음 |
| CROWD | G→표지판 | 인원 run_id·version·counts·품질 |
| ACK | 수신자→발행자 | 메시지 키와 수용/중복/거부 |
| REPORT | 표지판→G, S2·S3→관찰 담당 S1 | 다음 간선·표시·위험 벡터·인원 버전·이유·업타임. S1은 자기 보고와 수신 보고를 관찰 USB로 출력 |

위험 변경은 즉시 발행하고 미확인 장치에 150/400/800ms 시점으로 재전송한다. 위험 전체 상태는 1초마다 새 seq로 보고한다. 콜백에서는 길이 검사·큐 적재만 수행하고 계산·LED·저장은 별도 태스크에서 처리한다. 송신 콜백 성공, 응용 ACK, REPORT를 별개로 기록한다.[R1]

REPORT는 표시·사용 상태가 바뀌면 즉시, 변화가 없어도 1초마다 전송한다. G는 자신의 heartbeat와 각 표지판의 마지막 보고 경과를 1초마다 USB로 전달한다. 서버는 G heartbeat 3초 만료와 개별 표지판 보고 3초 만료를 구별한다.

### C5.2 상태 최신성

전송 중복 키는 원천·boot_epoch·메시지 종류·seq이며 종류별 순번을 별도로 증가시킨다. 위험 최신성에는 RISK_STATE의 risk_seq만 사용한다. REPORT나 ACK 수신이 위험 최신성 타이머를 연장하지 않는다. 같은/작은 위험 순번은 상태를 바꾸지 않는다. CLEAR는 마지막 새 위험 보고부터 3초가 지나면 UNKNOWN, BLOCKED는 명시적 새 해제 전까지 유지한다. 혼잡은 마지막 새 crowd_version부터 5초면 만료다. 100ms 주기로 만료를 검사한다.

새 부팅 세대를 발견하면 해당 원천을 동기화 대상으로 표시하고, 기존 차단은 유지하며 정상으로의 복귀는 challenge가 일치하는 현재 전체 응답 뒤에만 허용한다. 본인 재부팅 시에도 원천별 현재 응답을 받는다. boot_epoch는 영속 부팅 카운터로 사용하며 초기화한 교체 보드는 재등록한다. 지도 불일치 메시지는 적용하지 않는다.

### C5.3 물리 위험과 시험 위험

원천만 `effective_blocked = physical_blocked OR test_latch`를 계산·발행한다. TEST_SET OFF는 물리 스위치 ON을 해제할 수 없다. 담당 원천이 꺼져 있으면 서버는 해제 성공을 표시하지 않는다. 시험 차단은 통신 단절이나 인원 초기화로 만료 해제하지 않는다.

원천이 물리 스위치를 해제했어도 시험 latch가 남으면 차단을 유지한다. 화면에 물리·시험 두 원인을 표시하여 해제되지 않는 이유를 설명한다. 부스 운영자는 스위치 해제→시험 위험 해제 확인→장치 복구 확인→인원 초기화 순서로 다음 관람객을 준비한다.

## C6 초기화·서버·데이터

### C6.1 인원 초기화

분산 위험을 바꾸는 2단계 커밋을 구현하지 않는다. 서버는 새 run_id를 만들고 60개 ID를 WAIT_J로 배정한 완성 CROWD를 전송한다. 표지판은 해당 G의 현재 세대를 확인한 연결에서 새 실행을 수용하고 인원 후보 유지 이력을 비운다. 위험·물리 스위치·단절 상태는 유지한다.

인원 ID의 유일한 발급자는 서버다. SQLite에 보존한 `server_epoch`를 서버 시작 때 트랜잭션으로 1 증가시키고, 그 세대 안에서 `run_counter`를 증가시켜 run_id=(server_epoch, run_counter)로 만든다. crowd_version은 실행 안에서 증가한다. G는 이 값을 그대로 전달하며 새 순번을 붙여 과거 인원을 살리지 않는다.

G·서버 재연결 때 표지판은 G를 경유해 현재 서버의 challenge 응답과 전체 인원을 확인한다. 새로운 server_epoch는 해당 동기화 후에만 수용한다. 같은 서버 세대의 초기화 요청 재시도는 요청 ID별 기존 run_id를 재사용한다. 서버가 재시작했으면 새 epoch의 새 실행을 만들고 이전 실행을 재개한 것처럼 표시하지 않는다. DB 손상·삭제로 epoch를 보존할 수 없으면 0부터 자동 시작하지 않고 통제된 설치 ID 재등록·복구를 요구한다.

REPORT에 새 run_id가 없는 표지판은 ‘인원 적용 미확인’으로 표시한다. 3초 응답 제한을 넘으면 시연 시작을 보류하지만 장치의 위험 대응은 계속된다. 모든 표지판이 동시에 바뀌었다고 가정하지 않는다. G가 끊겨 있으면 실제 장치의 인원 초기화는 완료될 수 없다.

### C6.2 API·USB

USB는 115200bps 줄 단위 JSON, 최대 1,024바이트다. 무선 바이너리와 USB JSON은 G에서 변환한다. 서버는 localhost 바인딩과 실행 토큰·Origin 확인을 사용하며 포트·프레임 오류를 기록한다.

| API | 기능·검증 |
|---|---|
| GET /api/state | 예측·실제 보고·입력 품질·수신 경과 조회 |
| POST /api/crowd | 허용 구역·총 ID 수·범위 검증 후 분포 변경 |
| POST /api/run/reset | 같은 요청 ID 재시도, 위험 상태 유지 |
| POST /api/test/risk | TEST 모드에서 담당 원천에 latch 요청·원천 응답 확인 |
| GET /api/export | 실행·위험·보고·오류 CSV/JSON |
| WS /ws/state | 최초 전체 상태와 이후 증가하는 서버 이벤트 번호 |

| snapshots | run_id·crowd_version·counts·품질 |
| reports | 모드·원천 유형·장치·위험 벡터·인원 버전·현재 다음 간선·표시·이유·수신 시각 |
| tests | 시험 ID·입력·기대/실제·지연·누락·결함·증거 |

위험 이벤트는 특정 인원 run_id가 없어도 저장한다. 시험 분석 때 관찰 시각으로 연결하되 위험을 실행 종료와 함께 삭제하지 않는다. 로그 쓰기 실패는 별도 경고하며 장치 계산을 중단시키지 않는다. 기록 성공을 확인하지 못한 자료는 저장 완료로 표시하지 않는다.

## C7 화면·시뮬레이터·시험 추적

### C7.1 화면과 실행 모드

SIM과 HIL_TEST는 지도·장치 라벨·상태 색상·문자 기호를 공유한다. 화면 상단에는 모드와 계산 주체를 크게 표시하고, 중앙에는 2D 지도·구역 인원·차단 간선·출구를 배치한다. 옆에는 S1·S2·S3의 현재 방향과 X/?를, 아래에는 경로 비용·후보 유지 남은 시간·변경 이유·입력 이력을 표시한다. 계산상 후보 경로와 각 지점의 현재 안내는 구분한다.

| 모드 | 계산·표시 데이터 | 실행·기록 구분 |
|---|---|---|
| SIM_BASELINE | 사전 경로를 따르는 가상 인원·동적 안내 없음 | 로컬 독립 실행·초기 조건·사건·모델 설정 기록 |
| SIM | 알고리즘 시험용 가상 상태·가상 표지판 | 1단계 발표 화면과 분리·sim_session_id 기록 |
| HIL_TEST | ESP32 REPORT로 가상 인원 이동 결정, 별도 예측은 구분 | 서버·G·실물·관찰 USB 연결, 실제 수신 시각·run_id 표시 |
| HIL_OFFLINE | G OFF 후 ESP-NOW 위험 공유·관찰 USB의 실제 보고 | 중앙 단절·혼잡 만료·관찰 연결 상태를 각각 표시 |
| MOCKUP | 기존 UI·규칙 검토용 자료 | v4 산출물 검증 완료와 구분 |
| REPLAY | 저장 입력 재생 | P2 선택, 원본 모드·기록 시각 표시 |

HIL_TEST/HIL_OFFLINE에서 장치 원천·G·관찰 연결의 상태를 별도로 표시한다. 각 보고에는 G 경유/관찰 USB 원천과 수신 경과를 표시하고, 해당 경로가 끊기면 마지막 보고로 표시한다. 새 브라우저 예측값으로 실제 보고를 덮어쓰지 않는다. 모드가 바뀌어도 실물 스위치·위험 latch·위험 사건 로그는 지우지 않는다.

### C7.2 컴퓨터 시뮬레이터의 필수 구현

1. **독립 실행:** HTML·CSS·JavaScript·SVG 및 필요한 설정을 로컬 자원으로 제공한다. 외부 CDN·서버·USB·ESP32 없이 시작할 수 있게 한다. 파일 열기 환경에서 원격 자원이나 제한되는 로컬 fetch에 의존하지 않도록 지도·설정을 포함한다.
2. **조건 입력:** 정상·왼쪽 혼잡·오른쪽 차단·양쪽 차단 프리셋과 임의 유효 인원 분포·개별 위험 토글을 제공한다. 고정 시험은 e1–e5와 WAIT_J에 총60을 보존한다. 이동 시연은 WAIT_L/WAIT_R와 EVACUATED_EL/ER도 허용하고, 대기·도착 인원은 복도 밀도에 넣지 않는다. 잘못된 값은 거부한다. 프리셋은 실제 계산 입력이며 화살표 결과를 저장해 출력하지 않는다.
3. **가상 표지판:** S1·S2·S3별 StateStore·RouteEngine·DirectionPolicy 인스턴스를 두고 C3·C4의 비용·차단·타이머·X/? 규칙을 적용한다. SIM 화면의 위험 입력은 가상 원천에만 적용한다. 각 원천은 정상 실행에서 1초마다 새 상태를 전달하는 논리 모델을 사용한다.
4. **시간·단절:** 단조 증가 시각으로 5초 후보 유지·5초 최소 유지, CLEAR 3초·혼잡 5초 만료를 모사한다. 가상 G 또는 원천 단절은 해당 새 상태 전달을 중단하는 방식으로 재현한다. 실제 RF·전기·전송 지연을 시뮬레이션한 것으로 주장하지 않는다.
5. **초기화·설명:** SIM 인원 초기화도 가상 위험·단절을 유지한다. 위험 해제와 연결 복구는 별도 조작이며 변경 이유를 기록한다. 이 조작은 실물 서버 API나 TEST_SET을 호출하지 않는다.
6. **공통 조건과 비교:** 지도·방향·계수·프리셋 정의를 단일 원본 설정으로 관리하고 빌드 때 SIM과 펌웨어/서버에 배포한다. 버전·해시·scenario_id와 입력 순서를 기록한다. JavaScript와 C++ 구현의 결과는 독립 경로 열거 기준으로 각각 검증한다.
7. **기록:** SIM 결과는 모드·sim_session_id·scenario_id·지도 해시·설정·입력·논리 경과 시간·가상 방향·변경 이유를 CSV/JSON으로 내보낸다. 실제 REPORT와 별도 파일/저장 영역을 사용하며 비교표에서만 대응시킨다.

P1은 고정 분포의 알고리즘 시험과 다음 최소 대피 이동 모델을 모두 포함한다.

1. 60개 가상 ID의 초기 위치·출발 시각·사전 경로, 이동 속도·간선 길이·출구 처리율, 재난 사건의 논리 시각을 공통 설정에 저장한다. 기본 시연은 난수 없는 고정 조건을 사용한다.
2. SIM_BASELINE은 사전 경로를 유지하며 차단 앞에서 정지한다. HIL_TEST/HIL_OFFLINE은 갈림길에 도착할 때 해당 표지판의 최신 실제 REPORT로 다음 간선을 선택한다. 간선 이동 중인 인원은 즉시 반대편 경로로 옮기지 않는다.
3. 출구·간선 진입 대기는 공통 FIFO 규칙으로 처리하고, 이동 중 차단된 인원은 해당 위치에서 정지·미대피로 남긴다. 속도·처리율은 화면과 로그에 공개한 교육용 가정이며 실제 사람·화재 모델의 측정값이 아니다.
4. X/? 또는 해당 원천의 새 REPORT가 3초 이상 없으면 해당 갈림길에서 대기한다. PC 예측·오래된 보고로 실제 판단을 대체하지 않는다. 같은 세대·순번의 중복 보고는 최신성 타이머를 연장하지 않는다.
5. ID 집계는 간선·대기 지점·출구 도착을 포함해 총60을 보존한다. 출구 도착 ID는 별도 EVACUATED_EL/ER로 보존하고 복도 혼잡 계산에서 제외한다. 정상 중앙 연결에서는 현재 간선 인원을 1초마다 새 crowd_version으로 전달한다. 중앙이 끊기면 시뮬레이션 이동은 관찰 보고로 계속될 수 있으나 그 인원을 하드웨어에 다시 보내지 않는다.
6. 기준/연동 비교는 같은 초기 조건·이동 규칙·사건의 논리 시각을 사용한다. 실제 물리 스위치 입력의 시각 오차를 기록하고, 동기화·보고 대기로 일시정지한 시간은 별도로 남긴다. 결과는 가상 모델 안의 차이이며 실제 대피 시간 개선의 증거로 제시하지 않는다.

정교한 군중 상호작용·다양한 정책의 통계 비교는 P2다. 단순 이동 시연만으로 안전성이나 개선율을 확정하지 않는다.

### C7.2.1 실물 전환과 비교 절차

SIM을 종료하면 가상 기록을 보존한 뒤 로컬 서버가 제공하는 HIL_TEST 준비 화면을 연다. 독립 SIM 파일에서 실제 서버 API를 호출하지 않으며, 전환 링크로 서버 화면에 이동한 후 서버 화면의 실행 토큰·Origin 검사를 거쳐 실물 조작을 수행한다. 실제 모드에서는 USB·G heartbeat·세 표지판 REPORT·지도 해시를 확인한다. 운영자가 물리 스위치와 시험 latch를 명시적으로 해제한 뒤 새 인원 실행을 시작하고, 세 REPORT의 새 run_id 반영을 확인하면 실물 정상 장면을 시작한다. 미응답·위험 ON·지도 불일치이면 준비 사유를 표시하고 진행을 보류한다.

역전환은 화면을 SIM으로 바꾸되 실물 장치의 동작이나 위험 상태를 변경하지 않는다. SIM 복귀 후에도 실물 상태를 이어받은 것처럼 표시하지 않으며 새로운 sim_session_id로 별도 실행한다.

T17 비교표에는 scenario_id / 모드 / 입력 순서 / 지도·설정 / 위험 벡터 / 인원 분포 / S1·S2·S3 상태 / 안정화 여부 / 독립 기대값 / 일치 여부 / 증거를 기록한다. 네 장면은 같은 초기 상태와 순서로 수행한다. 전달 중의 일시적 차이는 별도 지연 자료로 남기고 안정화 후 판단과 구분한다. SIM 계산시간은 실제 LED 반영 지연의 대체 측정값이 아니다.
